## G-003 多进程代理流、工作树隔离与模型选择隔离 [active]
- 类型: 短期
- 来源: 2026-08-08 用户规划
- 说明: 多进程协作采用“并行查、串行写”——勘察与复核由只读子代理并行，项目级同时只有一个 writer run，工具调用串行；每条开发线仍可绑定独立 git worktree、独立会话与独立模型，用于隔离、diff、恢复和交付，不能绕过项目级单写。模型选择收敛为“全局→项目→线”分层真源，全部落后端可持久可恢复。
- 设计: docs/design/parallel_read_serial_write_orchestration.md 是代理调度与写入纪律真源；docs/design/deep_parallel_dev.md 保留 worktree、显式主根、diff、恢复与模型隔离方案。
- 门禁: R-171 按 memory system 开发序列之后取活并先交付调度地基；deep_parallel_dev.md §6 其余 D1~D7 未定项仍不得实施。自主循环可按 R-171 已定边界推进单写协调器，不得恢复多 writer 并行写。
- 验收: R-171 完成“并行勘察→串行实现/集成→并行复核→串行修正”真实轨迹；worktree 后续完成开发→提交→diff→合并闭环；重启后各项目/各线模型选择完整恢复。
