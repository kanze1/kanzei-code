>
> 取活序的唯一真源是引擎,不是记忆:队列优先级由本轮 work-priority mode 决定(桌面端按项目切换的按钮,存 localStorage `kz-work-priority:<project>`,默认 defect-first),经 `resolve_work_decision` 合成 `<resolved-control-state>`,dev profile 下**每轮**注入 system prompt(kanzei-app/src/run.rs、kanzei/src/main.rs);`work` 工具的描述里写死 "Queue priority comes from the run and cannot be overridden by tool input"(kanzei-tools/src/work.rs)。
>
> 本条 category 是 preference,正文会全文常驻注入并顶着 "STANDING DIRECTIVES (obey these; they are the user's own words)" 抬头(kanzei-tools/src/profiles.rs)。它改不动队列顺序(引擎封死),唯一可能产生的作用是怂恿模型借 `WorkInput.reason` 偏离引擎裁决,并把一条已过期的理由写进审计记录——有害无利,故退役。
>
> 要改取活序请切那个按钮,不要再建记忆副本。

取活顺序:先从上到下扫描 requirements.md,再扫描 defects.md;前一个队列没有可做项时才看后一个。
priority 标签只是背景信息,不改变列表顺序。
