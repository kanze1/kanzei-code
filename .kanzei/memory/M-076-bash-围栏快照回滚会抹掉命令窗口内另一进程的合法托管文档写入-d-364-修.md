根因:BashTool 的 D-173 结果侧围栏(crates/kanzei-tools/src/managed.rs::enforce_managed_files)在命令执行前后对整棵托管树(.kanzei/project + .kanzei/memory)拍快照比对,命令窗口内任何变化(含另一进程 kz CLI 经 tracker 合法写入 requirements.md)都被归因于 bash 并整体回滚到执行前快照。修复:围栏命令窗口内经专用线程持有 known_active_doc_paths 全部 FileLock(managed.rs::acquire_managed_locks,非托管目录返回 noop),并发写者在窗口内等锁、命令结束落盘;超过 CLI 3s 锁预算则明确报错。FileLock 是 !Send,跨 async 命令窗口持锁用专用线程承载(release channel + join)。坑:try_lock_exclusive 会 create_dir_all 父目录,在非托管根(如 %TEMP%)取锁会造出 .kanzei 标记污染目录发现(B3 加 managed_scope_exists 门槛)。collect_files 必须排除 .lock 文件(share_mode(0) 独占句柄读 metadata 被拒→快照误判超限,D-364 B1 实测)。
