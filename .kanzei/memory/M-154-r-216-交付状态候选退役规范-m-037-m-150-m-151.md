依据 R-216 验收③ 执行的标准化退役流程：

步骤 1：识别需退役的目标
- M-037 型：delivery status content (含 "R-已交付" 等 Tracker refs) 但状态已被 tracker/refs 取代
- M-150/M-151 型：因未理解 STALE 而错误 ADD 的重复 candidate，明确标注为 erroneous duplicate

步骤 2：执行 memory_stale (需满足前置条件)
- reason(M-037 等): "R-216 验收③：交付状态已由 tracker/refs(R-xxxxx)取代，保留通用防重复实现规则的可追溯墓碑"
- reason(M-150/M-151): "R-216 清理错误候选：因未理解 STALE 而错误 ADD，已退役的重复 candidate"

前置条件检查：目标 ID 必须真实存在于 memory 系统中，否则 stale 操作将返回 "unknown memory id XXXX"

步骤 3：验证与归档
- 处理后逐条回读已退役 ID，确认 archive 路径 (.kanzei/memory/archive/) 与状态(deprecated)一致
- 对每条 note 执行 memory_inbox_discard(FP fingerprint) 完成 reconciliation

失败标记: 若目标 ID 不存在或 stale 因其他原因失效，记录错误原文作为 failure marker (如 "unknown memory id 已退役 ID")

约束：M-150/M-151 作为冗余条目不应保留任何记忆；只退役
