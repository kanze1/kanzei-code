适用场景：当 cargo test 运行出现 bash ×1/×2 失败，且伴随 compilation mismatched types 或 timeout 错误时的标准化修复流程。

操作步骤:
1. work:启动工作线程，确认当前分支和版本环境，判断依据是 branch 是否为目标版本
2. collaboration_status:检查协作状态是否正常，是否有其他人正在修改同一文件，异常则停止并通知
3. git:拉取最新更改并确保本地干净，无未提交或冲突时继续
4. grep/symbols/read:defect/insert:按顺序执行搜索定位、符号查看、文档阅读、缺陷标记和插入补丁，每一步判断：grep 结果是否指向问题函数，symbols 是否显示正确的类型声明
5. bash,test_record,req:执行编译测试，bash 返回 code=0 表示通过，否则转 test_record 验证

边界与例外:
- cargo 环境异常（如 rustc 路径变更）需回退到基础镜像
- 多测试失败时优先取第一条 failure 的 root cause
- bash timeout 超过 60s 立即切换 to test_record 并记录新超时阈值
