# kanzei 使用手册

面向第一次打开 kanzei 桌面端的人。读完这一页就能开始干活;想了解代码结构看
[docs/目录.md](目录.md),想了解开发纪律看 `.kanzei/project/conventions.md`。

## 一分钟上手

1. **选项目**——左上角是当前项目;点它展开项目列表,`＋` 添加已有目录,`✦` 初始化一个新目录。
2. **写任务**——底部输入框直接说要做什么,`Ctrl+Enter` 发送。可以粘贴或拖入图片和 PDF。
3. **看它干活**——正文流里依次出现思考、工具调用、改动;左侧 rail 上的活动图标可以打开右侧活动面板看后台子代理。
4. **回答权限询问**——要动你的机器时会弹窗。`允许` 只放行这一次,`总是允许` 会把规则写进配置。

输入框上方那一行是**发送前的上下文**:去哪个项目、用哪个模型、思考强度。右端「更多」里是低频操作(总结对话、复制上下文、搜索、新建隔离工作树)。

## 三种运行模式

模式在输入框下方的「设置」里选,它决定 agent 被允许做什么:

| 模式 | 用途 | 特点 |
|---|---|---|
| 结伴开发 | 你在旁边看着,一问一答 | 不自动续跑 |
| 自主推进 | 让它自己按队列往下做 | 唯一允许「鞭挞」的模式 |
| research 研究 | 只读调研,产出报告 | 禁止提交、禁止改代码 |

## 鞭挞(自动连续推进)

勾上输入框下方的「鞭挞」,每轮跑完会自动发出下一轮,直到:

- 达到「连续推进上限」(默认 10 轮,可改);
- 队列里没有可执行条目,或全部被阻塞;
- 你点「暂停」或勾「本轮后停」;
- 连续两轮没有实质动作。

停下来时**一定会说明原因**——横幅、线路状态或运行日志里都能看到。看到「没有新消息了」先展开右下角「日志」。

## 需求 / 缺陷 / 测试:工作从哪来

kanzei 的待办不是数据库,是 `.kanzei/project/` 下几份可以手改的 Markdown:

- `requirements.md` 需求与工作项(R-xxx)
- `defects.md` 缺陷(D-xxx)
- `tests.md` 测试记录(T-xxx)
- `conventions.md` 开发规范——**agent 每轮都会读并遵守它**

侧栏「各线当前在做」只显示每条线正在做的那一条;完整列表、筛选、拖拽排序、批量改状态都在左侧 rail 的「需求与工作 / 缺陷 / 测试」页。`记需求` / `记缺陷` 两个按钮把一句自然语言交给后台子代理结构化入库,不打断当前对话。

自主推进取活的顺序 = 手动排序(拖拽)+ 取活顺序偏好(缺陷优先 / 需求优先)。优先级字段只是给人看的参考,不改变取活。

## 并行线路与隔离工作树

一条线 = 一个独立分支 + 一棵独立 git worktree + 自己的对话历史。互相不会踩到对方的文件。

- 侧栏「当前状态」列出所有线,点一下切过去;每条线下面的「历史对话」可展开。
- 左侧 rail 的「并行线路」页负责开线、看差异、收活、放弃。
- 主项目那几份 tracker 文档是全局唯一的,分支线默认**只读**;要让某条线改它,在「设置 → 写主根追踪器」里单独打开。

## 记忆

`.kanzei/memory/` 下是分级的 Markdown 记忆条目,全部可以手改。每轮开跑前按你的输入预检索,命中的会注入上下文。记忆页(rail 上的菱形图标)能看到:哪些被召回、召回后有没有真被采纳、这一轮 system 里各来源各占多少字符。

## 权限

权限是**硬门禁**,不是提示词约定:规则由代码强制。三种处置——允许、拒绝、总是允许。「设置 → 权限规则」里能看到记住了哪些规则并删掉它们。

输入框下方「设置 → 自动放行」等价于 yolo:所有询问直接通过,且跨重启生效。

## 常用快捷键

| 键 | 作用 |
|---|---|
| `Ctrl+Enter` | 发送 |
| `Ctrl/Cmd+K` | 聚焦输入框 |
| `Ctrl/Cmd+Shift+N` | 新对话 |
| `Ctrl/Cmd+Shift+C` | 停止当前任务 |

## 出问题时看哪里

- **右下角「日志」**——错误、鞭挞停机原因、后台线路的失败都会落在这里。
- **运行画像页**——每轮的上下文占用、token、工具分布。
- **版本**——右下角版本徽章;「设置 → 检查更新」可手动更新。
