# Kanzei 使用手册

本文只描述已有操作。下一版管理设计见 [管理工作区方案](design/management_workspace.md)，实现与权限边界见 [系统合同](design/system_contracts.md)。

## 开始一个任务

1. 从侧栏选择或新建项目，也可以进入无项目对话。
2. 选择模型、思考强度和执行模式，输入目标，使用 `Ctrl+Enter` 发送；图片和 PDF 可粘贴或拖入。
3. 对话区查看正文和工具摘要，活动区查看子代理及终端。权限请求按实际资源审阅；保存的规则可在设置中管理。
4. 完成后检查产物和验证证据。停止回复、工具完成、提交和安装更新分别代表不同状态。

无项目对话保留独立历史与文件目录，可使用通用工具、技能和记忆；项目需求、批次与提交门禁不参与。使用“关联项目”接续为项目讨论，原对话与文件保留。

## 执行与停止

结伴模式 `dev-pair` 按当前请求工作；自主模式 `dev-auto` 按有效目标和项目队列推进。前后端的 profile 与主 Agent 使用相同名称，两种模式分别使用独立提示词。显式 Goal 可使对话围绕目标继续。研究任务按研究档的能力与权限运行；不会因为切换浏览页面而改变既有运行归属。

发送前确认当前对话、项目、模型和模式。执行菜单提供 Goal、协作及权限策略；“自动放行”仍受明确拒绝、托管写入和实际资源权限约束。停止通过运行控制取消当前工作，不以界面卡片消失判断后台已结束。

## 项目管理与证据

当前管理页提供需求、缺陷、交付与项目地图。普通讨论不自动成为需求。当前状态和验收以 `.kanzei/project/requirements.md`、`defects.md` 及其归档为准；测试登记在 `tests.md` 与 `tests-archive.md`。

长程工作可使用 Work Unit：`create-unit → claim → checkpoint → verify → evidence → complete`。完成需要逐条验收证据，父目标仍需整体验收；子任务结束不自动证明父目标成立。当前命令与参数以 `kz --help` 和对应子命令帮助为准。

多个写任务通过独立 worktree 隔离；由主代理检查差异后整合。Git 文本合并成功不等于行为验证通过。切换页面或查看项目知识不会转移正在执行任务的收件人。

## 记忆、技能与文件

- 全局记忆入口查看项目记忆、召回和上下文观测。命中与读取不能直接证明任务收益；候选、反馈和已确认记忆分别管理。
- Skills 由全局目录管理，启用与读取按实际工具合同执行。
- 文件编辑保存使用磁盘指纹检查；出现外部修改时先比较，再选择保留的版本。浏览器页面、原生窗口与文件分别受资源权限约束。

## 常用入口

| 操作 | 快捷键或入口 |
| --- | --- |
| 发送 | `Ctrl+Enter` |
| 命令面板 | `Ctrl/Cmd+P` |
| 聚焦输入 | `Ctrl/Cmd+K` |
| 新对话 | `Ctrl/Cmd+Shift+N` |
| 停止 | `Ctrl/Cmd+Shift+C` |
| 当前对话搜索 | `Ctrl/Cmd+F` |
| 导出对话 | 对话右键菜单 |
| 检查更新 | 设置中的更新入口 |

遇到问题先检查活动区、日志、当前对话身份与版本徽章。更新下载成功和本地程序替换是两个步骤，安装后以运行中的版本确认结果。
