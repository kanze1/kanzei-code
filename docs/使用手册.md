# kanzei 使用手册

面向第一次打开 kanzei 桌面端的人。读完这一页就能开始干活;想了解代码结构看
[docs/目录.md](目录.md),想了解开发纪律看 `.kanzei/project/conventions.md`。

## 一分钟上手

1. **选项目**——从侧栏选择已有项目，或添加目录、新建项目；也可以直接开始无项目对话。
2. **写任务**——底部输入框直接说要做什么,`Ctrl+Enter` 发送。可以粘贴或拖入图片和 PDF。
3. **看它干活**——对话正文与工具摘要显示本轮进展，活动区查看后台子代理和终端。
4. **回答权限询问**——要动你的机器时会弹窗。`允许` 只放行这一次,`总是允许` 会把规则写进配置。

发送前确认当前项目、模型、思考强度和执行模式。执行菜单提供原生窗口、自动放行、子代理和 Goal；对话右键菜单提供 Markdown 导出。当前对话搜索使用 Ctrl/Cmd+F。

## 不选项目也能聊天

点侧栏“无项目对话”即可开始普通聊天。可发送文字与附件、选择模型、新建聊天、打开历史、分叉、停止回复；重启后会恢复聊天记录。没有项目时首次启动会直接进入该模式。

此模式保留通用 Harness：可以生成和编辑真实文件、执行命令和交互式终端、调用浏览器与网页工具、使用技能和记忆、与子代理持续协作、压缩上下文、回退、分叉和设置定时任务。每条对话有独立文件目录；生成文件后可直接给出文件链接。需求登记、项目阶段、批次收尾和强制提交等项目门禁关闭，普通工具使用全局权限设置，文件过期保护保留。

需要接着在项目中讨论时，点对话标题旁的“关联项目”，选择已添加的项目；会复制为一条项目讨论，原聊天和文件保留。实现和存储说明见 [无项目对话](design/general_chat.md)。

## 三种运行模式

执行模式决定本轮如何推进任务；权限规则和工具的真实限制另行执行。

| 模式 | 用途 | 特点 |
|---|---|---|
| 结伴开发 | 按当前请求问答、实现或审查 | 只有显式挂 Goal 才围绕目标继续 |
| 自主推进 | 按选定条目或项目队列推进 | 自动继续，运行控制负责暂停和停止 |
| research 研究 | 只读调研,产出报告 | 禁止提交、禁止改代码 |

## 鞭挞(自动连续推进)

自主推进按所选条目或队列继续，直到没有可执行动作、目标达成、需要用户回答，或用户暂停/停止。结伴开发只有显式设置 Goal 才自动围绕该目标继续；Goal 达成与否由模型根据用户目标判断，引擎不另造工作。

当前不再使用旧的默认10轮连续次数上限。轮次、上下文预算、取消、权限和无实质进展的停机条件继续生效。
停下来时**一定会说明原因**——横幅、线路状态或运行日志里都能看到。看到「没有新消息了」先展开右下角「日志」。

## 需求 / 缺陷 / 测试:工作从哪来

kanzei 的待办不是数据库,是 `.kanzei/project/` 下几份可以手改的 Markdown:

- `requirements.md` 需求与工作项(R-xxx)
- `defects.md` 缺陷(D-xxx)
- 历史想法记录保留为项目资产；当前导航不提供独立想法页。
- `tests.md` / `tests-archive.md` 测试记录(T-xxx)，终态记录在归档中；当前仍由 test_record 使用。
- `conventions.md` 开发规范——**agent 每轮都会读并遵守它**

在项目「管理」中查看需求、缺陷、交付与项目地图。登记需求或缺陷使用相应入口；普通提问和讨论不自动登记成需求。过期、重复和取消的工作保留原因后退役归档，待真实设备或 SSH 验收的工作保留独立状态。

自主推进按当前有效控制状态取活，综合项目顺序偏好、队列顺序和未满足的前置。已经完成的前置保留为引用，不继续阻塞取活。

### 长程需求：Outcome 与 Work Unit

普通需求维持原来的整条取活方式。预计跨多轮、上下文会持续增长的需求，可以在 Requirement 里写 `执行模型: work_units_v1`，再用 `kz work create-unit` 拆成 `R-xxx/W1`、`R-xxx/W2` 等执行单元。

每个单元有独立目标、范围、依赖、验收、验证方法和代码基线。`kz work next` 只把当前单元与父需求的目标/边界/验收注入模型；父需求里不断累积的旧进展与对账不会每轮重复装载。需求详情会显示各单元状态、下一步和证据覆盖数。

典型流程：`create-unit → claim → checkpoint → verify → evidence → complete`。`complete` 前必须为每条验收登记证据；所有单元终态后，仍需执行 `req close` 完成 Outcome 级验收。完整契约与 PowerShell 示例见 [`design/work_unit_foundation.md`](design/work_unit_foundation.md)。

## 并行线路与隔离工作树

一条线 = 一个独立分支 + 一棵独立 git worktree + 自己的对话历史。互相不会踩到对方的文件。

- 从侧栏选择对话；对话按自己的身份保存历史、模式和运行状态。
- 按需子代理的写任务使用独立候选工作树，由主代理查看差异并整合；已有隔离工作树仍可通过对应管理能力维护。
- 主项目那几份 tracker 文档是全局唯一的,分支线默认**只读**;要让某条线改它,在「设置 → 写主根追踪器」里单独打开。

## 记忆

`.kanzei/memory/` 下是分级的 Markdown 记忆条目。全局记忆入口选择项目并查看记忆、召回和上下文账单，浏览记忆不切换当前执行对话。界面区分注入、读取、验证和未知状态；召回命中本身不代表任务收益。

## 权限

权限是**硬门禁**,不是提示词约定:规则由代码强制。三种处置——允许、拒绝、总是允许。「设置 → 权限规则」里能看到记住了哪些规则并删掉它们。

执行菜单的「自动放行」按当前会话实际策略处理权限询问；明确拒绝和托管写入边界仍由代码执行。

## 常用快捷键

| 键 | 作用 |
|---|---|
| `Ctrl+Enter` | 发送 |
| `Ctrl/Cmd+P` | 打开命令面板，检索视图、项目、线路和可用动作 |
| `Ctrl/Cmd+K` | 聚焦输入框 |
| `Ctrl/Cmd+Shift+N` | 新对话 |
| `Ctrl/Cmd+Shift+C` | 停止当前任务 |

## 出问题时看哪里

- **右下角「日志」**——错误、鞭挞停机原因、后台线路的失败都会落在这里。
- **运行画像页**——每轮的上下文占用、token、工具分布。
- **版本**——右下角版本徽章;「设置 → 检查更新」可手动更新。
