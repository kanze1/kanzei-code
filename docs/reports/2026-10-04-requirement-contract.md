# 需求登记与数据格式改造

## 改动

| 原行为 | 当前行为 |
| --- | --- |
| 一次输入只能塞进一条需求 | 一次登记可返回多条独立行为，分享同一份原文 |
| 必须补复杂度、标签、优先级与发现记录 | 正文、验收、来源构成契约，未知工程输入进入草稿 |
| 信息不完整仍进入执行队列 | 新契约草稿先补齐，再显式转待开始 |
| 验收与证明混在长进展文本里 | 验收 ID 稳定，证据独立绑定需求版本 |
| 列表返回全字段及重复字段词典 | 列表摘要，按条读取详情 |
| 详情平铺全部字段 | 正文、验收优先；来源与执行记录折叠 |

## 新契约示例

```json
{
  "statement": "收到导出请求时，系统应生成包含所选评分的 CSV 文件。",
  "acceptance": [
    {"text": "选择两条评分并导出，文件中包含两条所选记录及对应评分。"}
  ],
  "source": {"quote": "导出我选中的评分"}
}
```

保存后验收获得 `AC-1`。若导出字段尚未确定，应在 `questions` 记录具体问题，进入草稿；不凭空填字段或阈值。独立行为使用不同需求 ID，同一行为的正常、失败、边界场景可成为多个验收项。

快速登记原文由应用保存，模型不能用摘要替换原文。模型调用失败但已有部分条目落盘时，返回实际编号及错误；所有登记界面保留原文，避免把部分成功显示为全部完成。相同来源、标题和规范内容的重复写入返回已有条目。

## R-245 的兼容边界

历史数据保留原状态、原文、边界、迁移回滚和未知字段。界面优化立即适用于旧数据；历史语义拆分需要逐条核对，不由程序自动推断。

对于 R-245，完整 artifact 的保存与读取、引用的完整性、显式清理的确认与结果、数据库整理与备份，应在后续内容整理时分别核对验收。32 KiB 是旧文中的实验参数，不能未经判断升级为产品固定阈值。“不自动过期”与“仍被引用的 artifact 不得清理”是有效约束，不能按普通背景信息删掉。

## 验证范围

- Rust 回归验证草稿调度与补齐、版本变化后证据失效、真实证据引用、旧字段保留、CLI JSON 文件输入。
- 模拟模型协议驱动实际登记代码：复合输入多条落盘、共享原文、重复调用幂等、模型中断后保留回执、先行调研兼容。
- Edge 运行真实前端模块：正文与验收展示、旧证据提示、草稿问题、编辑 ID 与来源保持、历史边界不丢失、窄屏可读。
- 模拟协议与浏览器 IPC 夹具用于可重复回归；不等同于对线上模型拆分质量的保证。

浏览器回归入口：`node scripts/ui-requirement-contract-smoke.mjs`。截图与判据记录输出到 `output/playwright/requirements-contract/`。
