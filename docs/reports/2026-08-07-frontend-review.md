## 2. 视觉与美观度评估(整体良好,做"微调"而非"重设计")

### 优点(保留)
- CSS 变量体系完整,改色成本极低。
- 色彩语义清晰:ok/err/warn/info 区分到位;需求 P0-P3 色条 + 状态胶囊一眼分层。
- 克制不花哨,与「日常主力开发工具」定位匹配。

## 3. 交互与易用性评估(重点)

### 3.1 高频路径梳理
按日常使用频率排序:
1. **发消息 → 看输出 → 跟工具进度 → 等完成**(核心闭环)
2. 打断/插入(停止、steer)
3. 切换模式/模型
4. 查看目标/需求/缺陷状态
5. 历史对话回看
6. 权限弹窗决策
7. 设置(低频)

### 3.2 主要交互问题(按优先级)

#### P0 — 顶栏超载与操作过载
- **现象**:顶栏常驻 9 个控件(继续/连跑/新对话/自动放行/总结/复制上下文/搜索 + 模型 select + 模式 select),窗口变窄时 wrap 成两行,进一步挤压消息区。
- **证据**:`index.html` topbar 段;`style.css` `#topbar { flex-wrap: wrap }` 注释明确"窄窗口换行"。
- **影响**:每次扫视成本高;低频操作(总结/复制上下文/搜索)抢占高频操作(继续/停止/新对话)的视觉位置;「复制上下文」本质是研发调试动作,不应常驻。
- **建议**:顶栏只保留高频 3-4 项(继续/连跑/新对话/模型/模式);其余收进 "⋯" 溢出菜单或迁到状态栏/快捷键。这是**收益最大、改动最小**的一条。

#### P0 — 消息流 markdown 可读性
- **现象**:`renderMarkdown` 是"markdown-lite",只支持围栏代码/行内码/加粗/标题;**不支持列表、表格、链接**——agent 输出列表/对比表时会渲染成一坨纯文本。
- **证据**:`main.js:136-152` renderMarkdown 实现。
- **影响**:结对开发场景下 agent 频繁输出计划清单/对比表,可读性差直接影响"看得清"这一核心体验。
- **建议**:要么把 markdown-lite 补齐列表/表格,要么换用成熟渲染器(见工具建议 T3)。同时 agent 消息加角色锚点(V3),长回复可折叠为标题+展开。

#### P1 — 键盘导航与快捷键薄弱
- **现状**:仅 Ctrl+Enter 发送、弹窗内 Enter/Esc;无全局命令面板、无"聚焦输入框""新开对话""切模式/模型""停止"快捷键。
- **影响**:开发工具用户对键盘效率敏感;当前几乎全程依赖鼠标。
- **建议**:补一组最小快捷键(Ctrl+K 命令面板或至少 Ctrl+L 聚焦输入、Ctrl+N 新对话、Ctrl+. 停止),并在空状态/顶栏 tooltip 中显式展示。这是"少打断"目标(G-001)的直接抓手。

#### P1 — 侧边栏纵向拥挤
- **现象**:6 个分区(项目/当前进展/目标/历史对话/需求/缺陷/开发规范)叠在 280px 宽栏内,需求/缺陷列表一屏看不全,要频繁滚动;分区标题已支持点击折叠,但**折叠状态不持久化**,重启后全展开。
- **证据**:`index.html` sidebar 6 个 `sidebar-section`;`style.css:50-54` 折叠实现。
- **建议**:折叠状态存 localStorage;需求/缺陷列表加"只看 doing/todo 前 N 条"的紧凑模式;考虑把「当前进展」从侧边栏挪到状态栏或顶栏下(它本来就是实时态,不需要常驻)。

#### P1 — 队列/steer 反馈可见性
- **现象**:delivery 有 queue/steer,但**排队中的消息没有可视化列表**,只在发送后 toast 一闪而过;连跑计数在状态栏文案里。
- **证据**:`main.js:772-833` sendText;R-032(队列可视化)已在 doing。
- **建议**:这正是 R-032 在做的,优先级最高,建议本次一并推动;连跑状态做成顶栏/状态栏的可点击徽章(点击停止连跑)。

#### P2 — 权限弹窗与 toast 的层级/位置
- **现象**:toast 底部居中,容易和「回到最新」按钮、状态栏提示重叠;ask 弹窗 OK,但权限弹窗出现时没有声音/明显吸引注意的手段(R-018 提示音需求相关)。
- **建议**:toast 位置与层级统一;权限弹窗出现时给状态栏/任务栏一个明显状态(配合 R-018)。

#### P2 — 历史对话回看的连续性
- **现象**:历史对话可加载回看,但"当前正在进行的对话"与"历史列表"是两套渲染路径(renderRecoveredMessages vs 实时 append),回看时右侧活动面板/todo 不会联动。
- **建议**:回看模式下右侧显示该会话的快照态或置灰,避免误以为还在跑。

#### P2 — 空状态引导
- **现象**:空状态只有 logo + 一行 hint;新用户不知道第一步做什么(添加项目→选模式→发任务)。
- **建议**:空状态加 3 步极简引导(可加示例 prompt 点击即填)。

#### P3 — 活动面板与 todo 面板的联动
- **现象**:bg-panel(活动)与 todo-panel(当前计划)是两个独立右侧面板,同时出现时各占 300px,主区被压窄;目前 max-height: 42% 限制只对 todo 生效。
- **建议**:考虑合并为单个右侧面板的两个 tab,或允许手动调宽/折叠。

### 3.3 工程与可维护性(影响后续迭代速度)

## 4. 前端开发工具推荐(轻量、免费、与"无构建"流程兼容)

> 原则:**不引入框架和打包器**,工具只服务于"写得快、错得少"。VS Code 生态与你当前环境完全一致。

### 推荐清单(按必要性排序)

| # | 工具 | 作用 | 为什么适合 kanzei |
| --- | --- | --- | --- |
| T1 | **Prettier**(VS Code 扩展 + 可选 CLI) | JS/CSS/HTML 格式化 | 零配置、保存即格式化;不改变现有"无构建"流程,只是编辑器层格式化 |
| T2 | **ESLint**(flat config,只开 `recommended` + browser env) | 抓未定义变量/手误/明显 bug | 对付 main.js 单文件全局函数最有效的安全网;不强制风格,只抓错 |
| T3 | **marked**(约 40KB,ESM 可直接 import) | 完整 markdown 渲染(列表/表格/链接/代码) | 解决 P0 消息可读性;配合 **DOMPurify**(约 22KB)做 XSS 消毒;两者都是单文件 ESM,不用打包 |
| T4 | **VS Code 扩展:Live Preview**(微软官方) 或 Tauri 自带 devtools | 静态页快速预览 UI 调整 | 调 CSS 时不用每次重启 kzapp;正式联调仍走 `cargo run -p kanzei-app` |
| T5 | **iconify / lucide-static**(拷贝 SVG) | 统一图标集 | 替换现有字符图标混排;直接拷 SVG 进 index.html,无依赖 |
| T6 | (可选)**TypeScript checkJs**(`// @ts-check` + jsconfig.json) | 不动代码结构就获得类型提示与部分类型检查 | 对 1500 行单文件平滑渐进;不满意随时删掉注释即可 |

### 不建议引入
- 任何打包器(Vite/webpack/esbuild)、React/Vue/Svelte、npm 依赖树——会破坏"clone 下来 `cargo run` 就能跑"的极简流程,且对当前体量是杀鸡用牛刀。
- 主题引擎/CSS 框架(Tailwind 等)——与现有 CSS 变量体系冲突,且当前设计问题不在"缺样式"。

### 最小落地组合(我的推荐)
**T1 + T2 + T3 + T5**:格式化保一致性、ESLint 抓错、marked+DOMPurify 解决消息可读性、lucide 统一图标。全部免费、全离线可用、不引入构建步骤。T6 作为可选项。
