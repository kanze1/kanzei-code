# 基础文件设施重构：事实、取舍与影响

范围：`问题.MD` 列出的 atomic_file、path_form、write_log，以及它们的直接调用者。继续使用独立工作树；本轮不提交、不合并、不发布。

## 全局判断

`kanzei-base` 的位置正确：memory 与 tools 都需要同一套文件设施，不能让它们反向依赖业务模块。保留零第三方依赖和现有 crate 层级。问题主要出在历史补丁增加的状态组合，以及写日志的数据模型含糊，不需要新框架或新服务。

依赖方向仍是：`std → kanzei-base → kanzei-memory / kanzei-tools → kanzei-app`。这张简图只描述本轮涉及的文件设施；业务层决定写什么和何时归一换行，base 负责字节指纹、路径、锁、原子替换与日志存取。锁和日志编码拆成内部文件，测试单独放置，没有增加 crate 或第三方依赖。

| 问题 | 当前事实与设计原因 | 本轮取舍 | 后续影响 |
| --- | --- | --- | --- |
| 非 Windows 锁 | create_new 把文件存在当成持锁，释放句柄却不删除文件；30 秒清理既会假阻塞，也可能删除活锁。当时为保持纯 std 做了平台降级。 | 使用标准库 File 的共享/独占文件锁，文件留存，锁随句柄释放。 | 各平台使用同一协议；base 最低 Rust 版本为 1.89。新旧进程应一起升级，不能依靠旧 O_EXCL 进程参与新协议。 |
| acquiring 特例 | 排他获取前已设置 owner，共享获取前已设置 shared；原特例要求二者都为空，因此正常路径不可达。原测试只验证了释放后唤醒。 | 每个路径一个互斥槽，在槽内非阻塞尝试 OS 锁；等待时释放槽。只保留空闲/共享/独占三态。 | 不再有“占位但没有句柄”的状态，也不再保留补探测、超预算重试等路径。共享升独占仍直接报错。 |
| 路径身份 | 替换斜杠和小写无法统一相对路径、点段、链接。 | 解析目标或其已创建的父目录，再解析锁文件身份；失败直接返回错误。 | 同一文件的普通路径别名进入同一槽。锁文件不能在持锁期间人工删除；硬链接的独立目录项不作为同一逻辑文档承诺。 |
| CAS | 临时文件落盘后读目标、比指纹、rename；这不是文件系统的条件交换。部分调用点自己持锁，接口却没有强制。 | CAS 内部获取同一 FileLock，覆盖校验到替换；调用者已有的外层读改写锁可重入。 | 参与协议的 writer 串行化。外部编辑器仍可能在检查与 rename 之间修改，明确记录边界，不用重复检查假装消除窗口。 |
| 原子替换重试 | 对任何 rename 错误都固定重试，掩盖真实错误并增加状态。 | 单次替换，失败立即报告；完整临时文件保留供恢复。 | 暂时占用会直接显示失败，由调用方明确重试。原子可见性不等于文档和日志的跨文件事务，也不等于断电后目录项必定持久。 |
| MAX_PATH | 检查了带前缀的 raw，且允许 260 个 UTF-16 单元。 | 检查实际 candidate，要求长度小于 260；盘符、UNC 使用同一判据。 | 259 可简化，260 保留前缀；组件规则保留，因为它们决定路径语义是否改变。 |
| 日志清理 | 全局删最旧 500 条，会删掉冷门文件唯一的合法内容。 | 保留每个路径的最新事件与最新可恢复状态，再清理其余历史。删除无生产调用的第二套按时间清理入口。 | 500 是历史保留目标，不是可以压过恢复正确性的硬上限；路径多时允许超过它。 |
| 空正文 | 空 Vec 同时表示合法空文件、未保存正文，memory 归档还用它表示删除。文档中“跳过空后选更旧一条”不完全准确：当前先取最新，再过滤空，因此返回 None，调用方才退回旧快照。 | 显式区分正文（可为空）、仅指纹、删除。 | 空文件与删除不再互相匹配；最新记录没有正文时明确报告无法自动恢复，不能偷用更旧版本。 |
| 日志身份和顺序 | sanitize 路径存在确定碰撞；毫秒不能决定同路径事件先后。 | 项目日志锁内分配严格递增编号，文件名使用编号与真实路径指纹。业务写锁覆盖文档写入和凭据记录。 | 时间只用于窗口筛选，编号决定顺序；同毫秒、时钟回退、多进程不会覆盖事件或随机选最后一条。 |
| 隐藏错误 | 日志读取、解码失败被跳过；缺证据又被当作越界，可导致错误回滚。 | 查询返回 Result，日志错误在围栏处显式报告；不自动回滚。既有旧日志只在解码边界处理，缺失的信息不猜。 | 暴露实际损坏与旧格式歧义，不再通过空集合或旧快照维持表面成功。 |
| 工作树归因 | 源码日志集中写到项目主根，但路径是相对各自工作树；不同树的同名文件会串用凭据。 | 源码凭据写到实际工作树根，复用 checkpoint 的根判定；路径 canonicalize 后取相对路径。跨树围栏逐树读取，托管文档仍使用所属项目根。 | 子目录 cwd、绝对/相对路径与 Windows 大小写不再拆成不同凭据；升级前的跨树凭据不再被混用。 |

## 不增加的设计

不引入锁服务、后台修复、过期锁抢占、自动锁升级、跨文件事务模拟、双写日志或多套哈希算法。真正的业务状态用类型表达；权限、读写、解码错误直接返回。既有 500 条运行时日志必须保留，不通过清目录“解决”兼容问题。

范围选择仍然明确：有身份的工具写入只为所属工作树中的文件留下源码凭据；工具获准写入的树外文件不归入这本日志。没有项目身份的独立工具调用、global memory 也不凭空创建项目日志。这些是业务范围，不是失败后的替代路径。

围栏使用一次窗口查询得到的最新状态，避免恢复时再次查询全部历史；原来的 `last_content` 因此不再需要，与无生产调用的 `prune_before` 一并撤掉。模块拆分也暴露出符号查询只能跟一层导出的问题，现有查询改为沿导出记录逐层收集，每条记录只处理一次，保持公开 API 的定位能力。

## 依据与验证

- [Rust File 文件锁](https://doc.rust-lang.org/std/fs/struct.File.html#method.try_lock)：1.89 稳定，共享/独占及非阻塞接口；句柄关闭后释放锁。
- [Windows MAX_PATH](https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation)：260 包含末尾 NUL。
- 锁：线程状态矩阵、真正的子进程共享/互斥、强制结束持锁进程后再获取、路径别名、超时与错误传播。
- 路径：盘符和 UNC 的 259/260 边界、UTF-16 多单元字符、保留名与原有危险组件。
- 日志：同毫秒多写、跨进程编号、冷门文件超过保留量、合法空文件、删除、缺正文、损坏日志，以及围栏不误回滚。

验证对象：`kanzei/hash-unification` 分支，基于 `fd36faa3` 的本轮未提交改动。Windows 与 WSL Ubuntu 使用 Rust 1.98.0；Linux 通过 `rustc --test` 直接编译零依赖的 base，未声称 Linux 全工作区通过。
