# 2026-10-03 桌面使用问题热修正

## 七项修改

1. 旧后台仍驻留时，新窗口此前只比较安装路径和协议号，导致新版 UI 调用旧命令表。现在握手比较编入二进制的构建标识；旧后台仍有主任务、子代理或终端工作时等待，空闲后退出旧后台再连接新版。转发命令前等待隐藏 WebView 完成导航，保留 Tauri ACL 校验。
2. 侧栏仅列活动对话；已关闭/归档记录仍可从搜索与历史中管理。去掉行尾三个点，保留右键、菜单键和 Shift+F10。常用右键菜单为 4–6 项，复制、排序和外部工具收至二级。
3. 无项目对话继续使用同一运行系统。补测原始旧安装版驻留 → 新窗口升级 → 自动恢复侧栏项目和实际对话标题 → 打开无项目对话及删除旧对话，而不只测试全新启动。首次连接失败不缓存空偏好；后台接通后重新载入项目，避免只恢复接口却留下空界面。
4. 当前发布入口只接受 Windows x64，安装器明确为 NSIS。Cargo.lock 中包含其它平台依赖并不表示构建那些平台；CI 本来就只有 Windows。
5. CLI 与桌面端改为一次 Cargo 构建，再单独生成安装包。同一提交重复打包使用提交时间作为构建标识，避免每次重试都因时间变量变化失去缓存。`dist/build-timings.json` 和 Cargo timing HTML 保留实测耗时。
6. 浏览器预览不再从偏好恢复展开状态；仅点击入口才打开，仍保留最近地址和设备设置。
7. **项目下面的对话标题**使用首条实际发送内容，包含以前固定显示“主对话”的那条；手动改名优先。不改写用户消息正文。

删除已退役且已无数据的对话现在返回成功。`conversation_get/list/trace_get` 查询不存在的会话返回空数组，不再创建空记录；不再有“读一次就复活”的路径。

## 编译耗时证据

上一版 f55c8e56：CLI 发布编译 81 秒，桌面发布编译 118 秒，串行合计约 199 秒。完整验证里 UI lint（含浏览器布局检查）194.5 秒，UI runtime（含多组浏览器验收）301.1 秒，Rust 测试 147.3 秒。用户等待中约 8 分钟属于前端回归，不能全部算作编译。

本轮第一次增量 debug 桌面构建 20.01 秒，随后一次为 18.10 秒；首次合并 CLI 与桌面端的 release 构建耗时 153 秒。各次修改与缓存状态不同，这些数据用于定位等待来源，不作为严格性能对比。发布优化仍保留 thin LTO；日常修改使用 debug。未清空 target 或依赖缓存。

## 回归入口

- `scripts/ui-sidebar-conversations-smoke.mjs`：侧栏隐藏、右键长度、无三个点、历史管理、预览偏好。
- `scripts/ui-sidebar-native-smoke.mjs`：真实 WebView2/SQLite 删除、幂等、重启不复活、启动不展开预览。
- `scripts/ui-general-chat-native-smoke.mjs`：真实 IPC 和本地模型验收无项目发送、附件、文件、终端、任务、定时、恢复及标题。
- `scripts/ui-runtime-upgrade-native-smoke.mjs <old exe> <new exe>`：旧版缺少 general_chat 命令的现场；有任务时不退出旧后台，完成后切到新后台，原历史保留，主对话标题正确。

原生回归使用独立临时数据目录和本地模型；不调用用户真实模型服务。发布门禁结果绑定最终提交，详见 dist/verification.json；原生结果在 output/playwright/ 各验收目录。
