# Softwire V3：交互与视觉验收

日期：2026-09-28。对象为 `docs/prototypes/softwire/` 静态交互原型。所有 agent、文件、版本和提交均为页面内示例；本记录不表示正式运行器、安装版或真实长周期链路已验收。

## 结论

第三版已把首页从同权重的说明块调整为有中心、有关系、有轻重的工作网络。保留原有暖白、灰绿、橙色；阅读注意力留给目标、对象名称、问题与依据差异。原型可以用于继续确认交互方向，尚不能凭自动检查认定首次使用者已经理解它。

## 改前发现与本次处理

| 改前问题 | 本次处理 | 实际检查 |
| --- | --- | --- |
| 模块同样大小、说明很多，难找当前执行中心 | 主执行圆形中心；左侧依据、右侧工具与产物；子任务靠近所属执行者 | 查看 1440、1280、1050 宽度截图，节点与连线完整 |
| 运行、进度、原因都靠文字解释 | 运行环缓慢呼吸，阶段轨道展示实施/验证/交付；异常才突出橙色，等待保留短原因 | 静态截图与动画属性检查；减少动画时停用 |
| 图与输入互相挤压，收件人重复出现 | 输入标题只显示一次项目/接收者；设置、上下文使用图标入口；正文留在管理页 | 各模块收件人、发送目标与草稿隔离验证 |
| 初次进入就弹出旧待办 | 旧事项留在收件箱与就地入口，只为新来信提示 | 初始无弹窗；模拟来信保留输入焦点与草稿 |
| 悬浮框默认位置遮住产物节点 | 默认悬浮位保留底部空间；自由拖动和一键停靠继续可用 | 图和待回复入口下缘高于默认悬浮框上缘 |
| 窄屏需要滚动后才看到问题，输入图标难点 | 问题入口移到图前；输入旁主要动作有 44px 点击区域 | 390px 首屏位置、点击尺寸与 320px 布局检查 |
| 管理页只有分段解释，标题焦点框抢眼 | 记忆版本并排比较，工具参数折叠；进入页后聚焦标题但不画装饰性焦点框 | 查看记忆页截图；保留可操作控件的键盘焦点样式 |

## 图形与文字各自负责什么

- 位置与连线：依据进入哪个执行者、子任务归属、工具与产物去向。悬停或键盘聚焦突出一跳关系，只有明确点击才切换收件人。
- 形态与状态：主执行中心、候选虚线、归档虚线关系、完成勾、等待标记。名称和必要短状态仍可读；完整名称同时提供给辅助技术。
- 动画：运行环表达“正在运行”；模拟请求实际发生时沿关联线短暂传递信号。不用永动粒子制造进展错觉。
- 文字：目标、对象名称、必要版本、等待的问题、证据差异、失败原因和人输入的内容。参数、完整来源与设置解释按需展开。

这不是把文字机械替换为图标：陌生概念仍保留名称，重要的阻塞原因不能只用颜色表达。鼠标提示与图例是补充，不能承担核心操作说明。

## 检查证据

真实 Chromium 页面通过 **81 项交互与布局断言，0 个 page error**。覆盖九个模块的管理/发送、原文保真、草稿隔离、上下文和版本边界、历史只读、问题回复及过期重试、跨项目回复、批次验证依赖与交付，以及悬浮拖动/键盘操作/视口约束。

检查窗口：1440×950、1280×800、1050×735、1024×768、800×600、390×844、320×768。全部无横向溢出；五种桌面窗口输入区在视口内。窄屏支持工作区滚动，不要求在一屏里塞完所有节点。

另在应用内浏览器查看了新版实际渲染，并通过键盘进入记忆管理、确认发送目标为“记忆管理”、返回工作网络后确认目标恢复为“主执行”；应用内预览未记录控制台错误。

## 仍有的不足

1. **首次理解还没有真人证据。** 现在图的主次清楚了，但新用户能否立即理解“虚线候选”“上下文入口”和连线方向，需要实际观察。不能仅用减少字数来回答这个问题。
2. **多任务规模尚未验证。** 示例只有少量对象。十几个子任务、几十条异常、持续来信时，仍需按批次/执行者折叠并保持选择稳定；不能把每个节点原样铺开。消息也需要合并同源重复提醒。
3. **窄屏牺牲了关系完整度。** 当前优先保证待回复事项与输入可达，关系图改为分组滚动；跨模块追溯不如桌面直观。正式移动工作面应以“处理事项”为主，长路径追溯进入详情。
4. **真实回执与恢复尚未接入。** 当前排队、处理、失败和过期都能在原型操作，但应用重启恢复、模型迟到响应、真实多 agent 事件频率还需随运行器接线验收。

下一轮人工验收直接给三项任务，不先解释界面：找出谁正在做事、找到为什么需要自己回复、给指定模块补一句要求并返回原草稿。观察停顿、误发、反复打开说明的位置，再决定是否补短标签或调整布局。
