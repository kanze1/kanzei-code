# Softwire V4 交互体验版

2026-09-28。用户暂定交互层级，要求先做新版进行试用。本次交付独立体验版，沿用 V3 的颜色与空间结构，不改动现有正式客户端或运行器。

## 已做成可操作的路径

- **项目 → 工作台 → 模块 → 依据**：所有模块均可继续打开对应原文、版本、工具调用、交接或请求清单。返回恢复入口与滚动位置；上下文/设置关闭后回到先前的依据页。
- **同一处输入**：进入依据不改变收件人；从工作网络发送会打开工作对话，发送后立即看到自己的原文和排队状态。
- **自动演示回执**：发送、版本变更、召回和批次收口无需手动推进每一步。按项目捕获目标，切到别处后照常处理原项目队列，不改当前收件人或草稿。回执标明演示身份，不推断用户自然语言已经完成的工作。
- **消息处理闭环**：快捷回答先进入输入框；处理后解除关联阻塞；已处理事项不继续显示橙色等待提示。回复框缩为“返回工作”，恢复处理消息前的位置与草稿。
- **固定版本的依据**：已打开的原文和请求清单绑定点击时快照，后续版本生效不重写它。
- **连续体验**：浏览器保存草稿、消息、排队、当前层级、设置与悬浮位置。刷新后恢复；损坏记录回退到初始场景，无法保存时仍可输入。体验选项支持重新开始和立即撤回。

自动演示只在存在排队动作或可继续验证的批次时运行，不定时制造新任务或无限工具活动。切换手动演示后停下自动回执，保留队列。

## 验收

真实 Chromium 页面通过 **121 项断言**：81 项原有交互/布局回归，加 40 项新增体验检查。两组均无 page error。脚本语法检查通过。

窗口包括 1440×950、1280×800、1050×735、1024×768、800×600、390×844、320×768。查看了工作网络、依据原文、处理后消息、悬浮和窄屏截图。验收中修复了缩窄窗口的悬浮布局时序、依据页顶栏占用过多、已处理消息仍显示等待状态、回复后回执落在可见区域以外等问题。

证据位于 `output/playwright/softwire/`：

- `check-workbench-v4-regression.mjs` / `verification-v4-regression.json`
- `check-workbench-v4-experience.mjs` / `verification-v4-experience.json`
- `v4-experience-home.png` / `v4-evidence.png` / `v4-receipt.png` / `v4-evidence-mobile.png`

## 体验入口与边界

运行 `node docs/prototypes/softwire/serve.mjs`，访问 `http://127.0.0.1:14078/`。端口可通过命令末尾的数字修改。

所有项目、agent、版本与提交仍是示例。浏览器输入只保存在本机浏览器；服务器只提供静态资源，不调用模型、不修改真实项目。真实管理角色路由、事件回执和长周期引擎接线沿用 [总体设计](../design/softwire_runtime_refactor.md) 的实施边界。

接下来主要通过用户试用判断：模块入口是否顺手、查看依据会不会迷路、收件人是否足够清楚、处理消息后能否自然返回。大量子任务与通知的聚合、真实系统输入法和真实运行器恢复仍未纳入本次体验验收。
