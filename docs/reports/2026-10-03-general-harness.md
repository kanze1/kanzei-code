# 无项目模式的 Harness 修正

日期：2026-10-03。用户要求无项目模式保留 Harness，只关闭项目门禁。已修复此前只提供网页工具、无法实际生成文件的问题。

## 最终行为

| 能力 | 当前行为 |
| --- | --- |
| 文件与产物 | 可以真实读取、写入、编辑文件，输出绝对路径链接并在应用中打开；每条聊天有独立产物目录 |
| 命令 | 普通命令、后台进程、交互式 stdin 继续使用共享运行时 |
| 子代理 | 默认开启，可关闭；持续消息与继续操作保留，可写子代理有隔离工作树和显式采纳 |
| 通用工具 | 浏览器、网页检索、绘图、LaTeX、记忆、全局技能和自定义角色保留 |
| 长对话 | 工具结果预算、自动压缩、手动压缩、停止和重启恢复保留 |
| 回退与分叉 | 沿用共享文件快照和对话回退；分叉复制对话前缀，使用独立产物目录 |
| 定时任务 | 无需添加项目即可定义任务；执行使用独立产物目录，历史保存在无项目存储根 |
| 项目流程 | 不提供需求/缺陷/想法队列等工具；不注入项目取活提示；关闭阶段、批次收尾、验收记录和强制提交 |
| 主动使用 Git | 可以普通暂存、提交与 finalize；无需 Cargo 工程、项目测试记录或事项 ID |

普通权限、文件过期检查、回退外部变化检查及暂存内容版本核对继续有效。无项目存储根不加入项目列表，也不覆盖最后选择的真实项目。

默认产物路径：`KANZEI_HOME/conversations/general/artifacts/<会话标识的稳定哈希>/`。可写子代理只在应用自有的会话产物目录按需初始化私有 Git 仓库；这用于隔离和采纳，不要求用户交付提交。关联项目复制为一条项目讨论，保留原聊天。

## 实现入口

- `kanzei-harness`：识别无项目存储根，提供每会话产物目录与 `ToolCtx.project_workflow`。
- `GeneralChatProfile`：共享桌面、CLI 和定时任务入口，保留通用工具/权限/技能/角色，移除项目工具与上下文。
- 运行器、Git、团队与定时执行：按 scope 关闭项目门禁，保留原有执行与持久化机制。
- 桌面组装与前端：旧会话迁移，展示子代理开关，开放通用能力，隐藏项目控制；回退使用对应会话的真实文件目录。

详细边界见 [设计](../design/general_chat.md)和 [使用手册](../使用手册.md)。
