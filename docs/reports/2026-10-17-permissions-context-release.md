# 文件权限、项目信任与上下文预算修复

本批修复来自 Claude 更新日志对照、p37 上下文审计和项目配置静态安全审计。基线为 e6e1ad56；最终提交与完整验证清单由本版 dist/verification.json 绑定。未包含主工作树中既有的缺陷归档编辑。

## 恢复的不变量

- 文件授权同时匹配请求路径及物理路径，目录联接不能使拒绝规则失效。grep/glob 对实际请求根和遍历发现的资源分别执行权限判断；未获批准的后代不进入结果。
- read/glob/grep/write/edit/insert 的访问范围为本次代码目录和项目根。实际读写通过目录能力句柄执行；写入沿用原子替换及读取指纹检查。授权后父目录被改为外部联接时，I/O 仍拒绝越界。
- grep 的普通、计数和上下文模式保留 I/O 失败，不能把失败报告为没有匹配。
- 文本读取逐段保留有限行前缀、流式丢弃超长行的其余部分；offset、limit、tail 不再要求整行分配。图片大小门禁保持有效。
- 压缩摘要的连接、流式响应及质量重试均可被停止；未完成摘要不提交历史替换和删除统计。
- 上下文容量使用 input + cache_read + cache_write。费用统计仍保留互斥分桶；历史缩减使用有符号估算差值，从旧 usage 锚点下调。
- 网页正文预览与链接清单分别标记截断，给出首个未读行的 from_line 参数；同会话缓存可续读完整保存正文。只有标题、脚本或 noscript 的 HTML 不登记为成功阅读证据。读取和搜索说明要求限定路径、复用已读范围，不能把封顶结果当作完整证据。

## 项目配置迁移

项目 `.kanzei/kanzei.toml` 和 `.kanzei/agents/*.md` 默认不执行。信任记录保存在用户目录 `project-trust.json`，绑定规范化项目根和每个文件的 SHA-256；使用已捕获的同一份批准内容进行解析。修改文件会使该文件的批准失效，新建 Agent 不继承旧批准。

用户审阅文件后执行：

```powershell
kz trust status --project-root "C:\path\to\project"
kz trust approve <审阅后的 fingerprint> --project-root "C:\path\to\project"
```

`kz trust revoke --project-root ...` 撤销配置、Agent 和该项目的永久授权。配置或项目模型设置修改后需重新审阅指纹。全局设置继续由用户目录管理。

“允许并记住”改写用户目录中的项目授权记录；桌面、手机和 CLI 共用同一存储。权限列表、删除和陈旧条目校验也使用该记录。旧项目 TOML 内的权限规则仅在文件获批后生效，不会被自动迁移为用户批准。

携带 API key 的 provider 必须使用 HTTPS；Codex 登录凭据只允许官方 https://chatgpt.com/backend-api/codex 端点。模型请求及设置页凭据测试不自动跟随重定向。

## 公网抓取边界

WebFetch 与 fetch_bytes 使用同一传输。每一跳解析并检查全部 DNS 结果，拒绝私网、回环、链路本地、元数据常用地址和保留网段；连接固定到验证过的 IP。通过代理时使用 CONNECT 到该 IP，原 URL 主机仍用于 Host 和 TLS 证书校验。重定向由工具逐跳处理，重新执行路径权限和地址检查。

传输使用系统绝对路径的 curl，禁用 curlrc，限制响应头、正文、诊断输出及请求时间。Windows 使用系统自带的 System32/curl.exe。

这些文件和网络边界不构成 Bash 的操作系统沙箱。Bash 仍以当前用户身份运行；用户批准的命令拥有对应的系统权限。不可信项目正文仍可能进入模型上下文，代理应将其作为资料处理。
