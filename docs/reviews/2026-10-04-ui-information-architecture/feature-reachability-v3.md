## 对话右侧如何响应调用

当前对话开始调用时自动展开，默认跟随最新工具类型。用户手动切换后保留所选标签；关闭后，同一轮的后续事件不重新弹开，仍能从正文结果恢复。主输入和子代理补充草稿分别保存。其他对话运行只更新自己的记录。

宽窗口并排显示对话和结果；980px 及以下使用可关闭的右侧覆盖面板；600px 及以下占满内容区。关闭恢复主对话，不清空消息。刷新暂停演示运行，保留记录，避免把已失去执行连接的工具显示为仍在运行。

正式接入时应按 `conversation_id + run_id + tool_call_id` 绑定事件和订阅，而不是绑定“当前项目”。子代理补充要求需要子调用身份；停止单个终端不等于停止整个对话。

## 已发布需求结构的呈现

本轮核对 HEAD `7b2b8096`，包含 `037185a8` 的需求结构更新；依据 [结构说明](../../reports/2026-10-04-requirement-contract.md)、[前端适配](../../../crates/kanzei-app/ui/26-requirement-contract.js)、[存储类型](../../../crates/kanzei-memory/src/docstore/requirement.rs) 与 [来源捕获](../../../crates/kanzei-app/src/requirement_capture.rs)。

- 展示使用 `entry.requirement` 的 `format: 2 / revision / spec / evidence / gaps` 形状。
- 首屏阅读 `statement`、带稳定 AC 编号的 `acceptance`，以及未决 `questions`。来源、关联、执行记录和原始字段可展开。
- `evidence` 独立绑定 AC 编号与需求版本。修改正文或验收含义后，旧证据保留，并标为待复核。
- 新建只要求原始描述，标题可以不填；正文/验收缺项或存在开放问题时保留草稿。补齐后仍需明确转为待开始。
- 原型编辑保留已有 AC 编号；新增项分配新编号；来源原文只读；旧格式的边界、迁移回滚与未知字段继续可读。

原型的版本标识和来源保存在浏览器示例数据里。正式写入应复用现有应用捕获与 tracker 契约，不再另建一套需求存储，也不把示例原文当成真实需求来源。

## 项目地图的来源和限制

生成器读取仓库根目录与各成员的 Cargo 清单，解析 workspace 继承、依赖别名、构建和目标平台条件，生成 8 个工作区模块、23 条直接依赖以及 531 个 Rust/前端文件索引。主图展示其中 22 条非纯开发依赖；依赖来源中保留所有类型。当前提交和清单指纹写入索引。

这是静态模块依赖和文件索引，尚不包含函数调用图、运行时调用链或所有外部包关系。更新源码清单后需要重新运行生成器；其他示例项目显示未生成，不借用当前仓库的数据。

## 还有什么未呈现完整

此前的功能盘点仍有这些缺口，不能因为每类都有按钮就宣称已全部覆盖：

| 缺口 | 正确归属 | 仍需补齐 |
| --- | --- | --- |
| 会话高级动作 | 会话右键/消息动作 | 重命名、置顶、回退分叉、交接、导出 |
| 提问与决定复核 | 待我处理 | 当前原型只实现交付；待回答和待复核决定还没有完整流程 |
| 工作条目依赖 | 需求/缺陷详情 | 阻塞原因、关联跳转、影响范围；与源码依赖地图区分 |
| 子代理工作树 | 右侧子代理详情 | 独立分支、差异、采纳、冲突和重启 |
| 真实后台执行 | 对话右侧终端 | 实际进程订阅、断线重连、退出恢复 |
| 真实网页工具 | 对话右侧预览 | 真实 URL/端口、浏览器控制、控制台和调试 |
| 规范建议稿 | 设置 → 开发规范 | 对照、采纳/丢弃、并发修改保护 |
| 记忆追溯与效果 | 记忆管理二级视图 | 图谱、详细来源、召回与使用证据 |
| 连接和高级设置 | 设置 | 服务商实际连接、远端宿主、手机配对、语音及真实计划执行 |

目前不需要再加一套一级导航。先将以上能力接回明确的所属对象，再补二级操作。研究和想法的正式代码退役仍属于后续正式接入，原有资料保留读取。

## 试用验收

重点是调用展开是否顺手、主动关闭后是否安静、切换对话是否保留各自上下文；再检查完整需求、项目地图和项目右键。具体操作、检查记录及范围见 [原型 README](../../prototypes/familiar-workspace/README.md)。
