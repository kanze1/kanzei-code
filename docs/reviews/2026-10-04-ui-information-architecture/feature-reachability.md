# 第二轮：功能可达性与产品边界

**历史版本。第三轮已取代本文的入口安排：** 子代理/终端/预览回到对话右侧；运行记录/规范/测试归设置；项目地图与交付并列；VS Code 只从项目右键打开；移除想法与重复记忆入口。当前定义与尚未覆盖的能力见 [第三轮功能归属](feature-reachability-v3.md)。下文保留第二轮盘点及源码证据。

日期：2026-10-04。依据用户对本地原型的六条反馈，以及当前正式前端、页面路由、菜单、调用入口和设计文档。附件和文档是分析材料，不覆盖用户本轮指令。

结论：**第一版原型没有覆盖所有现有功能。正式前端也不是没有功能，而是入口分散、部分入口被隐藏、同一作用范围使用了不同名称。** 第二版先完善用户指出的核心流程，并给其他能力确定归属；仍未完整模拟的能力在页面和本文中直说。

本轮修改的是 `docs/prototypes/familiar-workspace`，没有改正式程序、需求存储结构或真实记忆。以下“正式已有”表示核实到源码接线，不等同于本轮重新完成桌面实机验收。

## 1. 六条反馈如何落地

| 反馈 | 第二版处理 | 正式接入要点 |
| --- | --- | --- |
| 文件管理没必要 | 撤掉文件页；页头、管理页及差异面板提供 VS Code 入口 | 复用已有 `open_with`，传正确项目/工作树；不再做一个编辑器 |
| 记忆应是全局管理 | 左下「记忆管理」汇总全局和所有项目；范围、项目、状态、搜索、完整条目、管理对话分开 | 不能依赖当前聊天项目；条目身份必须包含存储范围和项目 |
| 格子批次、完整需求、交付平级 | 需求 / 缺陷 / 交付同一行切换；批次仅显示格子；点击进入整页详情 | 展示适配层接当前条目结构；保留原文与未知字段；不预定正在调整的存储结构 |
| 研究模式砍掉 | 新方案没有研究工作区、模式、课题或论文工作流 | 需要退役整条专属链路，不能只隐藏一个按钮，见第 6 节 |
| 红绿差异 | 增加绿色、删除红色；独立于运行/成功/错误颜色 | 保留原差异视图和动作语义 |
| 所有功能是否可达 | 增加设置、定时任务、项目工具、功能对照与搜索入口 | 用实际动作链验收；菜单文字存在不等于完成 |

“可交互”指原型中的本地示例流程；只有 VS Code 打开按钮实际调用本机编辑器。

## 3. 入口为什么难找

### 真实存在的隐藏

`workbench.css:133–136` 用 CSS 隐藏了活动栏大多数 `data-view` 按钮，开发空间通常只保留设置。HTML 里存在按钮，不代表用户能看见。

`21-palette.js:38–44` 收集视图时只检查 `.hidden` 类，没有检查 CSS 最终可见性。因此一些页面仍可能从命令面板进入。应称为“视觉入口隐藏/发现性差”，不能直接判为死路由。

`25-softwire-view.js:34–39` 把记忆、文件、架构放在概览的“记忆”行，把历史与并行线路分散在其他行，运行画像又在用量行。这种嵌套要求用户先知道内部分类。

`12-session-menus.js:349` 又把外部打开工具放入二级菜单。VS Code 能力早就存在，新增一级文件页并没有解决最常用的打开动作。

### 交互复杂的主要来源

1. **对象混用。** 需求列表里出现聊天文字；交付被当成需求附属区；项目工具挤进“记忆”一行。
2. **范围混用。** 全局记忆必须先选项目；应用后台状态贴着发送按钮；权限默认值与下一轮配置并排却含义不同。
3. **名称混用。** 实际管理页叫“概览”；“全部记忆”实际只是当前项目加全局；“待我处理”不能只统计交付。
4. **详情过浅。** 窄侧栏适合临时核对，不适合阅读完整需求、依赖和验收证据。

第二版的常用路径是：对话一步进入；模型/思考/模式点开即选；管理点分类再点条目；记忆从左下直接进入；VS Code 从页头直接打开。低频项目能力多一步进入“项目工具”可接受，但运行中的子代理/终端仍应从当前运行就地进入，不能强迫用户先去管理页。

## 4. 记忆页需要纠正的不是一句名称

正式 `13-memory.js:180–202` 绑定 `currentProject`，没有当前项目便不加载；`:1229–1239` 的 all 只展开 project/global 两种 scope，并不遍历全部登记项目。`src/memory.rs:8–14` 也为一次调用创建当前项目与 global 两个存储。

所以要做真正的统一记忆管理，需要：

- 全局管理路由无需当前项目也能打开；项目筛选是浏览条件，不是切换当前聊天对象。
- 管理查询接受明确的 owner/scope；所有项目聚合时能够区分读不到的项目，不将其当作空结果。
- 所有打开、编辑、归档、恢复、溯源与管理对话都传入 scope + project/store + id。同样的 `M-001` 不能串号。
- 管理对话显示目标范围，跨范围切换分别保存草稿；主聊天草稿和接收者保持原样。
- “能保存全局记忆”“能列出全局记忆”“执行时会跨项目召回/注入”是三件事。`memory_system.md:18–22` 已记录保存和普通检索仍有差异，统一页面不能宣称已经解决运行时生效。

第二版仅验证这些范围、导航与编辑交互；不会绕过正式记忆生命周期和来源校验。

## 6. 研究退场清单

用户已经明确删掉研究模式，设计不再保留开关或“可选专业工作区”。正式代码仍有以下链路，后续实施需要一次对齐：

1. **页面和路由：** `03-workspaces.js`、`03-research-library.js`、`19-research*.js`、`index.html` 中空间切换、课题、文献、来源/发现/报告/论文页以及相关样式。
2. **运行选择：** `08-compose-runtime.js:1079` 的 research 模式、会话创建/恢复与默认 profile、research 自动流程、代理定义及注入。旧 research 记录只能历史读取，不能因自动 fallback 转成可写开发任务。
3. **定时任务：** `24-schedules.js` 仍有研究选项；已有计划需明确停用/迁移，不能静默换成开发任务执行。
4. **后端注册：** `src/main.rs:298–306,378–384` 的课题、文献库、自动流程、计划批准、LaTeX 和 arXiv 专属应用命令；移除接线后核查独占依赖。
5. **历史数据和文档：** 旧报告、文献、实验记录保留文件访问/导出；产品导航和旧偏好恢复不再暴露研究工作区。
6. **共享能力复用：** 网页搜索、抓取、阅读文档、代码实现前调研、通用 SSH/命令执行仍服务开发。研究专属实验/论文编排退出，不按 `research` 字符串全库盲删。

退场完成标准：冷启动、旧偏好恢复、旧会话、命令面板、定时任务、错误重试都不会重新出现或启动研究模式；真实文件能从编辑器继续访问。当前原型符合入口方向，正式代码退役尚未实施。

## 7. 接入顺序与验收

1. 先试用第二版的导航、宽详情、格子进度、全局记忆和红绿差异。这些决定呈现方式，不绑死新数据结构。
2. 对接真实项目/条目/交付，复用外部编辑器与现有运行控制；保留原始字段、证据、未知扩展字段。
3. 改记忆查询与目标身份，让全局页脱离 `currentProject`；单独验证 global 保存、查询及运行时使用，不能靠列表出现就算完成。
4. 搬迁其他现有入口，补齐会话菜单、依赖、决定复核、图谱和高级设置；保留正在运行的对象与订阅。
5. 完成研究退役和文档身份对齐，再执行正式前端/后端与桌面验收。

核心验收：没有丢功能、没有改变消息接收者、没有把示例或机器通过当用户认可、完整条目不丢字段、项目/记忆范围不串、常用动作仍能按原习惯找到。
