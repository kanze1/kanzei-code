## 建议验收五组操作

1. **日常对话**：新建对话、切换模型、发消息；切换管理再返回，确认草稿还在。展开活动栏，检查输入框不会被挤没，更多菜单能打开。
2. **需求管理**：点需求进入完整详情，核对 AC、来源、开放问题和证据；编辑未保存时切换页再返回，确认草稿保留。列表只显示格子进度；需求、缺陷、交付和地图能直接切换。
3. **工作选择**：选择一个可执行需求后发消息，核对绑定的需求编号。运行中改选应在下轮生效；被别的对话占用、阻塞或已结束的条目不能被抢走。失败发送保留草稿。
4. **活动和网页**：让 Agent 调用子代理、终端和 browser open；子代理/终端出现在活动栏，网页单独弹出。拖动、缩放、最大化再恢复；输入时自动弹出不抢焦点。关闭网页后不要反复自动弹出，切换对话不能显示别人的网页。
5. **项目地图与记忆**：点模块检查局部依赖，再切换运行统计范围；缺失数据显示「—」。在记忆管理选择另一个项目，返回原对话发送时仍应发给原项目。

## 数据与验证边界

浏览器回归使用隔离 IPC 夹具，不修改真实台账；桌面试用程序才会读写实际数据。原生网页的拖动追随、实际 WebView2 页面缩放、遮挡冻结以及连续 Agent 操作，尚需按上面第 4 组在桌面程序验收。

项目地图当前读取 Cargo 模块清单，不支持的项目显示缺失说明。运行统计在最近最多 200 轮、200 次记忆观测内筛选；平均时长排除缺失计时，失败不包含规则拒绝，召回/注入/读取分开，未观察不补零。统计用于观察运行，不据此声称记忆有效。

旧概览六模块、研究空间和原停靠式网页的布局用例退出当前 UI gate；新工作区用例代替它们。异步归属、交接、回答、权限、会话、需求契约和通用控件回归继续运行。上述记录是试用构建验证；正式发布另外执行绑定提交的 `scripts/verify.ps1 -Full` 和 `scripts/package.ps1 -Publish`，以 `dist/verification.json` 和发布回执确认结果。
