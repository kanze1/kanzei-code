# 通用输入状态与文件编辑链审查

基线：7287f1ca。按 `SessionStore → app/CLI 输入服务` 和 `base CAS → 文件服务 → 编辑器` 两条依赖链推进。A 家支持范围暂不处理。

状态所有者：SessionStore 拥有输入及生命周期事件；文件服务拥有磁盘写入、CAS 和写日志；编辑器拥有当前 model、未保存版本及草稿。历史依据：R-173/D-173（输入生命周期）、R-253（输入域拆分）、docs/design/files_editor.md（文件编辑、冲突和草稿）。没有更换数据库格式或添加依赖。

以下明确标注全文或调用链切片；切片不代表整个文件审查完成。

## crates/kanzei-core/src/store/inbox.rs

### 职责
输入准入、排队、提升及执行意图存储；全文审查。

### 判断
P1

### 确切问题
- 原来准入/提升先提交，再由 caller 单独写事件；事件写入失败会返回错误，但输入已入队或已提升，造成状态与调用结果分叉。

### 修改
- 将 prompt.admitted、prompt.promoted 写入同一事务；批次/工作条目准入复用已有事务，避免嵌套事务。
- 新增 admit_input_with_source 保留后台通知来源；重复准入不重复记准入事件。

### 影响范围
- app 输入、运行装配、验证通知、异步回调及 CLI；调用方不再另写相同事件。
- 事件字段及数据库 schema 不变，之前漏记的入口现在也产生准入事件。

### 验证
- SQLite 触发器注入事件写失败：普通/批次/工作准入全部回滚；提升第二条失败时整批仍为 pending，无半批事件。
- 重试成功、重复准入只有一个事件、提升顺序及重复提升为空均有断言。

## crates/kanzei-app/ui/17-files-editor.js

### 职责
编辑 model、保存、冲突、草稿和文件切换；全文审查。

### 判断
P1

### 确切问题
- 保存等待期间继续输入，旧版本保存成功后仍允许离开，丢失新输入。
- 打开另一文件等待期间继续输入，迟到的预览会释放仍有新修改的旧 model。
- 重载前先清草稿，读盘失败时失去持久化备份。

### 修改
- 保存后重新检查文档身份和 dirty 状态；异步打开应用前核对原 model 版本，发生新编辑则保留原文件及树高亮。
- 重载成功后才删除草稿，重载时禁止用旧草稿覆盖刚读到的磁盘版本；确认框返回时核对文档身份。

### 影响范围
- 文件切换、离开、保存、放弃修改和重载；IPC/草稿格式不变。

### 验证
- 延迟 file_write/file_preview 的确定性回归证明新输入不会丢；删除文件导致重载失败时不调用草稿清理。
- 修复前回归失败日志 editor-before-20261003.log；修复后完整 UI 运行时、浏览器测试通过，Files editor 18 checks。
