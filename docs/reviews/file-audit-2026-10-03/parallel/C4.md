基线 0e5355c6，独立分支 kanzei/audit-c4-session-owner。本包先建立 [caller/状态/锁地图](C4-map.md)，再修根因。新增 session_execution.rs 和真实进程 fixture 全文检查；其它九个已审文件只重开必要切片，不重新统计全文 coverage。无 schema、事件格式或第三方依赖变化；没有修改真实 state.db、凭据、coordinator、app persistence、scheduler executor。

按三项根因计数：C4-01 活跃执行被恢复/重置；C4-02 FIFO 正文与身份错配；C4-03 CLI 失败/终态收尾合同未落实。以下多个文件共同修复同一根因，不重复计数。

本包最终正确源码验证：core413、CLI单测54、CLI集成46、app555通过，0失败；三个直接包 all-targets check/Clippy -D warnings、全workspace fmt、diff检查均 exit0。旧production负对照5/5实际断言失败；terminal等价旧行为实际退出成功却无完成终态。负例恢复SHA256+mtime后，正确core/CLI及terminal真进程再次验证。Cargo已明确释放，root统一基线后的整合检查另计。

## crates/kanzei-core/src/store/session_execution.rs

### 职责
新增专用 primitive，拥有同 canonical DB/session 的跨进程执行权。

### 判断
P1（C4-01，共同根因）

### 确切问题
- 原入口没有活跃 owner；A 的真 provider 请求仍存活，B 能恢复/重置 A 并同时执行。

### 修改
- 复用既有系统 FileLock，稳定 canonical DB/session key；独立线程 acquire/drop，Send+Sync guard 只拥有释放通道和 join。
- busy 立即返回；prepare 验证 DB/session，writer Arc 保留 owner 到晚回调和输入收尾；进程死亡由 OS 释放。

### 影响范围
- 直接 caller：CLI run、app schedule_run/assembly、typed 的公开短恢复入口。
- 新增 state.db.session-owners 锁目录；不修改数据库/序列化合同。team 可复用 namespace，C4 不改 team。

### 验证
- 四条真实临时 DB 回归：路径别名/public recovery/最后 writer Drop 互斥；错误身份零修改；输入与 typed 恢复同事务回滚；terminal 拒绝后 owner 保持至失败收尾。
- 真双 CLI held HTTP 和实际强杀回归，OS 崩溃释放及恢复一次得到证明；Drop worker 不访问 DB/runtime/guard Arc，无 join 自锁或反向锁序。

## crates/kanzei-core/src/store/typed.rs

### 职责
持久 typed 事实、恢复和 writer（仅 prepare/recovery/writer 生命周期切片）。

### 判断
P1（C4-01，共同根因）

### 确切问题
- Immediate 可原子追加恢复事实，但不能证明其它进程死了；公开恢复可闭合仍在运行的 turn。
- 崩溃恢复只处理 typed draft/tool/terminal，旧 promoted/running 输入仍残留。

### 修改
- 公开 prepare/recovery 用同 key 短锁；真正执行用 owned helper，不重入获取长期锁。
- 同 Immediate 追加恢复事实并失败 orphan claims；保留当前已声明 input。writer 私有 Arc 保留执行 owner。

### 影响范围
- CLI/app 所有 prepare caller已查；rewind facts 为空的兼容短恢复、其它测试 caller保持签名。
- C2 source/floor/checked append、C3 message receipt和 A2 source CAS不变；内存 DB 保持既有语义。

### 验证
- core 全包、错误身份/SQL rollback/last Drop/public recovery忙态回归；实际强杀 draft 后恰一份 interrupted 和 failed terminal。

## crates/kanzei/src/cli/run.rs

### 职责
CLI 会话执行入口与本轮输入装配（必要入口切片）。

### 判断
P1（C4-01、C4-02）

### 确切问题
- 原 prepare/--new/promote 不与同会话活跃执行互斥。
- 原 promote 得旧队首 A，正文却继续用新 argv B，user/provider/episode 与 input ID 不一致。

### 修改
- owner 先于恢复、--new、admit；writer 由 owner生成并持有。
- 使用实际 promoted.prompt；新 argv 留 FIFO pending，不把新 invocation autonomous策略给旧输入。
- 搜齐五个 input 字段及 work/batch额外元数据；CLI 不支持桌面载荷时明确失败该 claim并保留新 pending。start_input false明确 Err。
- Ctrl-C finalize_interrupt 收尾后回传 typed terminal 拒绝，避免假成功。

### 影响范围
- user fact、provider/body、prompt hints、episode/finish 均来自同 promoted 输入。
- busy 不 admit/reset；本地既有 FIFO 与 queue/steer承诺不变；无新 flags/API格式。

### 验证
- 真双 CLI held POST、busy --new、retry、强杀；A/B fixture 检查 provider/user/episode/pending；不支持 work载荷无 POST且旧输入 failed。
- 精确旧 production负对照5/5真实断言失败，恢复字节/hash/mtime后正确代码再次全通过。

## crates/kanzei/src/cli/run/finalize.rs

### 职责
CLI typed终态、会话状态与 input/episode 收尾（必要 failure切片）。

### 判断
P1（C4-03）

### 确切问题
- provider Err 的 run_result? 早于 finish_input，输入一直 running。

- 正常 provider Err 在返回前 durable failed；成功输入收尾必须成功。公开 finish签名不变。

### 影响范围
- 直接 caller：run_cli 的正常 finish和 Ctrl-C；持有 owner直到收尾/回调释放。
- app/scheduler同类失败由后包收口，本包没有改其它 terminal caller。

### 验证
- CLI helper真 durable terminal拒绝回归；真 CLI HTTP不完整响应输入failed。
- 真 CLI SQLtrigger仅拒 turn_completed：正确 exit1/input failed/session failed/完成terminal0；等价旧行为 exit0/completed/idle/terminal0，真实假成功得到证明。恢复SHA256后再验证正确binary。
