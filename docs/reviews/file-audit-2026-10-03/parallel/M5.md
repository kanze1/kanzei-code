## crates/kanzei-memory/src/docstore/parse.rs

### 职责
将 markdown 投影为 Entry 与原布局模板，识别状态/severity 并提供共同标题清理。

### 判断
P1

### 确切问题
- 解析循环两次剥离 status：合法“实现 [RFC] [todo]”被解析为 RFC 状态，调度将正常任务判 INVALID；“旧标题 [todo] [fixed]”又被解析为 todo，隐藏最外层非法状态，破坏 D-332 fail-closed。
- 同根因也重复剥 severity：缺状态的合法存量更新标题为“新标题 (high)”且保留 low，下一次 load 把标题截断并将 severity 改成 high。

### 修改
- 每个 header 各认领最外层一次 status/severity；下一次剥离仅兼容另一种 metadata 的位置。标题原文留给既有 validation/normalize，不替调度修改状态。
- 补全部七种文档的实际 render→parse 往返、非法外层状态、历史标题标记、两种 metadata 顺序。

### 影响范围
- repository/归档读取、memory migration、work/tracker/scheduling、app docs/workspace 投影；未改变公共签名或 markdown 格式。
- 未知外层状态继续保留并 fail closed；vec[index]、括号标题与单行字段原语保持。

### 验证
- 5 个实际 parse 测试通过；旧源码 4 个断言失败，正常 severity 顺序测试通过。真实 Tracker add/update→文件→load 两项回归通过；单独恢复旧 status/severity 分支时分别出现实际断言失败，均非编译失败。
