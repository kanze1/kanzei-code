## crates/kanzei-harness/src/project_root.rs

### 职责

入口发现/显式解析项目根，比较目录身份，防止项目数据与 HOME/全局根混用。

### 判断

P1 已修：发现式解析忽略 Git worktree/submodule 的 `.git` 文件。

### 确切问题

247行 git_marker 仅 `.git.is_dir()`，而显式入口66行认 `.git.exists()`。普通 worktree/submodule 根有 gitdir 指针文件但尚无 `.kanzei` 时，从它的子目录运行 CLI main_project_root(None,cwd)→resolve_project_root→discover_project_root，会跳过实际 Git 根：无其他标记时返回子目录，有祖先标记时返回祖先项目。配置与 state.db/tracker/记忆从而绑定到错误项目。ToolCtx 现有 worktree 测试覆盖的是同时有 `.kanzei` 的分支副本，不能覆盖此场景。

### 修改

已将发现式git_marker改为exists，与显式校验一致；不自动跳到主worktree。gitfile_root_wins_over_ancestor_marker_from_child 写入测试gitdir指针，覆盖根自身、嵌套子目录和上级另有.kanzei marker三种取根结果。

### 影响范围

CLI 启动/一次性查询、配置发现、ToolCtx::discovering 和 app 的根发现查询；运行期显式携带主根的链路不重新发现。

### 验证

基线全文523行、修后551行，所有文件内测试已读；核实 cli/mod.rs:340–353、config.rs:177、tool.rs:123、projects.rs:325/340、memory_consolidation.rs:552。路径折叠、HOME/temp排除、显式路径不canonicalize的既有约束已核对。使用临时 gitfile fixture，不创建额外工作树；git diff --check、执行回归与旧行为负例均通过。
