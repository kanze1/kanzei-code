# A3：权限 UI 的项目与规则身份

基线 `441e0c2983b8e8aeaf287bfc330d3df76d5b01b2`，分支 `kanzei/audit-a3-ui`，复用 B 工作树。全文审查 `07-events.js`、`16-settings.js`；其他源码只读，已有脚本仅适配必要 fixture。本包仅本地提交七个明确文件，未运行 Cargo、未发布。主代理负责 M3 后端事务与 coordinator 的来源字段，再统一验证 IPC / 全量 UI。

## 依赖与状态地图

`harness permission Rule / 项目配置事务 → app settings Tauri commands → ui/16-settings.js 权限列表 / ui/07-events.js 记住与撤销`。

后台路径为 `RuntimeDeps.project_root → coordinator emit → UiEventSink PermissionResolved → 01-core.on / withSessionRender → 07-events blockedToolCalls / tool-end → permission_rule_add`。

- 项目 `.kanzei/kanzei.toml` 的权限规则是持久真源；UI 保存的 index 只是列表快照位置。
- `16-settings.js` 拥有最近权限列表和请求代际。列表、行按钮、确认、错误 retry 必须保留加载时项目身份；`currentProject` 只用于检查当前是否仍允许操作该列表。
- `07-events.js` 的既有 bounded `blockedToolCalls` 保存非交互拦截的操作身份；增加来源项目，不新增注册表。`01-core.withSessionRender` 只切换 pane/stream 状态，不切换 `currentProject`，因此不能从当前项目推断后台事件来源。
- native 来源使用 `RuntimeDeps.project_root`，它由 assembly 的 `request.main_root` 装配，与权限配置 owner 相同。没有从 session ID、pane 或工作树路径猜测来源。
- 并发边界是 IPC response / confirm promise / 后台事件抵达与项目选择之间的异步交错。删除的读写原子性由 M3/D1 配置事务负责。

已搜索所有 `permission_rule_delete`、`deletePermissionRule`、`renderPermissionRules`、`loadPermissionRules`、`mountBlockedAllow` 和 `permission-resolved` 的定义与调用方。UI delete 仅设置页与记住撤销两处；设置页 renderer 由 load、语言重绘和 runtime fixture 调用。直接读取了 shell/general scope、core 路由、sessions 项目切换、native coordinator/assembly/events 和 settings 接口。

设计依据为 [D1 实际根因地图](D1-map.md) 的 D1-C4。以下两个文件的表现共享这一项 P1，不按每个交错重复计数。已有 A 家专属代码按范围暂停；其余正确逻辑保持原样。

## crates/kanzei-app/ui/07-events.js

### 职责
消费运行事件，维护提问、工具结果及权限记住/撤销的 UI 交互。

### 判断
P1

### 确切问题
- 撤销查询返回 rule/index 后，另一个窗口删除前项，旧 index 可删除替代规则；旧请求没有携带完整预期规则身份。
- A 会话后台 PermissionResolved/tool-end 进入旧 pane 时，B 已被选中；记住按钮捕获 `currentProject=B`，将 A 的规则写入 B。

### 修改
- 撤销仍使用原捕获项目，查找 `action/resource/effect=allow`，删除传入完整 `expectedRule`，由同一配置事务核对当前位置。
- 既有 blocked 记录保存 native `projectDir`，按钮按来源项目记住。旧 payload 缺来源时显示明确原因并禁用按钮，不推断项目。

### 影响范围
- `permission_rules_get` / `permission_rule_delete` / `permission_rule_add` 直接 caller；工具结果按钮、撤销 toast 与持久项目规则。
- delete IPC 新增必填 `expectedRule:{action,resource,effect}`；native `kz:permission-resolved` 新增来源 `projectDir`。主代理适配后端/coordinator，不改全局 `withSessionRender`。
- 旧事件缺字段可渲染工具结果，但不能记住权限；配置格式与现有规则字段不变。

### 验证
- 实际完整 JS 模块执行记住→撤销，控制查询 promise 后移动规则位置；替代规则保留且冲突可见。
- 实际 07 订阅者接收旧 pane 的 PermissionResolved/tool-end，切到 B 后点击，A 新增规则、B 保留；缺来源 payload 无新增 IPC。
- 此定向 fixture 不执行 native coordinator 或真实 01-core 路由；这两段读取确认，主代理整合后补统一 IPC / 全量 UI 验证。

## crates/kanzei-app/ui/16-settings.js

### 职责
读取、展示和保存设置，维护权限列表及删除确认的交互状态。

### 判断
P1

### 确切问题
- A 的晚响应或错误覆盖 B 列表，同项目的旧请求也能覆盖较新结果。
- 行按钮确认等待、错误 retry 或语言重绘后重新读取当前项目，可把 A 的 index 用于 B 的删除。

### 修改
- 请求捕获项目与递增代际，仅当前项目的最新响应/错误发布；项目变化先清空旧列表。
- renderer 保存原项目；按钮在确认前后、delete 前及 retry 前核对项目。IPC 使用原项目和完整预期规则，成功后只为仍选中的原项目刷新。
- 语言重绘保留最近列表的项目身份，不把旧行重新绑定到当前项目。

### 影响范围
- `loadSettings`、删除成功刷新与语言事件是直接 caller；权限列表、确认/重试及持久规则。
- `deletePermissionRule` 的内部 UI caller 增加必填项目；`renderPermissionRules` 保留单参数兼容缺省，生产 load/语言 caller 显式传来源。
- 没有更换 persistence、框架或依赖。

### 验证
- 控制 A/B IPC 的真实返回先后、同项目请求返回先后、晚错误、确认中切项目及旧 retry；没有错误列表发布或 B 规则删除。
- 普通删除仍成功，调用包含原项目与 action/resource/effect 三字段；加载/重绘/确认的 invariant 均有执行断言。
- 全文核对 reasoning 读取/保存：HTML 已有 xhigh，UI 保持 xhigh 并如实提交；主代理复核当前清洁后端也已支持 xhigh，此区域 PASS，不计新问题、无修改。
