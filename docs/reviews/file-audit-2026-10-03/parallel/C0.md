## crates/kanzei-core/src/store/session.rs

### 职责
数据库打开、会话生命周期、迁移备份与恢复、引用计划及显式删除；全文审查。

### 判断
P1

### 确切问题
- v7 恢复在主迁移事务之前把 cancelled 改成 completed。随后迁移失败会保留恢复写入，schema 却回滚，产生状态分叉；旧 CHECK 仍不接受 completed 时还会吞掉恢复错误。
- 显式整理在读取无引用计划及静止性后，先 VACUUM 再沿用旧候选删除。期间新准入或引用能够提交，已有 artifact 会被按旧计划误删；会话删除后的引用重查与物理删除也缺少 writer 互斥。

### 修改
- 备份通过独立只读 SQLite 连接读取 promoted IDs；主库恢复写入和恢复计数在 schema 主事务内完成，错误传播并回滚。坏/过旧备份保持原有跳过规则。
- 收敛 artifact 删除到一个私有 helper：Immediate 事务内重查静止状态及全部当前引用，保持原候选集合，覆盖物理删除到事务结束。新创建文件不会被额外加入删除范围。
- 会话数据删除已提交之后，清理失败/新活动只写入 artifact_cleanup_errors，保留文件及可重试结果。

### 影响范围
- migrate、显式 CLI/app 清理、delete_session/purge_session；公共返回格式不变。
- 保持 0d0875ab 输入准入/提升与事件原子契约；删除期间其他 SQLite writer 无法提交准入/引用。
- **未登记数据库活动的手动压缩 archive 窗口仍未闭环**，见剩余风险；本包不声称已解决全部 artifact 生命周期并发。

### 验证
- `failed_upgrade_rolls_back_legacy_recovery_and_can_retry`：v6 库、v4 备份、路径迁移触发器注入失败；输入 cancelled、版本 6、恢复计数未提交，备份可用，删除触发器后重试成功。
- `cleanup_rechecks_stale_plan_and_serializes_admission_through_deletion`：计划形成后另连接提交引用，被引用文件保留；删除回调中另连接准入返回 SQLITE_BUSY 且无输入/事件，删除结束后准入成功；新文件不扩大候选，后续 pending 输入阻止删除。
- 既有存储统计、共享引用、只读删除拒绝、purge 缺失引用、恢复证据与通知删除、清理失败/活动守卫测试均通过。

## crates/kanzei-core/src/store/schema.rs

### 职责
旧库升级、列/对象补齐和数据迁移；全文审查。

### 判断
P1

### 确切问题
- v6 的历史 promoted 回填没有旧版本门槛，每次后续升级都会把较旧 promoted 推断成 completed。现代 promoted 可由提前提升、异步装配或进程中断留存，不能替 runner 编造完成状态。
- v7 恢复调用位于主迁移事务前，故后续失败未整体回滚，根因与 session.rs 同一问题。

### 修改
- 只对版本 <6 的旧库执行 promoted 推断回填；v6 及以后保留真实输入状态。
- 在旧 session_inputs CHECK 重建之后、主事务提交之前调用 v7 恢复。

### 影响范围
- 所有 SessionStore::open/open_in_memory 的升级路径；现代输入仍由 start_input/finish_input/finalize_interrupt 拥有状态转移；schema 对象、版本及字段不变。

### 验证
- `modern_upgrade_preserves_promoted_inputs_without_inventing_completion`：v24、已超过保护窗的 promoted 升级后保持 promoted，真实 runner 仍能 start 并以 failed 完成。
- 旧 v5 promoted 回填、保护窗内输入不回填、v7 备份恢复/真取消不复活、v10/v11 缺列升级、v23 检查点补齐、上一版补列/索引、备份及拒绝更高版本共 14 项 schema 测试通过。
- 故障触发器证明 v7 恢复、计数、schema 和路径迁移一起回滚且可重试。
