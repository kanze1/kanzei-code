## crates/kanzei-tools/src/schedules/executor.rs（完成终态切片）

### 职责
本切片将 prompt 运行的持久化 Completed 转换为 execute 的成功或失败结果。

### 判断
P1

### 确切问题
- TypedSessionWriter::finish(Completed) 写入失败仍直接返回 Ok(previous)，execute 继而写 run_finished.ok=true、session completed，并覆盖成功回写目标。
- WriterGuard::drop 的 Stopped 可随后成功，不能撤销已算出的成功 Outcome。这是 C4 移交的真实 caller，SQL trigger 只拒绝 Completed、不会拒绝模型或 assistant commit。
- 同一明确拒绝路径如果仅返回 Err，Drop 仍写 Stopped；枚举 reason 为 stopped_by_user，projection 区分 stopped 与 failed，已知保存失败不能记成用户停止。

### 修改
- 同一 writer 临界区 finish 后检查已有 is_terminal；未提交终态就返回包含持久化错误的 Err，沿现有 outcome.ok=false、失败状态和回写策略传播。
- 仅这个已知 Completed 被拒的路径，沿既有 finish(Failed(error)) 记录真实失败，再返回原 Err；不扩大其他取消或 early-error 路径。

### 影响范围
- public execute 直接 caller 为 app spawn 与 CLI schedule run；私有 run_steps 仅 execute 调用。
- writer 公共 API、Outcome JSON、DB schema 与事件格式不变。原返回错误分支使 CLI 非零退出、app 结果失败。
- 仅完成切片，不把 executor 其他功能计全文 PASS。

### 验证
- 新 fixture 实际运行 kz schedule run：本地 provider 接到真实请求后，在临时项目 SQLite 安装拒 Completed 的 trigger，再释放正常 SSE；检查 outcome、run_finished、session 与原回写文件。
- 实际 CLI 两控制通过：正常 Completed=1/Failed=0/Stopped=0、exit0、成功回写；拒绝时 Completed=0/Failed=1/Stopped=0、exit1、Outcome/receipt=false、session failed、Failed payload 保留 SQLite 原因，原回写文件不变。
- 旧 void 逻辑真实负例是 Completed=0/Stopped=1，却 exit0/Outcome=true、session completed、receipt=true、文件被改为 done。第一版只返回 Err 的真实对照仍 Failed=0/Stopped=1，新增事实断言失败；最终两负例均修复。
- tools 调度 10/10；三包 all-targets check、Clippy -D warnings、fmt 通过。负例源码精确恢复，哈希一致、刷新 mtime 后实际重新编译。

## crates/kanzei-app/src/schedules.rs（全文）

### 职责
应用 timer 扫描与手动操作入口，协调定义 CAS、host 登记/失败恢复、运行服务与结果事件。

### 判断
P1

### 确切问题
- 每个桌面窗口和隐藏 service 都从 main 启动 scheduler；原入口缺 owner gate，窗口可抢到 durable claim 并拥有任务，关窗会中断本应由 service 继续的任务；claim 保证互斥但不保证生命周期归属。
- list 的正文和 revision 来自两次独立读取，允许旧定义配新指纹并绕过 stale-write 检查。
- 同一版本合同还漏掉缺失态：旧 editor 携带 Some(revision)，另一窗口已删除定义时 previous=None，原检查跳过并把旧编辑当新建，复活已删除任务。

### 修改
- scheduler 沿已有 service 或 embedded 归属启动，继续服从 off/E2E gate。main 的统一 spawn 入口保持原合同。
- list 消费底层同读配对，不再重读定义计算指纹；私有 helper 仅提供 after_load 测试屏障，生产传 no-op。
- 私有版本检查完整比较 Option<当前hash> 与 expectedHash；Some 与缺失冲突，None+None 仍允许新建。run/history 仍无需 revision。
- 已有短 FileLock、进程内编辑 mutex、host 错误恢复及原文 CAS 写原语保持，未发现需改的实际问题。

### 影响范围
- scheduler 唯一 caller main；schedule_action 由 Tauri 注册并经 runtime_service route，UI24 是直接 UI caller，General 原生 fixture 沿原参数消费。
- 扫描和任务通知归运行 owner；共享 claim、手动 run、system/server host 语义不变。没有新增 persistent 字段或 IPC 参数。

### 验证
- 新增 owner/gates、真实 list 读后外部修改→旧保存拒绝、实际删除合法任务后旧 editor 拒绝且新建可用回归；5/5 通过。保留原有 General 扫描、CAS/恢复不覆盖外部编辑测试。
- 旧 app 逻辑 3 项真实数据断言失败、2 PASS：desktop gate、旧正文实际覆盖外部 B、已删定义实际 recreated=true。无编译失败；精确恢复与重新编译后 5/5。
- 读了实际 service/embedded/route 与 main spawn，确认 owner gate 放于 scheduler 入口。未执行 native 多窗口关窗运行场景，不将静态 caller 核对写成原生测试。
