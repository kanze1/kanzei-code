## crates/kanzei-tools/src/background/lifecycle.rs

### 职责

后台 guard、合法写窗口吸收、停止、项目/子任务回收与托管文件恢复。本包全文读取含所有函数；测试在父文件按必要切片核对。

### 判断

P0

### 确切问题

旧 stop 在最后 guard 未结束时回执成功；其后合法 tool_scope 已关闭的文件仍被旧 guard 回滚。停止后 observer 仅筛 is_running，遗漏收尾中的合法窗口。另实际 quarantine IO 失败被吞，停止/回收可错误成功。分别属于 P0 合法数据回滚、P1 失败合同根因，各只计一条。

### 修改

stop_owned 共用既有 exit/guard Shared completion，完成后消费唯一 finish_restore。正常 guard join Ok 是清理成功收据；终结失败可在原 baseline 锁下重新恢复并发布 GuardTask::Recovered。复核、恢复和发布同临界区；成功后 stop/reaper/child wait/retry 不再重放旧基线。未成功的守卫保留合法窗口吸收。bool/usize API 保持，失败有具体日志，只有实际停止并完成清理才计数。

### 影响范围

ProcessTool、app stop_for_project、runtime_service、run_stop/reset 的 reaper，以及 team 的既有 scoped child 清理。守卫内部不调用 stop、不等待 exit；所有异步等待不持 registry/baseline 锁。

### 验证

真实注册进程和 final_guard_hook 屏障证明旧合法文件回滚。完成后重复 stop/reaper/child wait/retry 的合法文件保持；失败记录排障并发重试、之后再合法写也保持。定向/负对照及最终包检查的实际结果见 B4-verification.json。

## crates/kanzei-tools/src/background/registration.rs

### 职责

实际 child 登记、输出 reader、退出完成与持久条目自动删除；只读写必要切片。

### 判断

P0

### 确切问题

reader timeout 只 abort 不 join，尚有 reader 持句柄时可宣布退出完成；persistent 退出自动删除也未以最后 guard/恢复成功为条件。前者是完成边界，后者是失败保留根因的表现，均不额外计数。

### 修改

abort 后实际 await reader；exit/guard Pending 在 registry 可见前建立；原 keep127 历史回收仅允许 exit 已终结与 guard 成功/Recovered 的记录，保留未完成/失败基线。exit 先记录停止，再等待 guard；成功清理收据后才移除磁盘项，错误保原内存基线及条目。callback 保实际退出事实及错误输出。

### 影响范围

普通/persistent 注册的实际 reader 与 exit worker；原日志路径、限额、通知语义不扩。

### 验证

真实 Windows File 禁止共享删除，在 reader Drop held 时 remove_file 返回 OS32；finish_reader 未提前完成，release/join 后删除成功。registered persistent 恢复失败保留，排障后 retry 清理成功。

## crates/kanzei-tools/src/background/persistent.rs

### 职责

持久后台条目的发现、接管、kill、自动删除；只读写必要生命周期切片。

### 判断

P1

### 确切问题

adopt watcher/kill/discover 会在真实恢复失败时删除 disk 或 memory 基线，失去重试条件；旧 kill bool 对失败不能给 Result consumer 具体原因。同 P1 恢复失败错误成功根因，不按多个表现重复累计。

### 修改

adopt exit Pending 在发布前建立，watcher 实际停止后等待 guard；失败保内存与磁盘，成功收据才自动移除。kill_registered_result 消费同 stop_owned；旧 bool 包装记录错误。同步 mark_registry_failed 只检查既有完成槽，Pending 不阻塞、失败可 fresh 修复，成功后 prune；无内存 ghost 保原语义。

### 影响范围

ProcessTool discover/adopt/kill 与 persistent 自动 writer。registry 路径、JSON 格式、atomic 写原语保持。

### 验证

实际 quarantine 路径阻碍覆盖 registered/adopted × stop/kill 四 fixture：失败保记录，discover 不暗删，排障 retry 实际恢复并 prune；原正常 ghost/control 通过。具体结果见 metadata。真实注册记录也经同生产 prune helper 证明失败时保留、恢复后仍按原规则可回收。
