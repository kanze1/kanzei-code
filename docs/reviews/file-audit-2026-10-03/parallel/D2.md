# D2：活跃 child 的跨进程恢复与接管

P1根因一条：进程内TEAMS未覆盖同一持久child的跨进程生命周期，导致误恢复、并发resume、等待误判及清理身份遗漏。旧默认双profile/native实证与当前真实正负回归分开保留；不把各表现重复累计。基线/C4依赖、caller全集见D2-map.md，逐项结果/hash见D2-verification.json。

## crates/kanzei-tools/src/team/mod.rs

### 职责

team 注册、恢复、准入、worker/transcript/清理和显式handoff。B2既有全文，重开必要切片。

### 判断

P1

### 确切问题

真实旧native中B查询将A running写interrupted、B resume发出第二正确路由请求，A首socket仍held。旧local wait和仅childID的身份另会错误拒绝合法远端等待/双parent同call_id，属于同链caller遗漏。

### 修改

复用C4Guard并按DB+(owner,id)稳定claim；busy查询只读、mutating admission明确Err，wait沿原等待；取得owner后重读状态。worker/晚callback/非persistent真实joined+restore/终态handoff保持owner，异常RAII、精确cleanup-failed标记，attach不pin父callbacks。

### 影响范围

原app两attach/inspection、UI task、模型host、question_reply、message、stop/close；公开签名与schema不变。

### 验证

team37pass、真实跨process/busywait/双parent模型与PID/latecallback/finishpanic/restore失败回归。相关8负例真实断言失败，最终层见verification。判断来自实际caller、durable DB行、请求payload/socket、真实Guard/PID/最后reconcile证据，没有以编译失败作负例。
