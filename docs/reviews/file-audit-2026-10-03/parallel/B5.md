### 确切问题

当前唯一生产 allocator 返回 bg<ms>-<seq>；真实 ID 结束后通过原历史回收移出 registry，ProcessTool stop 的 get(None) 分支却只接受旧 bgdigits，返回 PROCESS_STOP_BAD_ID。等价旧判定下，真实注册、自然退出、joined 和被回收的 `bg1791025490411-1` 实际返回该错误，并触发目标断言失败。合法历史句柄不能因不在 registry 就成为非法输入。一个 P1 格式/幂等合同根因；未发现其它有实际影响的问题。

### 修改

只扩私有 managed_process_id：兼容旧非空 ASCII 数字，以及当前非空 ASCII 数字-非空 ASCII 数字。BAD_ID 指引说明两种格式；多连字符、空字段、字母/符号仍拒绝。公共签名、权限/并发、进程 owner、allocator 与持久格式保持。新增真实 ID 回归，保留原旧句柄控制并验证八种非法格式的实际 stop 输出。

### 影响范围

只影响 ProcessTool stop 在记录已不存在时的幂等判断；已有记录的 project 身份检查与 B4 stop_result 完成/失败合同不变。BaseComponent 和 writing TeamTools 实际工具表均使用 ProcessTool。

### 验证

真实 BashTool echo background→ProcessTool wait 确认自然退出→stop_result 实际 join→生产 prune 判据移除自己 ID→get(None)→实际 ProcessTool stop 已通过。正例真实 ID `bg1791025456893-1` 返回 is_error=false、code=None 与合法幂等文案。旧私有判定负对照：编译成功、单测试 exit101、真实 BAD_ID 后目标断言失败；旧 ID/非法格式控制单测试仍 PASS。负例仅恢复等价旧判定，保留新夹具、test-only 桥与错误指引，不是完整旧源码。finally 两源码原字节、raw/LF SHA 和刷新后的原 mtime 精确恢复，再刷新全 Rust 后运行最终检查。process 七项 PASS；tools 799 PASS/0 FAIL/3 IGNORE；tools/core/app all-targets check、Clippy-D warnings、fmt/diff 均 0。
