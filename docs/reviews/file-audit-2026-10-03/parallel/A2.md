## 来源与依赖地图

```text
core/runner/drive：完整工具组已经提交；下一次请求前
  → ItemContext::prepare：识别真实 work claim 切换
     → 克隆 runner 原消息 source
     → archive_context_result：正文写入不可变工件，candidate 改成指针
     → RunEvent::WorkContextPrepared(source, surface, accepted)
        ├─ app/run/events：转发到 app/typed_events 的 core writer re-export
        └─ CLI/run/events：转发到同一个 core TypedSessionWriter
           → 先捕获 event sequence
           → 按 floor、typed facts、completed compaction 投影 durable current
           → current == source
           → A1 run sequence CAS / 同一 SQLite 写事务
           → 返回成功，accepted 置位，runner 才采用 candidate

mobile 独立 writer → UserMessageCommitted → durable current / 恢复 prior
```

- producer 唯一入口是 drive.rs 的 item_context.prepare；候选生成不读数据库，不引入 store/业务反向依赖。
- WorkContextPrepared 两个生产消费者分别为 app/run/events/mod.rs 与 CLI/run/events.rs；core item_context/tests.rs 有算法与实际持久化消费者。其他 RunEvent 消费者忽略此事件，不设置 accepted。
- commit_work_context_surface 的生产 caller 只有上述 app/CLI arm。app/typed_events.rs 是纯 re-export，未维护第二份 writer 或来源规则。
- 来源快照证明候选属于哪些真实消息，sequence CAS 防止 projection 读取期间的新写入。不能只在提交时读取新 sequence 来证明旧候选安全。
- 原 WorkContextReport 的序列化字段、四个 compaction 事件、数据库 schema、归档路径与业务裁剪策略不变；source 只在 Rust runtime event/API 中传递，不写新的 persistent 字段。
- 普通运行仍由已有 running/promoted input 保护归档的生命周期；本包复用 A1 run CAS，不修改手动 idle/no pending contract，也不重写普通运行预算或停止策略。
- 历史依据：R-241 typed facts 与确定性 projection；R-243 surface 事务；R-236 无损正文与失败保留历史。C2 审查明确把 work-context 候选来源窗口移交本包处理，不另造 issue 编号。

## 确切问题

**A2-01 / P1：工作条目候选隐藏后到的耐久用户事实。** ItemContext 先从 runner 本地消息克隆候选，再逐个归档；期间手机可以通过独立 writer 写入 UserMessageCommitted。旧 commit_work_context_surface 不核对 candidate 的 source，随后提交 sequence 更晚的 completed surface。projection 以该旧候选作为前缀，新手机事实在 completed surface 之前，恢复 prior 会把它隐藏。

这是 source→归档→提交之间的真实并发路径，不依赖理论碰撞或新平台。修复以 exact source 相等和 sequence-before-projection CAS 同时约束提交；不匹配只拒绝本次整理，accepted 保持 false，runner 保留原文，耐久新输入继续存在，也不污染 writer.errors 使正常运行失败。

## 验证证据

- 负例：只将 writer 提交切片恢复为 C2 基线的 unchecked 行为；为使新 caller 编译，仅保留未使用的 source 参数，不加入 source/CAS 修复。实际 ItemContext.prepare 已写真实归档、生成候选，此时独立 writer 提交 UserMessageCommitted；旧行为在 `a completed replacement must not hide the later durable mobile input` 数据断言失败（1 failed，exit 101）。不是用编译失败证明 bug。
- 恢复：在 finally 中恢复最终 writer，刷新源码 mtime，Cargo 实际重新编译。core 全包 402 passed / 0 failed；包含实际正常来源的归档→提交→恢复、手机后到的拒绝→正常 assistant/finish，以及已有运行 CAS 两连接回归。
- CLI：实际 make_event_handler 的正常匹配、手机已写导致失配两个分支都通过（1 项）。正常匹配产出 completed surface；失配保留原文和手机新事实、不置 accepted、不记 writer.errors。
- app：typed_events 相关 3 项通过；core、CLI、app 三包 all-targets check 与 Clippy `-D warnings` 通过。六个修改源码的 rustfmt 检查和 git diff 检查通过。
