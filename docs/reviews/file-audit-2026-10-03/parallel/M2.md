# M2：移动端凭据、输入提交与服务生命周期

全文范围：app/mobile.rs。core/store/inbox.rs 为已审文件的输入原子性重开切片；mobile_devices.rs 已确认正确传递存储错误，不改该文件。验证尚未完成，本文先记录已确认根因，执行结果随后补齐。

依赖链：mobile HTTP/Tauri → core mobile_devices / inbox / typed → SQLite session_events → runtime conversation cache → UI/PWA。SQLite 是凭据和会话事实真源，缓存与成功回执必须后于提交；服务槽拥有唯一 listener，stop 与请求准入共享设备锁。复用 C2 的事务内 typed invariant 与 seed 来源边界，保持 A1 的 cache → SQLite 锁序。

## crates/kanzei-app/src/mobile.rs

### 职责
解析移动端 HTTP、设备配对/撤销、消息提交、通知路由与桥接服务启停；全文审查。

### 判断
P0

### 确切问题
- P0：配对和撤销忽略 SQLite 错误，内存和回执宣称成功。失败撤销的 token 在重启后重新有效，撤销安全边界失效。
- P1：一次性配对码的读取、校验和清空分开加锁，并发请求可消费同一码多次。
- P1：消息 raw receipt、typed user fact 和缓存分开写；typed 失败仍返回 202。旧实现重放所有历史 invariant，D-417 允许跳过的旧终态脏事实会使新手机消息跳过持久化；未 seed 的旧历史也可能被手机首次 typed fact 隐藏。
- P1：启动检查与服务槽发布不在同一临界区，并发启动可留下无法 stop 的 listener；凭据库读取失败还会按空设备表启动。stop 返回时旧 listener 尚未退出，立即用同一指定端口重启还会被错误拒绝。
- P1：已经接入的连接可以在 stop 返回后完成请求体、提交消息；stop 没有与其鉴权/副作用准入形成同一边界。

### 修改
- 持有配对码/设备锁至凭据提交，成功后才发布设备和消费配对码；失败保留可重试状态。
- HTTP unpair 与桌面 revoke 共用持久删除后更新缓存的私有函数，错误如实返回。
- 使用 inbox 原子输入 API，提交后发布同一事务的 canonical cache，再发 UI 通知；失败返回 500。只验证本次 touched turn，不让无关历史终态脏事实拒绝合法输入。
- 服务槽锁覆盖检查、bind、设备装载、listener 发布；装载失败不启动。stop 在相同锁序内等待已准入请求并关闭 active；读完请求才准入，停服后完成的连接不能写入。服务拥有 listener JoinHandle，stop 释放 pair/devices 后等待监听线程退出，再允许新服务使用相同端口。

### 影响范围
- 已搜索 mobile_service_start/stop、mobile_device_revoke/list、mobile_pair_code_regenerate 全部 Tauri 注册与 UI16/PWA caller；外部命令参数和成功 JSON 保持。
- 已搜索 consume_mobile_message、remove_device 全部私有 caller；唯一生产消息入口适配 Result，不吞错误。
- 没有 schema、序列化字段、第三方依赖或凭据格式变更。POST messages 仍只提交输入，triggers_run=false，不伪造 assistant/完成 turn。
- 锁序为 service → pair → devices；普通 HTTP 为 devices → optional conversation cache → SQLite；未在全局 runtime map 锁下等数据库。

### 验证
- 已准备 8 项新增回归：凭据库故障保留配对码后重试；8 请求单码仅成功一次；撤销故障保留凭据后重试；坏 legacy 来源不发布 receipt/cache 且修复后重试；旧历史/终态脏事实/reset；stop 后延迟请求体；8 并发 start 唯一 owner 和失败后重启；stop 后立即按原端口重启。
- SQL 第二写失败的原子回滚在 inbox 存储层注入测试，不为 app 增加 rusqlite 依赖。
- 30 项 mobile、14 项 inbox 定向通过；7 个等价旧行为负例均为真实断言失败，源码逐字恢复。全工作区 2315 passed / 0 failed / 5 原有 ignored，check/Clippy/fmt、IPC 与完整 UI/浏览器回归通过。

## crates/kanzei-core/src/store/inbox.rs

### 职责
拥有 durable 输入的事务边界；本次重开手机 receipt 与可见 user fact 提交切片。

### 判断
P1

### 确切问题
- 与 mobile 消息同一根因：原 caller 用两次独立提交生成 receipt 和 user fact，第二写失败仍留下成功 receipt，没有能够保证两者一起提交的原语。

### 修改
- 新增 append_mobile_message：序列化兼容 seed 维护，再以一个 Immediate 事务写 raw receipt、checked UserMessageCommitted，并读取当前段 canonical surface；commit 后才返回。
- 复用 C2 append_session_facts_tx，只验证本次 turn 的权威状态；无 runnable inbox item，无伪造 completed turn。

### 影响范围
- 新 API 创建前搜索无重复 primitive，创建后核对唯一生产 caller 为 app consume_mobile_message。
- 复用既有消息、事件格式和投影；无 schema 或旧字段迁移。失败输入可留下已成功提交的兼容 seed 元数据，不能留下半份 receipt/user fact。

### 验证
- 回归用 SQLite trigger 拒绝第二个 user fact 写入，断言 receipt、typed fact、inbox 均未出现；撤掉故障后重试仅提交一次，返回投影与持久事实相同。
- 14 项 inbox 定向通过；第二写 SQL trigger 负例确实留下半份 receipt 而失败，修复后原子回滚；全工作区 2315 项通过。

## crates/kanzei-app/src/state.rs

### 职责
定义应用状态；本次只重开 MobileService 的监听资源拥有者切片。

### 判断
P1（与 mobile 启停共用根因，不另计）。

### 确切问题
- 服务只有 active 标志，没有等待 listener 释放端口的句柄；正常停服后的立即指定端口启动可能仍被旧 listener 拒绝。

### 修改
- MobileService 保存可选 JoinHandle；生产构造保存线程，连接测试 fixture 无 listener 时为 None。

### 影响范围
- 搜索全部 MobileService 构造，只有 mobile 的生产 start 和一处测试 fixture；AppState 只是持有服务槽，IPC/序列化未变。本切片不算 state.rs 全文审查。

### 验证
- 实际 TCP 请求后 stop 并立即按同一端口重启通过；恢复 detached listener 行为时真实 bind 失败。源码恢复后完整工作区与 Clippy 通过。
