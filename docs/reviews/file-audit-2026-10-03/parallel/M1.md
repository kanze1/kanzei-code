## crates/kanzei-app/src/mobile/sse.rs

### 职责
移动通知流、每设备游标与撤销/停服收尾；全文审查。

### 判断
P0

### 确切问题
- HTTP 入口仅确认 token 存在，SSE 却使用 query.device_id 检查撤销和推进游标。设备 B 使用自己的 token 指定仍有效的 A 后，撤销 B 不会关闭订阅，也会推进 A 的游标。撤销安全边界失效。
- 缺 device_id 时使用不存在的 paired-device，合法已认证订阅写完响应头便关闭；与上方同属设备身份来源错误。

### 修改
- SSE 接收入口从 token 解析的真实设备 ID，不再自行选 query/fallback 身份；保持显式 cursor 的补发语义。

### 影响范围
- 唯一 caller handle_mobile_connection 已搜索并适配；设备表和 SQLite schema 不变。标准 PWA 已同时发送匹配 ID/token；不匹配请求明确返回 403。

### 验证
- 新回归走真实 TCP 请求：通知 JSON/SSE 拒绝其它设备 ID；缺 query 时推进已认证设备的游标；合法 SSE 在其认证设备撤销后关闭，另一台设备不受影响。
- 读取/持久化失败分支及既有游标故障测试已检查；实际执行结果见验证 JSON。

## crates/kanzei-app/src/mobile.rs

### 职责
移动 HTTP 入口；本次仅检查 token → 设备 → notifications/SSE/unpair 身份切片。

### 判断
P0

### 确切问题
- 与 SSE 同一根因：bool 鉴权丢失已认证设备身份，后续使用独立 query/fallback 身份读写通知状态。

### 修改
- 鉴权返回已认证设备 ID；通知 query 只能确认该身份，不能指定另一个 ID；缺 query 直接使用认证 ID。
- unpair 复用同一身份解析函数，保持仅解除请求设备。

### 影响范围
- 通知 HTTP、SSE、unpair 和已有认证测试；无需修改 PWA 协议、凭据格式或 core 通知 API。

### 验证
- 所有私有鉴权 caller、唯一 SSE caller 和 PWA URLSearchParams 已核对；真实请求回归覆盖伪造 ID、默认 ID 和撤销路径。
- 其余 pairing/message/server 生命周期尚未全文审查，不标 PASS。
