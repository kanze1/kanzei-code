# B0：Harness 调度契约与托管窗口

基线 `f5a72fe0`；分支 `kanzei/audit-b0`。全文审查 4 文件，调用链适配 6 文件。运行级租约属于 core 协调器，托管窗口属于 harness，后台镜像基线属于 tools/BackgroundProcess；三者不能互相替代。

历史依据：R-171/R-173 阶段契约、R-182 任务级并行修订；D-174 后台围栏、D-258 精确吸收；D-275 接受同项目同窗口同前缀的残余边界。本轮修跨项目错归因及状态竞争，不改变 D-275 的已定范围。

## crates/kanzei-harness/src/managed_fence.rs

### 职责
全文；持有专用工具合法窗口，向后台守卫暴露项目范围与调用身份。

### 判断
P1

### 确切问题
- 活跃窗口只有工具名/相对前缀，进程内 A 项目的合法工具会给 B 项目的后台改动提供错误豁免；关闭观察者还会将 B 的改动吸收进基线，使其永久失去越界依据。
- 同名窗口缺少调用身份，观察者按工具名栈配对，与异步调用的真实关闭顺序不一致。

### 修改
- `tool_scope`、`ToolWindow::open` 和 `write_in_progress` 显式携带托管主根；增加进程内 window id；observer 收到同一窗口身份。
- 使用 base `canonical_or_simplified` 和已有 harness `dir_key` 处理路径身份；不新增独立归一实现。
- 按 window id 回收，取消仍走 RAII。

### 影响范围
- core 并行/串行工具执行、tools 后台守卫、记忆整理和定时任务写回。内部 public API 调整，所有仓库 caller 已适配；无持久化格式变化。

### 验证
- 新增项目隔离、同名乱序回收、目录别名回归；原有白名单、前缀和取消测试保留。后台真实观察者/恢复路径的回归见下方切片记录。

## crates/kanzei-tools/src/background/lifecycle.rs

### 职责
切片；托管窗口打开/关闭观察、基线提交与 `reconcile` 检测/恢复。其余生命周期函数未全文审查。

### 判断
P1

### 确切问题
- observer 遍历全项目并按 tool 栈配对，消费了上面不完整的窗口身份。
- 并发关窗各自 clone 旧 baseline 后整份替换，不相交的合法更新可丢失；下一次守卫会将丢失的一侧判为越界并回滚。
- 守卫 clone 旧 baseline 后，合法窗口可以关闭提交新 baseline；守卫随后读到新文件且窗口已经消失，便回滚刚完成的合法写入。

### 修改
- 只处理窗口所属项目；打开镜像以 `(process.id, window.id)` 配对，关闭清理已结束进程遗留镜像。
- 同一 baseline mutex 覆盖关闭镜像/吸收，以及守卫同步读取/判定/恢复；新窗口先在同一锁下拍打开镜像再执行工具。
- 进程终止 await 在锁外。删除可分离 clone/set 的生产更新入口。

### 影响范围
- BackgroundProcess 运行时镜像、守卫回滚和合法工具写入；状态格式不变。跨项目错误豁免与 managed_fence 为同一个根因，统计一次。

### 验证
- 两项目回归覆盖窗口打开期间及关闭后，两条路径均保留合法项目 A、隔离/恢复项目 B。
- 乱序关闭回归检查首个已完成窗口立即归入正确基线。
- barrier 同步两条不同前缀关闭路径，检查两侧更新均保留；channel 使守卫暂停、合法窗口提交后再继续，检查无误报/误回滚。
- 锁序：Opened baseline→snapshots；Closed 先释放 snapshots 再取 baseline；guard baseline→active/原子文件恢复。active 不持锁回调，baseline 内无异步等待。当前生产 caller 在 Opened/Closed 外未持文档/记忆树 FileLock；锁均在工具 body 内同步释放。core 工具工件配额锁在 scope 完成后获取，schedule 定义锁在写回完成后获取。
