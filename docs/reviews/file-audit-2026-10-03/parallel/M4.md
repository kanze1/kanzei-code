## crates/kanzei-app/ui/09-sessions.js

### 职责
显示项目/会话/排队输入，并将切换、建线、关闭和权限恢复操作路由到真实项目及会话。

### 判断
P1

### 确切问题
- M4-01：A 的权限恢复等待期间切到 B，恢复结果进入 B 的权限队列。
- M4-02：迟到的 A 输入列表覆盖 B，或同会话旧列表覆盖新列表；旧行的撤销按钮使用新的全局项目/进程。
- M4-03：建线在 facts/confirm 之后才捕获项目，在 B 建 A 的任务。
- M4-04：facts 查询时尚未认领创建操作，连续点击可重复准入。
- M4-05：旧隔离查询、旧 Git facts/修复动作沿用到新项目；旧告警按钮可 detach B。
- M4-06：关闭 A 的确认前 active 快照在请求完成后清除后来选中的 B；失败又可把已终结状态恢复为 running。
- M4-07：项目选择入口绕过已有导航代次，旧 projects_select 响应覆盖更新导航。
- P2 M4-08：权限恢复第一次失败后同步标记未清除，正常轮询不再重试。
- P2 M4-09：撤销回执为 false（输入已被后端消费）时不刷新列表，行一直停留且按钮被禁用。

### 修改
- 请求前捕获项目/进程/session；权限按原 session 分区恢复，失败允许下一次轮询重试。
- 输入和隔离投影使用私有请求代次；切根/切线立即使旧投影失效，旧行操作不再路由到新身份。
- 建线在第一个 await 前认领项目和 in-flight；所有退出统一释放，确认/事实读取/创建后重新核对身份。
- 关闭完成时重新检查活动线，只恢复自己仍处于 stopping 的乐观状态。
- switchProject 委托已有 openProjectSpace 导航事务，保留 boolean 返回和同项目刷新合同。
- false 撤销回执也重取真实列表，finally 恢复按钮。

### 影响范围
- 直接 caller：07-events、08-compose-runtime、12-docs-pages/session-tree/session-menus、20-lines、21-palette、29-general-chat；身份与 IPC 参数保持原形状。
- 只改变前端错误归属和失败恢复；SQLite、process ID、session ID、路径身份及事件格式不变。
- 原权限队列和 pane/stream owner 继续由 07-events、01-core 持有，不新增重复状态注册表。

### 验证
- 真实 09/12 ES 模块的 22 项定向回归全部通过；精确 aff48f96 两模块源码对照 15 项真实断言失败、7 项正常路径通过，无跳过或编译错误。
- 验证迟到响应、同会话逆序、旧按钮、确认中切项目、重复建线、关闭终态、失败释放和正常同项目刷新。
- A4 状态回归 15/15、A3 权限身份回归 12/12；IPC 184/201 命令、36/36 事件一致；i18n、两个修改 UI 文件 ESLint、三个 JS 语法与 diff 检查通过。
- 完整 UI 回归：90 模块、4006 次模拟 invoke、10 主视图、0 运行时错误；脚本关联的真实浏览器问答、工作台、交付、子任务、文件、QA、深浅主题回归均通过，进程退出 0。
