## crates/kanzei-core/src/runner/drive/history.rs

### 职责

向同步消费者提交 assistant/tool 结果，维护运行消息和本轮提交记录。

### 判断

P1

### 确切问题

- typed 拒绝 assistant+ToolCalled 或 ToolResult 时，void 回调仍 push 消息并 Proceed；数据库与运行 prior 分叉。

### 修改

- 事件携带共享 receipt，回调返回后检查；拒绝返回 Err，不 publish messages。round 仅收集未拒绝的消息，已有输入 receipt 行为不变。
- commit_step_messages 返回 Result；停止占位的结果提交失败同样传播错误。

### 影响范围

- 直接 caller：drive 的步骤提交/finalize、serial_tools 两个提前收尾出口。
- 运行 messages/round_messages；无持久字段或 schema 变化。私有 Result 合同已完整适配。

### 验证

- 完整 caller 核对及新增拒绝消息不进入 runtime/round 的回归通过（core 408/408）。既有停止占位成功语义测试也通过。

## crates/kanzei-core/src/runner/drive.rs

### 职责

驱动 provider、子代理和工具执行，持有运行历史、步骤结果和 round receipt。

### 判断

P1

### 确切问题

- assistant 事务被拒后仍运行/派发子代理、执行工具；结果事务被拒后仍可发下一请求。
- 包装回调在实际 durable sink 前记录 round，将拒绝消息误计为已提交记录。

### 修改

- step commit/finalize 的 Err 直接返回 runner；拒绝前不进入子代理/工具执行，结果拒绝后不请求下一 provider。
- round 在同步 sink 返回后才依据共享 receipt 记录。run_once、run_once_with_parts 与 on_event 签名保持原状。

### 影响范围

- 直接 caller：app run execution/fixup、CLI run、scheduler prompt、subagent/memory/stateless reader。
- runner 返回真实 Err；没有伪装 halted_by_user，也没有新增恢复排他框架。

### 验证

- 真 SQLite + 真 TypedSessionWriter + 本地 HTTP/SSE + CountingTool 四条实链全部通过：实际 prepare 关闭活跃 turn → Err/0 effect/1 request/DB=0/0；SQL trigger 拒结果 → Err/1 effect/1 request/DB=1/0；正常 durable → 1 effect/2 requests/DB=1/1；stateless → 同样正常效果，round 与 messages 相等。
- 负对照清理 fixture 在断言之前，保留实际 durable call/result 和请求/执行计数，避免仅凭红灯宣称 bug。
