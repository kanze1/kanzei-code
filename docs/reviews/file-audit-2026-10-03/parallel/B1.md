# B1 应用异步回复、日志订阅与子任务回调

基线 `fbb85333`，分支 `kanzei/audit-b1`，工作树 `C:/Users/kanzei/.codex/worktrees/audit-b0/kanzei code`。全文审查 4 个 app 文件；tools/team 和 tools/background/monitor 仅检查本报告列出的准入、停止、订阅切片。只本地提交，不发布。

依赖链：harness/pending_question 单记录文件锁与 AsyncMailbox → app/SessionRuntime 代数、lifecycle 和 SessionStore 准入 → durable reply → AgentTeam 的 worker 准入与日志订阅。单记录状态由磁盘记录拥有；主 actor 退役由 SessionRuntime 拥有；child active/cancellation 由 AgentTeam 拥有。没有新持久化格式或第三方依赖。

历史依据：D-342 协作式停止、R-173/D-173 输入生命周期、R-253 运行域拆分，以及本目录 B0/M0 和依赖地图。旧回复不是新的“明确续做”授权。

锁序：主回复准备为 app.lifecycle → callback_options/async_mailbox，释放后才 publish；handler 准入再次持 app.lifecycle，随后释放并调度。child 回调为 team.lifecycle → question 文件读取/TeamStore/active，事件和主 mailbox 可继续进入 app.lifecycle；app 不持 lifecycle 调 team。stop_all 的 active 快照及逐项停止同持 team.lifecycle，stop_locked 避免重入。关闭 mailbox 不等待正在运行的 handler。所有 stop_all caller（commands/run、processes/lifecycle、core/runner/drive）均未持 app.lifecycle 调用。

## crates/kanzei-app/src/durable_questions.rs

### 职责
保存后台问题、持久化回复并恢复尚未投递的 outbox；全文审查。

### 判断
P1

### 确切问题
- answer_ask、softwire answer、recover_outbox 持有 answered 快照时 stop 可把实际记录取消；deliver 仍信任旧快照，创建新邮箱并唤醒已停主 actor。
- child reply 在读取未停止状态后走有 await 的 UI message 入口，最终被当作 from=main 的明确续做。
- 上游旧 ask handler 的 save/asks.insert 与 stop 的 cancel_owner/retire 未共用原代数门槛；save 等文件锁时 stop 可以先漏枚举，之后旧问题才写入。该根因需要 events/stop/state 共享契约收口，已交主代理，不在 persist 中猜测 running/halt 状态。

### 修改
- 在 actor lifecycle 下重新读取原问题状态、校验归属并绑定同代邮箱；取消记录在创建邮箱之前拒绝。释放 lifecycle 后发布，避免 handler 重入。
- 回复使用磁盘真源；已 delivered 的重试只返回既有 receipt。恢复 callback options 也在同一 lifecycle 内完成。
- child reply 传原代数、原邮箱和固定 callback ID，交给专用回调入口。

### 影响范围
- commands/run answer_ask、softwire、启动 outbox；mobile 前台 oneshot 路径不变。
- 固定 callback ID/回复幂等、取消语义和已交付 receipt 保持；无持久化兼容性变更。

### 验证
- answered 快照 → cancel_owner → retire → prepare：拒绝且邮箱 factory 没有运行。
- prepare → stop → publish：保留的邮箱已关闭，不新建邮箱。
- 当前合法回复与 delivered retry 均通过。
