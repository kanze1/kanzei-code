## crates/kanzei-app/src/settings.rs

### 职责
全局设置保存与项目权限规则查询/删除，负责命令边界及配置编辑合同。

### 判断
P1（另含一项 P2 查询失败语义）

### 确切问题
- D1-C1 同根因：普通读改写绕过配置锁，bootstrap 检查后覆盖并发创建，删除写入不与追加串行。
- D1-C4 同根因：旧 index 可指向替代规则，合法撤销误删另一条授权。
- 合法内联表能加载而无法保存；相同实体的两种 TOML 表示合同不一致。
- provider 删除后的模型校验仍认可旧 provider，保存出运行时无法解析的配置。
- P2：规则读取/解析失败被伪装成空列表，用户看不见真实失败及重试入口。

### 修改
- 保存、bootstrap 和删除统一 lower 文档事务，锁覆盖当前快照、校验与原子提交。删除重复裸读写 helper。
- bootstrap 在锁内确认缺失，只创建注释模板；已有空文件、已有内容与读取错误不会被覆盖。
- 删除要求完整 expectedRule，事务内核对实际 index 和 Allow 三字段；不重新定位、扩大授权或吞冲突。
- 使用既有 TableLike 编辑普通/内联表，保持原键和值的装饰；内联 providers 的新增子项也保持内联表示。
- 校验实际将提交的配置，失败不写；三个模型角色只引用提交后仍可解析的 provider。
- 仅文件缺失返回空规则，其他错误带配置路径返回。

### 影响范围
- settings_save/open；UI16 设置、权限列表；UI07 撤销；项目模型补丁共用编辑原语。
- expectedRule 是唯一需同包更新的 IPC 参数，两个生产 UI caller 与测试 caller 已全部适配。
- 原 TOML schema、项目/全局分工与 provider 权威清单语义不变。

### 验证
- 24项 settings 测试通过。真实上层 writer 等待已持有的同路径事务，并保留后提交数据。
- 三种规则表示下，重复旧 index 删除和错误 effect 都拒绝且原文不变；缺失/损坏/IO错误可区分。
- 内联各节保留业务字段；删除 provider 的三个角色均拒绝、零提交，换成保留 provider 成功。
- 对应旧行为负例均编译成功后断言失败；现有注释/未知字段、默认值、非法原文与 provider 合同回归保留。

## crates/kanzei-app/src/model_config.rs

### 职责
解析模型生效来源，按键编辑项目模型覆盖并提供查询/保存/打开命令。

### 判断
P1

### 确切问题
- D1-C1 同根因：最后复读与写入之间仍可覆盖并发权限提交；四次重试不形成互斥。
- 共用编辑原语拒绝合法内联 models 表，查询成功后合法 save/unset 失败。

### 修改
- 补丁在同一个 lower 配置事务内读取和应用；删除两读/重试及生产中的测试 hook。
- 共用 TableLike 支持内联表示；只修改原五个模型键，未管理的 scout/provider/权限保持。

### 影响范围
- UI08-models、UI08-project-models 四个 native 命令及 settings 项目覆盖显示。
- save/get/open 的载荷和返回形状不变，未引入 persistence 或 provider 专属模型。

### 验证
- 14项 model_config 测试通过，含真实另一线程模型保存等待权限事务，双方状态均保留。
- 内联 save/unset、删空继承、非法键/冲突/模型/provider 拒绝及实际两层 load 回归通过。
- 旧未加锁与拒绝内联逻辑分别触发真实失败。
