## crates/kanzei-core/src/store/typed.rs

### 职责

定义版本化会话事实、状态机和 typed writer，提交、播种及恢复 SQLite 事实。

### 判断

P1

### 确切问题

- terminal 预检在写事务外：B 未提交 terminal 时 A 读到旧状态，A 等 B 提交后仍追加事实；caller 局部 invariant 同样可能漏掉别的 writer 已提交的 draft/call 状态。CLI 与桌面共用 session/DB，CLI 不参与桌面仲裁，路径可达。
- recovery 在事务外读 open draft/决定恢复计划：另一 writer 在其等写锁期间提交同一 message 后，旧计划仍提交 interrupt/terminal，事件重放不再合法。
- seed 在事务外读 source/floor：并发 CLI --new 提交 reset 后，旧 source 被播种进新段，恢复旧 prior。
- seed 幂等只比较 source_sequence：fork inline seed 的外源序号与目标会话新快照序号相同，会错误拒绝播种目标快照。这与投影截点同属 seed 来源边界问题。

### 修改

- checked append 先获得既有 Immediate 事务，在其快照中查 terminal、重建涉及 turn 的 DB 状态、验证整批并追加；只合并涉及 turn，保留 caller 其它 turn/顺序。commit 成功后才采用新 invariant。
- 提取 pub(super) append_session_facts_tx 复用同连接事务，要求传入提交成功后才采用的局部副本；恢复不再嵌套事务。
- recovery 的读、决定、写和提交共用 Immediate，保留历史 post-terminal 容忍、确定性顺序及不重执行工具的行为。
- seed 的 source/floor/幂等检查和追加共用 Immediate，duplicate 同时匹配 source_event_id/sequence；继续按 D-375 存引用。

### 影响范围

- 直接 caller：TypedSessionWriter；app mobile/general_chat/fork；CLI run、app run assembly；core rewind/prepare/recovery。完整清单见地图。
- SQLite session_events 与 caller invariant；公开签名、schema、持久格式、路径及终态词表不变。新 helper 仅 store 内可用，可供 M2 输入事务复用。
- work-context surface 方法保持原状，来源合同由 A2 接续；没有将数据库守卫当作上层执行 ack。

### 验证

- typed 34/34、core 全包 401/401、0 失败、0 忽略；core all-targets check、Clippy -D warnings、三修改文件 rustfmt 和 diff 检查通过。
- 三个 busy_handler/channel 回归在实际 writer 等锁处设屏障：terminal 提交、assistant finalize、reset；无 sleep。旧生产实现对应回归确实失败。
- stale caller 回归证明重复 commit 被拒绝且 caller 不前移、其它 turn 保留；第二条 SQL 写入失败证明整批和 caller 状态回滚；扩展旧脏 turn fixture 证明新 user fact 仍可写入。
- fork 低序号碰撞用真实 store/prepare 回归；旧 duplicate 谓词只有 1 条 seed，修复版为 2 条且投影采用新目标快照。

## crates/kanzei-core/src/store/typed/projection.rs

### 职责

纯重放 surface、transcript、中断诊断及 shadow 比较，不拥有持久状态。

### 判断

P1

### 确切问题

- 中断草稿只增加 transcript；后续新 turn 的连续两个工具结果共用 surface 下标写入两向量，第二结果进入 transcript 的 assistant 消息。真实 writer/recovery 可生成此合法链。
- 旧 conversation.updated@1、独立手机 user fact@2、prepare 发布 seed@3：投影从 seed 发布位置之后开始，永久隐藏 fact@2。简单改为 source_sequence 又会用 fork 的外源序号截掉目标会话事实，必须核对来源身份。

### 修改

- 私有 result_group 分别保存 surface/transcript 下标，两向量独立追加同组结果。
- 采用最新 seed 的消息基线，继续重放本会话真实 source_sequence 之后的事实；只有 source_event_id 与 events owner 生成的本会话 canonical ID 完全一致才使用该截点。
- fork/general 外源 cutoff 为 0，保留目标会话在 seed 前后的输入。seed_source_sequence 的信息字段保持原值；seed 事实本身仍不追加消息。

### 影响范围

- 直接 caller：app conversation/shadow、CLI prior/finalize、workspace 候选、core rewind、writer shadow，以及 A2/M2 来源核对。
- 错误 transcript 与被隐藏的合法输入得到恢复；同源快照仍覆盖其 source 前的事实，避免重复。公开 API、序列化字段和 compaction surface 合同不变。

### 验证

- 实际 TypedSessionWriter 生成中断旧 turn → 新 turn 两 call/两 result/terminal；完整 invariant 重放合法，两个结果只进入正确工具消息，assistant 和中断草稿不受污染。旧实现明确把第二 result 放进 assistant。
- raw legacy → 独立 phone typed fact → 真实 prepare 回归：旧投影只保留 legacy，修复后 surface/transcript 同时保留 legacy+phone；第二次 prepare 幂等。
- 新 legacy source fixture 证明 source 前已覆盖的输入不重复、source 后输入保留；fork source@1000 fixture 证明目标会话 seed 前后输入均保留。
- 最终 typed/core/check/Clippy/fmt/diff 均通过；负例后逐字恢复三份源码，记录 hash 并刷新 mtime，最后重新编译测试。

## 依赖影响

- 无公开签名、schema、事实格式、文件布局或第三方依赖变化。
- 内部 projection 复用 events::session_event_id；同连接事务复用 typed helper。caller invariant 必须在 commit 成功后采用。

## 剩余风险

- A2：work-context 候选来自 runner 局部 messages，手机另线程提交新 fact 后 unchecked surface 可隐藏它；需 producer/event/两入口提供真实 source 和版本 CAS。本包未改该方法。
- M2：旧 mobile consumer 在历史脏条或 typed 写入失败时仍 202，先 emit/更新缓存；raw mobile.message 无恢复消费方，重启可能丢失接受过的输入。root 正收口原子 raw+typed 提交，本包不改 mobile/inbox。
- 后续执行/恢复包：typed 拒绝 tool-called 批次只记录 errors，void sink 无 ack；runner 仍 Proceed 执行工具。CLI 并发 recovery 可闭合桌面活跃 turn，使此路径可达。精确 caller 和无外部副作用的 CountingTool fixture 方案已交 root；本包 DB 拒绝脏事实不等于执行层已闭环。
- 只验证本包/core，尚未在合并结果上执行全工作区、Linux 或真实 UI；由 root 做统一 caller 验证。未检查真实用户数据库。
