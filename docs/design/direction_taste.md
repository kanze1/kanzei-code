## 背景与问题

仓库 3 天龄、521 commits,体检总体结论:底层质量(分层/权限引擎/LLM 协议层/docstore/记忆系统)远超同龄项目,事后免疫机制(验收核查、失败→硬化回路)一流;但三个系统性弱点成立——①可靠性缺口正好压在日用路径上(R-086 后台事件丢弃、i18n 篡改输出显示、限流/凭证过期整轮报废);②调度机制空转(priority 不参与取活、架构级条目被合法绕行、WIP 上限只在提示词),自举选题系统性偏向过程建设而非用户痛点;③事前防线欠账(E3 靠仿真、E4 为零、docstore 裸写无锁)。

评审共识中最尖锐的一条:**约两万行在以更低可靠性重造 Claude Code 已解决的问题**(context overflow 六次逃逸、限流无策略、凭证无续期、thinking 回放缺失——每一项都是 CC 已打磨多年的地方)。用户认可此判断,并当日定调两条,即本文档的两个基线。

## 目标与非目标

- 目标:给后续所有取活、设计、验收提供方向判据("taste"),让"好用压倒一切"在机制上可执行,而不只是目标宣言。
- 非目标:本文档不是实施计划(执行序见 §5,具体拆条归 tracker);不推翻既有品味决策(A-001~A-005 继续有效)。

## 讨论摘要

用户提问:"我们应该更直接复用 Claude 的设计,但是压缩和选择性丢弃,我们要先复刻,才能提改进、优雅和设计?"评审意见(已被采纳)是同意,理由三条:

1. **CC 的设计承载了海量真实失效模式的迭代**。kanzei 正在逐条重新踩这些坑(context overflow 六连逃逸、限流整轮失败、凭证过期即死),每颗都是 CC 早已解决的;从第一性原理重造等于把对方的缺陷史再走一遍。
2. **复刻提供一个便宜的 oracle**。行为与 CC 基线不一致 = 要么是记录在案的刻意改进,要么就是缺陷——验收从"agent 自由发挥"变成可判定的对照。这正好治本项目已被证实的最大弱点(08-07 核查出 55% 完成水分):有了基线,打假不再依赖人工逐条抠。
3. **Chesterton 栅栏**。只有理解到能复刻的程度,才有资格判断哪根栅栏该拆。"先复刻,后改进"是获得改进资格的最短路径,不是保守主义。

附带两条限定:复刻的对象是**行为契约与设计决策**,不是代码与像素(CC 闭源,基线取自官方文档+真实使用观察;opencode 开源,作实现参照——本项目本就源于 opencode 重写);复刻区必须选对——护城河区(见 §4)不复刻,那是 kanzei 领先的地方。

## 最终方案

### 定调一:复刻优先(可替代区)

**原则:凡 Claude Code 已解决的问题,先复刻其行为契约,压缩与选择性丢弃后落地;复刻达标后才谈改进与优雅。**

- **压缩判据**(丢弃过滤器,不满足即丢):单人自用 / 桌面+CLI / 中文优先 / 服务自举场景。企业协作、多用户治理、marketplace 类能力一律不做。
- **执行规则(可检查)**:凡触及 CC 已有能力的需求或设计文档,必须先写「CC 基线行为」一节;偏离基线必须给出一行理由;无理由的行为偏差按缺陷处理。
- **节奏**:不另起"复刻工程"大跃进,把复刻作为既有条目的验收口径(例:修限流 = 复刻 CC 的限流等待续跑行为),避免制造一批平行需求。

**复刻清单 v0**(随 CC 演进复核):

| 能力 | CC 基线行为 | kanzei 现状 | 复刻优先级 |
|---|---|---|---|
| 上下文压缩 | 结构化摘要保留关键上下文,自动阈值+手动触发,不无声丢轨迹 | bytes/4 估算(仅桌面)+紧急 8000 字符截断,被裁剪段无声消失 | **高** |

### 定调二:i18n 保留,换架构

用户明确:**英文一定要**。判死刑的是机制不是目标——现行"中文源 + 800 词条词典 + MutationObserver 事后重写全文档文本节点"已产出 8 条缺陷家族(D-092/D-108/D-129/D-135/D-136/D-142/D-157/D-160)、正在篡改模型输出的显示(CJK 词界缺口)、并造成 O(n²) 渲染税。新架构四条铁律:

1. **chrome/content 分离**:UI 骨架文案(按钮/标签/提示)可翻;对话内容(模型输出、用户输入、文件内容、追踪条目正文)**永不触碰**——展示层不得修改数据,无例外。
2. **翻译发生在渲染点**:静态 DOM 用 `data-i18n` key 一次性应用;JS 动态字符串一律经 `t(key, params)` 产出;禁止任何事后全文档扫描改写。MutationObserver 整个退役。
3. **模型输出语言是 prompt 问题**:想要英文回复,走 profile/system prompt 设置,绝不做显示层转换。
4. **漏译可机械检出**:现有词典资产迁移为 key 表;漏译回落中文原文,冒烟脚本加 key 覆盖率断言——替代现状的"漏一条只能肉眼发现"。

迁移两步:**立即止血**——消息容器子树整体豁免词典替换(一行过滤条件,先终结现行数据篡改);**渐进 key 化**——按 A-003 粒度规则一轮吃一个界面域,直至词典机制退役。
