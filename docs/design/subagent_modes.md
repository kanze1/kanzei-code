# 子代理协作三档

2026-10-04，R-384。每个对话独立保存协作倾向，默认按需。协作档位与结伴／自主执行、模型推理强度相互独立。

| 档位 | 模型倾向 | 默认运行并发 |
| --- | --- | --- |
| 关闭（Off） | 主代理自己完成工作，不提供 task 派发入口 | 0 |
| 按需（Auto） | 有明确收益时委派，简单任务可自行完成 | 2 |
| 积极协作（Ultra） | 主动寻找独立任务并行，仍自行决定是否委派、人数和依赖 | 8 |

设置页提供按需并发、积极协作并发、所有对话并发上限。最后一项默认 16，是当前进程中所有桌面团队共用的额度。额度表示上限，不是要求开满的人数。任务超出运行额度时排队；等待依赖不占运行额度，等待用户回答时释放额度，继续运行前重新取得。调低额度不终止已有任务。会话修改在下一轮读取，面板操作时也同步当前档位；已启动的任务继续运行，关闭档仍可查看、停止和收取已有任务。显式重新启动已结束任务需要先启用协作。

`limits.max_tasks_per_turn` 保留，表示单次模型响应中 task 调用的数量上限，默认 16；它不代表同时运行数。无桌面团队的 CLI 只读派发也按协作额度分批运行。额度适用于当前应用进程，独立启动的另一个应用或 CLI 不共享全局额度。

模型决定任务分解、任务依赖、是否复核和什么时候整合。可用 `task` 的 spawn、message/resume、restart、wait/collect、diff/adopt 组织工作，没有固定勘察→实现→复核顺序，也不自动插入周期核查。fresh 为默认上下文，必要时才 fork；续做沿用身份和历史，重启保留旧记录并创建新身份。子代理不能继续派发子代理。

explore/plan 和自定义角色只读；开发档提供 general/implement/verify 写角色，每个写任务使用独立 Git 工作树。依赖任务在自己的候选工作树中加载依赖产出，验证读取真实候选文件，不只读报告。主代理检查差异后 adopt，最终提交和发布仍由主代理负责。讨论与研究档仅暴露只读角色；独立工作树不会改变角色的写权限。

运行时保留取消、跨进程身份锁、持久历史和按代码树仲裁的写租约。固定角色表、阶段状态机、屏障参数、复核修正调用及旧隐藏开关已删除。角色步数、输出上限和单任务超时继续由既有配置控制。

持久库升级到 v26。迁移前自动保存旧版数据库副本；旧 `subagents_enabled=0` 迁为 off，其他旧记录迁为 auto，旧高级勘察复核标记不恢复固定工作流。`phase_pipeline` 和 `subagents_enabled` 两列在迁移事务中物理删除，策略只保存 `subagent_mode`。旧 `models.scout`、`barrier_timeout_secs`、`cadence.verify_every_n` 不再参与运行，设置保存时移除。

回退需退出新版本并恢复升级前的数据库副本，再使用旧版；旧二进制不能打开 v26 数据库。恢复旧副本也会回退升级后的会话变化，保留当前数据库备份以便再次升级。
