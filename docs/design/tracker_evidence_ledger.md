# Tracker 状态可信化:改动面账本与两轴状态

- 身份: live_design
- 状态: 设计基线(2026-09-02 用户就三个方向定调后冻结 §3;§4 为实施拆解)
- 上游文档: [work_unit_foundation.md](work_unit_foundation.md)、[ci_release_evidence_chain.md](ci_release_evidence_chain.md)、[weakness_register_20260820.md](weakness_register_20260820.md)
- 关联决策: A-012(SQLite 存运行事实/Markdown 治理真源)、A-013(容忍 self-report)、A-002(可用即关闭)
- 一句话: tracker 里缺「条目 ↔ 改动 ↔ 证据」这个第一类对象,所以状态只能靠声明、门禁只能拿全局代理量去猜。

## 1. 根因

**tracker 里不存在「这条条目 ↔ 哪坨改动 ↔ 哪条证据」这个第一类对象。** 一切摊成条目上的
自由文本字段,于是状态只能靠声明,门禁只能拿**全局代理量**去猜条目与改动的关系——既必然
误伤,又必然可绕,字段也必然只增不减。

三处门禁,同一个病:

| 门禁 | 它实际看的东西 | 与被判条目的关系 |
| --- | --- | --- |
| `close_verify_trigger` | `git diff --numstat HEAD^ HEAD` | **零**。代码注释自陈「这条判据看的是仓库最近一次提交,不是被关闭的那个条目」 |
| reconcile `target_fingerprint` | `declared_commit..HEAD` 之间**全部**源码文件 | **零**。R-249 的目标指纹 292 个文件、14892 字符,没有一个是 R-249 改的 |
| `implemented-uncommitted` | 全工作树指纹 | **零**。分支条件里根本没有 entry |

而唯一被当作「实现凭证」的 `observed_head`,按代码自陈是「由『进展』落笔时写入的机械指纹」
——它记的是**写笔记那一刻的 HEAD**,不是实现提交。所以现行判据的真实语义是
**「凡写过一次进展的条目 = 已实现」**。

两个副作用值得单独点名:

- **自反馈闭环**:`close_verify_trigger` 近 80 次提交里触发 43 次,其中 6 次的触发文件是
  tracker 自己的归档 md——**上一批 close 写出的账本增量,把下一次 close 顶过行数阈值**。
- **门禁教人绕**:`test_record/coverage.rs` 里记着 D-371 的教训——给「前端冒烟」标题加覆盖
  门禁后,模型把标题改成「定向测试」绕开,「门禁反过来教会了谎报跑过什么」。
  **推论:门禁不得落在模型自填的字符串上。**

## 2. 已定(2026-09-02 用户逐条定调)

1. **交付态由引擎在提交通道自动记账本产出**,模型无从插手。代价接受:所有提交须走 kz 的
   提交通道;主树手工 commit 的部分缺账,落进遗留模式(只提示不拦)。
2. **取活裁决对「看起来做完了但没关」的条目只提示、只降序,永不封禁**。队列必须永远有出路。
3. **`不变式` 字段的执行器与两道恒真门禁删除**,承认采纳失败。

## 3. 设计

### 3.1 改动面账本(地基)

在 `.kanzei/artifacts/work-log.jsonl`(已是引擎写、append-only、带 `run_id` 的事实流)
新增 `deliver` 事件:

```json
{"event":"deliver","id":"R-349","commit":"b0827f39","paths":["..."],"test_record_ids":["T-..."],"at_ms":0,"source":"engine"}
```

写入点是 `git finalize` / commit 通道——**那一刻引擎同时知道三件事**:谁在 WIP(work-log 的
claim)、暂存了哪些文件(`git/plan.rs` 已算出 safe stage set)、提交出来的 sha。
该处今天已经在机器写 passed 测试记录,只差顺手记一行归属。

它天然不可伪造**不是因为防敌对模型**(威胁模型里没有敌对模型),而是因为**模型根本不经手**。

### 3.2 状态拆两轴

| 轴 | 谁写 | 取值 | 回答什么 |
| --- | --- | --- | --- |
| **意图态** | 模型声明,写在 Markdown 标题 | `todo / doing / done` | 我还打不打算做 |
| **交付态** | 引擎从账本推导,**不落 Markdown、不落任何字段** | `unstarted / uncommitted / committed / verified` | 仓库里有没有这条的东西 |

划界一句话:**「我要不要做」归模型,「仓库里有没有」归引擎;引擎永不改模型的意图,
模型永不能声明交付。**

配套两处硬改:

1. **堵住 `update status=<终态>` 这条绕行道**。今天 `update` 到终态完全裸奔,全部关闭门禁
   只关在 `action == "close"` 里。实测后果:`close-telemetry.jsonl` 只有 17 行且全是 `D-*`,
   R-346~R-352 一条不在——近期 R 线是走 update 关掉的,一道门没跑。
   改法:`update` 目标为终态时转走 close 门禁,或在交付态 = `unstarted` 时拒绝。
   **这是全案唯一新增的硬拒绝**,判据来自账本,可满足性成立:提交过就有行。
2. 门禁一律 key 在**组合**上:`close` 放行 = 意图态 `done` ∧ 交付态 ∈ {`committed`, `verified`}。

### 3.3 门禁判据换成本条目改动面,并确立可满足性通则

| 位置 | 现在 | 改成 |
| --- | --- | --- |
| `close_verify_trigger` | `HEAD^..HEAD` numstat | 本条目账本所有 commit 的 paths 并集 |
| reconcile `target_fingerprint` | `declared_commit..HEAD` 全量 | 账本行记录的 paths |
| `implemented-uncommitted` | 全树指纹 | 脏文件 ∩ 本条目 paths(`source_endorsement_fingerprint_for_paths` 已存在) |

**通则(写进 conventions,并做成代码不变式)**:

> 任何门禁在拿不到本条目证据时**默认放行,不默认拒绝**;拒绝时必须给出一条本项目产得出的命令。

这不是道德要求,是可满足性的形式化。今天 reconcile 违反它:passed 记录的「源码指纹」取的是
**脏工作区**,干净树上返回空串因而根本不写该字段——所以「提交后再跑测试」产出的记录必然
无指纹、必然覆盖不了 target、必然永远 `committed-unverified`。要翻案得让几百个别人改的文件
同时以 HEAD 内容脏在工作树里,实操不可达。

### 3.4 调度:只提示、只降序、永不封禁

1. 对账结果**不改分类**,不进 `blocked_items`。
2. 只加一行短提示到该条目 hints:`看起来已提交待关闭(3 commits / 12 files),确认要关闭还是继续?`
3. Start 候选里**降序,不剔除**。
4. 硬不变式测试:**存在非终态且未停车的条目时,`decision` 不得为 `Blocked`**。

> **2026-09-02 实施状态**:本节由 D-736 B1(`7823d6f6`)先行落地并已验证:
> `blocked_items` 24→0、`parked_items` 2→17(停车/阻塞错分同时修正,不再推翻 D-434)、
> 裁决输出 191419→15035 字符(-92.7%)。剩余 §3.5 的可见性问题未动。

### 3.5 对账要有出口:prompt 裁剪与结构化输出分家

1. `compact_for_context` 只作用于 **prompt 注入路径**;`kz work next` 今天与 prompt 共用
   同一个 compact,导致 26 条判定算出来却 `reconciliation.items = 0`——**判定全不可见**。
2. 新增只读动作 `work reconcile`:输出四类全表,每条给 id / class / 账本行数 / 改动面文件数 /
   `test_record_ids` / 缺口一句话。**不含指纹串。**
3. `block_reasons` 里只放「class 名 + 条目 id + 文件数」,细节让模型去读 (2)。

### 3.6 字段三类 + 词表 + 清理

- **引擎字段**(模型不得写):`observed_head` / `observed_worktree_hash` / `recorded_at` / `取活依据`。
  今天已经是引擎写,但**没有「模型不得写」的拦截**——补上。
- **调度字段**(有机器判据,受语法门禁):`优先级` / `依赖` / `阻塞` / `停车` / `阶段` / `取得线` / `refs`。
  `阻塞` 必须带 `解除条件:` 或 `解除人:`(判据已存在,只在读侧判、不在写侧拒——挪到写侧)。
- **叙事字段**(自由文本):`内容` / `验收` / `进展` / `来源` / `发现记录` / `边界`。

建 `FIELD_REGISTRY`(键名 → 类别 + 有无消费者)。**不硬拒未知键**:R/D 各有 167/185 个不同键、
81/114 个只用过一次,硬拒会把历史全变成完整性破损,而完整性破损会拒绝该 kind 的一切写操作。
改为:未知键照写,但计数 + 在 `req get` 里标灰。

**该砍的**(确认零代码消费者):`对账`、`批次表`、`背景`、`根因`、`执行者`、`归属`、`原始描述`、`不变量`。
走 `ENGINE_DERIVED_FIELDS` 的现成先例(归档时 retain)。

**`不变式` 字段单独处理**:全库条目使用 **0 次**,却背着 355 行执行器 + 一道 close 门禁 +
一道 finalize 门禁(两道门因 declared 恒空而恒真通过);同期模型实际手写的是散文键 `不变量`
(归档里 82 次,零消费者)。二者类型不同(单行 JSON 断言 vs 散文),不能靠别名合并。
**按用户定调:删执行器与两道门禁,承认采纳失败。**

### 3.7 活动面/归档面按「裁决会不会读到它」划

1. **停车超期条目移出活动面**:停车 > 14 天且解除条件未变 → 移入 parked 面,裁决不再遍历,
   但 `work reconcile` 与前端面板仍能看到。
2. **`tests.md` 废止为 Markdown 面**:它 12 字节、0 条记录;唯一可能的居民是 `running` 记录,
   而 running 是瞬态,不该占治理真源(A-012 的 Markdown 是**治理**真源,不是瞬态状态板)。
   running 迁 `state.db`。
3. **「还需要跑什么」由 `kz work gaps` 回答**,而不是靠一个活动文件。输入 = 账本改动面 +
   该条目 passed 记录的指纹覆盖 + close 门禁判据;输出每条缺口一行,**附一条可直接复制的命令**。
   给不出可执行命令的缺口不出这一行(§3.3 通则的落地)。

### 3.8 批次与 Work Unit 收敛到一套

现状是两套并行账本,close 时两道门同时跑、**中间零一致性校验**(设计文档明写这是有意的)。
采用率:Work Unit 全库只用过一条,批次遍地;而「Git 是批次真源」这条不变式对 work_units_v1
静默失效(命名空间只认 `B`/`S`/`批N`,不认 `W`)。

**方向:废 Work Unit 的独立机制,保留批次**,并把 Work Unit 唯一不可替代的东西搬上来:

1. **分子停止手写**:`批次: k/N` 的 k 由 git 推导(引擎已能推、推导值也已优先,只是**对模型
   不可见**,所以模型必然在 close 那一刻才知道对不对得上)。改成接受 `批次: /N`,存量 `k/N`
   继续解析但 k 被忽略,删掉那道对账门。立刻解除四条存量地雷(R-283 3/5 vs 2、R-101 3/6 vs 2、
   R-312 2/3 vs 1、R-249 0/4 vs 2)。分母 git 推不出来,继续手写。
2. **acceptance ↔ evidence 的机械绑定下沉到条目级**:把今天的「文本包含条款号」升级成
   「每条款一行结构化 evidence(`file:line` 或 `T-` 记录 id)」。
3. **删 `执行模型: work_units_v1` 开关**:双门之所以互不校验,就因为它是可选开关。

## 5. 迁移路径(存量一条都不用回改)

1. **账本从今天开始记,历史不补**。账本行数 = 0 的条目走**遗留模式**:交付态由 `observed_head`
   启发式推导,但**只作提示、不作门禁**。
2. **交付态是纯派生量,不落 Markdown**——不存在「给几百条加字段」,也不违反 A-012。
3. **门禁切换走双写观察期**:新判据与旧判据并行计算,新判据只记 `work-log` 不拦;跑一周看分歧,
   收敛后切换。两边都是只读计算,极便宜。
4. **字段清理走归档钩子**:零消费者字段加进 `ENGINE_DERIVED_FIELDS`,归档时自动 retain;
   活动面手动清一次。归档的 2780 条**永不回改**——它们不进任何裁决。
5. **批次**:分子停手写,存量 `k/N` 继续被解析、k 被忽略。零回改,四条地雷当场解除。
6. **停车归档**:一次性把停车超期条目移入 parked 面。批量操作,不动内容。
7. **`tests.md`**:直接删,running 迁 state.db。12 字节,零迁移成本。

## 6. 边界(本设计不做)

- 不为「模型故意造假」设防——威胁模型里没有敌对模型,防线是结果侧快照 + 回滚(A-013)。
- 不引入外部 CI 或多人评审作为证据源:本项目产不出,门禁就不能索要。
- 不做全局 schema 强校验(会把历史条目变成完整性破损,连带拒绝该 kind 的一切写操作)。
- 不回改归档条目。
- 不改 Markdown 作为治理真源的地位(A-012)。
