## 状态与持久事实

| 事实 | 真源与约束 |
| --- | --- |
| 当前代码与用途 | 当前 `cwd` 工作树；用途指纹绑定实际内容 |
| tracker、决策、规范 | 主项目根 `.kanzei/project/`；通过相应领域工具维护 |
| 长期记忆 | Markdown；检索、图和目录投影可重建 |
| 会话、任务与运行事件 | core 的持久领域服务与 SQLite 事件；UI 数组不拥有运行事实 |
| Skills | 全局 catalog；按需读取正文，不按项目另建发现目录 |
| 研究课题 | 独立课题身份与存储根，开发项目关联可选；旧材料不因导航变更自动迁移 |

所有异步结果携带会话/项目/课题身份。切换视图、隐藏浏览器或查看记忆不改变执行归属。关闭、归档、停止和永久删除分别使用其生命周期，不能靠清空界面代替持久操作。

自定义 Agent 是可选的主 Agent 或子代理定义，拥有适用档位、模型引用、步数预算与正文；它不增加工具能力或执行授权。Agent 来源由 harness 的 `agent_sources` 一次读取和解析，运行注册与设置目录共用该快照。正文仅在选为主 Agent 或委派为子代理时装载，不将其他定义、项目规范或仓库文档拼入主提示词。TOML 贡献类型配置与权限规则，不定义 Agent 正文。

同名 Agent 按内置模板、用户全局 Markdown、内容已批准的主项目 Markdown 顺序覆盖。项目批准绑定项目身份、文件路径与全文版本，注册直接使用被批准的读取快照，后续修改使旧批准不再匹配。目录保留有效但未批准、被覆盖、档位不适用和配置错误的来源，显示版本与真实注册链；诊断报告不包含规则正文。Agent frontmatter 使用 YAML，支持 `name`、`profile`、`mode`、`model`、`steps`，重复或未知字段及错误值产生配置诊断。

无项目目录显式加载全局配置，不从进程工作目录发现项目或读取项目批准；General 模板先注册，用户定义随后覆盖，末尾的项目能力投影只裁剪工具和上下文。Isolated 不安装自定义 Agent 来源。设置页统一称为“Agent 定义”，原文入口限定所选全局/项目来源目录的 Markdown，并作为独立编辑器参数打开；切换项目或档位后，旧目录响应不能覆盖新范围。修改后刷新会重新解析来源，原快照的预览和版本保持其读取时的含义。

General 主提示词只约定当前请求的自主协作、无项目工作目录和真实产物交付。方法、工具与协作按任务需要选择，验证范围依据当前请求；主提示词不枚举工具能力或项目流程。工具目录、来源策略、技能、偏好及运行环境通过各自的上下文来源装配；项目工作流边界由实际能力投影执行，用户指定路径仍受当前请求和工具权限约束。

Readonly 主提示词约定自主调查、证据区分与只读交付，不以提问或固定工具顺序作为分析前提。档位定义与执行策略在 CLI、桌面和定时任务的共享装配中注册。工具物化、延迟目录与权限快照统一依据 `ReadOnlySupport` 排除未审计的能力；运行器在串行和并行执行前检查具体操作，Readonly 档位不能被普通执行策略、会话放行或自定义 Agent 正文升级。混合工具的写操作仍被拒绝，委派沿用只读范围；来源缓存、日志及控制记录是系统观察事实，不能成为修改用户资源的旁路。桌面端不再维护另一份工具和 Git 命令限制列表。

Isolated 使用独立的能力集合，主提示词只保留调查目标、显式输入复制、一次性沙箱及结果边界。项目代码仅通过 sandbox 执行，不联网，不向宿主发布文件；输出可给出发现、建议与补丁文本。运行前提、执行参数和失败由 sandbox 工具合同表达，权限放行不安装缺失的宿主、项目自定义来源或子代理能力。

社交会话使用独立能力投影：大肥鱼入口、QQ 好友、群聊与 B站均不注册宿主 shell、文件、桌面、浏览器、子代理或延迟工具；普通无项目助手保持原合同。该投影在自定义 Agent 与权限配置之后执行，自动放行不能恢复未注册能力。渠道组件只追加自身记忆、读取、草稿与发送工具。持久 sandbox 的挂载路径由受信会话身份派生，模型参数仅有命令和时限，不能选择宿主挂载或打开网络；只挂载专属工作区、只读 /usr 与临时 /tmp，不传递宿主环境、磁盘或 WSL 互操作。个人社交渠道共享 `social-workspaces/personal`，群按机器人账号与群号分别存储；这些目录与会话数据库、配置、登录凭据、记忆目录分离。跨会话写入通过工作区目录锁互斥，取消和超时先回收 namespace 再交付结果。公网检索复用 websearch/webfetch，其中网页传输验证并固定公网 DNS 地址，各次跳转仍走原权限与地址校验，不访问 localhost、内网或云元数据。持久目录无总配额；命令资源与单文件写入受执行器限制。

主动搭话由 `kanzei-app::initiative` 持有会话策略、话题意图与评估租约；消息事实仍归原 SessionStore 和渠道发送账本，长期记忆仍归 kanzei-memory。受信根目录、process 与 session 共同绑定归属，模型只能操作原会话话题。`social_plan` 保存主题与依据，不缓存待发送成品，也不把模型笔记当作已确认记忆。评估装配与原会话共用渠道、人设和记忆范围；输入为带 role/origin 的有界原聊天投影，省略与截断显式标记。严格结构化决定只允许选择 speak/defer/silent，评估过程不发送聊天消息。

评估租约串行化同一会话的自动开场。选中的意图通过稳定命令号投递为原会话 Engine 输入并绑定真实 run_id，不新建对话或伪造人类发言。调度、提交和渠道发送边界再次检查真实人类输入号、QQ 入站序号、停止代际、策略与话题版本、安静时段和消息预算；QQ 检查与开始发送共享入站锁。新输入先取消旧评估/输出并更新停止水位，再准入新消息。HTTP 评估可取消，停止后的目标仅由不同的人类活动或显式保存设置恢复。QQ群安静时段由群规则唯一持有，旧主动间隔只用于一次性迁移，不再产生定时空消息任务。

自动开场不向界面流出未确认的正文或推理；真实发送或核心提交完成后才展示一次正文。管理事件只更新原会话策略、话题与原因。发送中断记为 unknown，相关话题转为 uncertain；重启不重放未确认消息。每日与未回复预算计入确认及未知发送，同毫秒的新回复仍按输入身份重置未回复预算，不能用时间戳猜测已读。后台失败保留原因并暂停自动评估，不自动重试。前端按会话隔离草稿并使用版本保存，后台刷新不替换正在编辑的表单。

Research 常驻正文约定当前请求范围、自主调查、可追溯证据与真实交付，保留结构化研究记录的 V0–V3 口径。具体计划、检索循环、实验和论文操作由对应工具及当前状态说明，不在主提示词中预设用户已授权，也不把所有研究请求扩展为完整论文流程。

`research/docs` 按模型步骤读取主项目资产，装配 topic 内的来源/发现与项目需求/缺陷的非终态记录导航。条目与全文版本来自同一个 DocStore 快照，保留 topic、状态、来源路径和版本；记录状态不证明证据已验证或当前执行授权。整块使用共享字符预算，轮流选择各类记录，整条列出或省略；预算包含来源说明、版本、闭合标签和省略回执，省略量不再展开成完整编号清单。历史 flat 文档与 research/memory.md 不自动装配，归档与其他记录按需读取；没有匹配记录时不生成空块，读取失败保留来源错误。导航不改写记录，也不自动登记来源、发现或工作项。

绑定课题的研究对话通过独立的 `research/topic` 必需动态来源提供 topic 与实际工件目录；不向 Agent 定义追加课题规则，也不限制比较其他课题。目录由主资产根解析，消失或越界时报告来源失败。旧 AUTO Research 阶段机、流程工具、专用续跑分支、界面及 IPC 已删除；历史 `workflow.json` 保留为工件，不再解释为控制或预算来源。研究任务的方法与步骤由 Agent 在授权范围内决定。计划、检索记录、写作及实验工具各自维护自己的事实合同，检索预算来自显式预算文件或计划，仅在工具调用时读取，不自动装入模型上下文。研究档不再提供阶段机驱动的跨轮自动续跑。实验准入由运行记录服务在事务中拒绝重复 result_id，结果路径复用领域服务的标识校验；执行策略、环境租约和实际资源预算仍由实验工具执行。

延迟工具由 `kanzei-harness::tool_search` 提供有界目录和发现合同，runner 负责把选中 schema 加入后续请求并逐项计入账单。目录最多 4000 字符，包含完整行、总量及省略后的继续位置；空 query 可按 offset 浏览。关键词分页以完整排序结果定位，已加载状态不改变后续页位置；精确 select 接受最多 10 个不同名称。输入越界、空选择及未知字段明确拒绝，不截断或钳制后继续加载。搜索结果仅回传 loaded/already_available/unknown/matched/next_offset，不再把完整描述与 schema 复制进历史；未知名称与已成功加载的部分分别报告。直接调用仍会加载允许的延迟工具，权限和只读边界照常执行。工具描述只说明能力、结果及必要约束；字段语义和枚举保留在 schema，详细格式说明通过对应查询按需返回。

开发模式的需求、缺陷、测试台账和记忆投递工具默认延迟装载；`work` 仅在 DevAuto 常驻，DevPair 按需装载。已加载 schema 的生命周期是一轮运行，轮内后续步骤和上下文压缩继续使用同一工具集；新轮从当前档位的常驻工具开始，不因历史调用或发现回执重新展开旧工具。历史调用及结果仍保留在对话中，发现、直接调用、权限与受管文件写入继续走原有实现。

临时运行上下文只报告实际执行边界：达到步数上限或获得收尾额度时追加预算事实，不按固定步数追加工作盘点。自动续跑文本保留引擎来源标记，提供当前选择、现有队列和记录中的等待状态，不要求固定实现步骤、登记或修改阻塞字段。重复 Git 输出和已知路径不再触发结果注入，旧冗余判断器、兼容标记解析、画像字段和界面提示已移除；普通调用、拒绝和故障计数继续保留。参数纠错只报告真实解析问题，不复制 schema、原始输入、虚构参数示例或固定重试指令。权限拒绝说明实际规则和所属写入工具在当前档位的可用性；缺少能力不自动产生缺陷登记任务，回滚结果报告恢复与隔离事实。旧连续轮数上限及其偏好、IPC、状态与历史事件适配已删除；轮数仅用于观察，用户暂停/停止、实际失败熔断和目标停止合同继续有效，停止回执中的阈值由其真实原因提供。

固定步数触发的实现批次门禁、强制验证/提交/台账更新指令及重复源码检查点账本已删除；实现、委派、提问和交付不因该计数窗口而被封锁或强制续跑。既有文件、会话事件、工具回执与 Work Unit checkpoint 保持各自的恢复和完成合同，历史批次工件不改写。子任务返回只报告实际结果及其验证边界，不附加固定整合或测试步骤。

Skills 目录按模型步骤刷新，仅显示已启用、允许模型选用的元数据；目录按 6000 字符预算整条列出，省略条目通过 `skill_list(query, after)` 查询，正文由 `skill_read(id)` 按需读取。索引不按关键词强制工作流，没有可选技能时不产生空指令块。技能以 `source:name` 标识，目录记录全文版本；正文读取发现版本已变时保留错误，不将旧元数据与新正文拼接。

桌面、CLI 和定时任务共用显式技能装配，选择依据实际领取的原始任务输入，在附件或前序输出合入前完成。`$source:name` 精确选择来源，唯一名称可简写；代码围栏和引用中的文字不触发装配。正文作为本轮快照单列 `skills/invoked`，不拼进 Agent 主提示词或持久消息；它保留原输入的权限范围，不证明人类作者身份，也不增加操作授权。停用、允许手动调用和允许模型自动选用分别生效；Isolated 不读取全局技能，子代理不继承父运行的显式正文。停用记录只接受来源限定标识，没有旧名称映射或按项目发现的兼容入口。跨产品全局资料库读取和显式导入仍是独立能力。

环境上下文按模型步骤刷新，项目与无项目对话共用本机日期、UTC 偏移和执行环境格式。`run.facts` 保存主运行启动时的身份、配置模型与时钟快照；`run.baseline` 保存启动时的 Git 观测，两者均不充当当前状态。起点不能单独证明文件归属，采样错误与裁剪部分保持未知，完整事件可回读；Isolated 不执行宿主 Git 探测。

稳定 system 只包含 Agent 指令、静态能力约定与固定工具目录。运行身份、时间、起点快照、完成契约、任务召回、已调用技能与每步刷新源，在历史之后、当前输入之前投影为带来源的请求级运行上下文；预算准入、实际请求和来源指纹使用同一内容。运行上下文不进入对话消息，不在下轮重复回灌；必需源失败仍在请求前停止，刷新替换旧值，不删减原始约定。历史压缩和用户改变指令仍可以改变缓存前缀。

同一进程中的本地推理调用按服务地址共享准入，不按 primary/fast/compact 别名分池。交互运行跨模型步骤和工具间隙保留服务；记忆整理、主动开口评估、文件用途标注与导出摘要属于维护请求。交互到来时，维护请求丢弃尚未提交的模型步骤并关闭 HTTP，等待交互结束后继续；已完成工具及其回执不重放。前台请求之间保留并发，远端服务沿用自身并发策略。该准入不接管其他进程直接发给同一服务的请求。

项目概览使用有界文件探测，缓存按代码根与项目资产根共同区分，最长 30 秒或失效后重采样。布局、清单和工具链来自当前代码树；需求关键词线索来自主项目的活动需求，明确标为未确认，读取错误单独表达。工具文件定位不等于版本可用性验证，未定位不等于未安装。概览只提供事实与来源边界，不选择建库、安装、工程搭建或交付流程。

## 执行、工作与交付

运行装配进入 [runner](../../crates/kanzei-core/src/runner/drive.rs)。权限、工具执行与结果语义遵守 harness；拒绝、需要修正、等待用户和执行失败应保持可区分，不通过重试或吞错伪造成功。压缩只改变模型可见上下文，原始事件和可追溯引用保留。

消息来源独立于供应商的 `user/assistant` 传输角色，贯穿准入事件、输入队列、实时运行、历史事实与提供商投影。用户、引擎、通知、Agent、工具和摘要分别标记；历史缺失来源保持未知，不按正文前缀补成用户输入。附件原文和可读引用持久化，输入正文保留原样；附件资料沿用来源数据标记，不追加强制读取指令。回放和导出展示实际来源。

持久输入队列同时承载用户消息与后台回传，调度顺序和停止结算统一处理；输入框的「排队输入」只投影明确标记为 Human 的记录。子任务、工具完成、引擎唤醒、摘要与未知来源不占用用户队列计数或撤销控件。用户回答后台问题仍保留 Human 来源，可以按用户输入撤销；撤销 IPC 按持久来源检查，不能用后台消息编号绕过界面撤销任务证据。

运行中发送消息默认插入当前任务；显式排队才等待下一轮。插话经过持久化输入通道，工具结果完整提交后纳入后续模型请求。停止确认与停止完成分别表达：`kz:stopping` 保持运行所有权和可继续提交输入的通道，重复停止仍为同一次协作取消；后台写入任务结束且会话执行锁释放后，调度器才能公布 `kz:idle`。界面不能用停止指令的确认提前表示空闲。

会话生命周期由 core::ConversationSupervisor 唯一裁决，输入持久 inbox、后台资源、自动推进与客户端 outbox 各自保留所有权。监督器在 worker 被强制取消后继续存活并 join；writer、所属资源和执行锁未结清前不得公布空闲。重复停止保留原输入水位，之后的新输入等待回收后继续执行。process_list.runtime 与 kz:lifecycle 使用同一个 actor_epoch/revision，前端超时只查询并表达未确认。第一条消息也先持久准入，outbox 重试复用 commandId；相同 ID 改载荷返回冲突。具体转换、兼容投影和验证边界见[运行时状态机架构](../architecture/01_runtime_loop.md#当前实现与所有权)。

引擎熔断审计属于合法托管写入，必须通过现有 managed_fence 写入窗口更新后台守卫基线；其写入范围只覆盖审计日志，不能让后台任务因引擎记账被误杀，也不能放宽其他项目文件的保护。

自动与手动压缩共用来源明确的记录。摘要按任务内容组织，保留仍有效约束、进度、证据和待办，不要求空标题或固定验收仪式；手动压缩重点作为数据传入。机械摘录只记录用户输入和工具请求/回执，不推断命令执行、提交号或验收成功。摘要保留归档引用并标明截取，长度与文件名检查只用于排除明显不合适输出，不证明摘要正确；无可用纪要时保留来源摘录。压缩、缓存与导出不改变材料的授权属性。 溢出恢复保留用户与未知来源的输入、原委派任务和已有摘要；只有上下文实际变小时才重试，无法安全缩减时终止该次恢复。

需求/缺陷登记、想法拆解和缺陷审查是按钮范围内的独立任务，使用所选任务配置的模型，不在失败后换模型重做写入。登记工具只提供读取、新增和显式复用；原文由应用保存，来源由工具绑定，不将旧自由字段转换为新需求契约。回执来自实际保存或复用的记录，模型文字不能制造编号。拆解工具只允许读取所选想法及提交 `split` 与真实产出引用，引用必须覆盖本次登记结果；完成时机由 Agent 判断，应用不根据新增条目推断完成。中断保留真实产出和未完成状态，审查报告保留未核实和截断边界。

调研按钮只委托调研，继续推进按钮保留实施目标；规划和方向调整按钮表达目标与范围，不注入固定工具序列或旧队列迁移步骤。跨对话交接冻结来源段并保留消息来源，作为引用材料随用户交接意图传入，不额外要求登记、调研或实施。

需求目标、Work Unit、执行状态和历史分别建模。父子归属与依赖是不同关系；准备度从领域事实推导，不按 UI 节点比例计算完成。交付将条目、commit、paths 与验证事实关联；源码存在、定向测试、真实设备/服务、发布和安装是不同证据。

Auto 项目工作流按步刷新默认工作选择及状态；Agent 可说明理由在工具约束内调整选择，实现方法和拆解粒度由任务决定。动态上下文只解释当前适用的执行、规划、目标收口或方向复核操作，不叠加互斥阶段，也不规定批次数量、提交标题或设计冻结流程。依赖、归属、WIP、契约版本与验收约束由领域工具校验；历史进展、工作树快照和测试记录保留各自的来源与适用范围。

自动测试记录区分进程结果与测试结果：未声明验证合同的零退出码为 `unknown`，不作为通过证据。`python_unittest` 合同仅在恰有一份非空、无跳过的 unittest 汇总且结果为 OK 时通过；失败汇总即使退出码为零也判失败。`exit_code` 合同是调用者声明，适用于零退出码确实保证至少运行一项且全部通过的命令，记录无法自行验证该声明。日志保留合同、退出码、可取得的测试数量及源码身份。历史自动通过记录如果没有合同，在读取和证据消费时标为无法判定，原台账不改写；手工登记的外部证据仍保留其来源和既有语义。

完成声明区分工作项、阶段、请求与目标。局部交付不代表整体完成；请求标识与当前目标分别绑定，目标存在时请求完成也不能清除目标。完成契约根据真实推进开关和工作来源装配，Pair 的请求循环不接管项目队列。声明先持久化，再返回待控制器核对的回执；记录失败不能产生成功完成信号。运行中接纳新输入后，旧完成声明失效，须基于新输入重新判断。

`[cadence]` 是模型可见的验证、提交和推送节奏偏好，不构成操作授权或后台调度。Auto 自主组织实际工作批次；Pair 围绕当前请求选择验证范围，提交和推送节奏只在任务包含这些操作时适用。推送统一由 Agent 选择 Git 工具执行，轮末提交成功不触发额外推送。项目验证入口、工具提交门禁与发布要求独立于节奏配置。

自主模式不要求普通实现选择逐项登记。`question` 用于记录值得复核的重要决定或调查后仍缺少的必要外部事实；须提供结论或事实缺口，不先生成占位决策。决定记录不构成用户答复或权限授权，也不要求等待复核后才执行。事实缺口只影响依赖工作，不强制创建跟踪条目或调用队列工具。用户纠正默认作用于本次，只有明确选择项目或全局范围时才保存长期偏好。

并行写任务使用独立 worktree，主项目资产仍指向主根；Git 预检和合并不证明语义正确。工具编辑与受管写入使用现有路径、锁、内容指纹和 CAS 合同，不复制第二套写通道。

协作快照分开表达当前身份、对话和工作树。对话关联 session、run 与工作树；同树 Git、登记关系和写租约只采样一次。查询包含空闲对话及 Git 仍登记的保留工作树，工作树发现失败单独报告。未提交变化与共同祖先至工作树 HEAD 的分支提交差异分别计数、查询路径并保留错误；计数不证明冲突或修改者。tracker「取得线」只作为带来源的工作登记，界面不据此声明负责对话或开工状态。运行状态来自执行与等待事实，活动时间不用于推断进展或卡住。子 Agent 的过程和结果归团队能力提供。

子任务消息通过运行器输入通道进入对话，消息状态与正文历史在同一事务中保存。`queued` 表示待投递，`admitted` 表示已持久化到对话，不代表模型已收到或理解；对应运行成功完成后才标为 `processed`。上下文中的消息列表只读状态快照，读取不能确认投递；历史展示限额不能裁掉待投递消息。消息保留来源、标识与时间，不构成新增用户授权。子任务经验缓存按项目、角色和任务名称共享，正文按字符预算裁剪并报告省略量，可完整读取；它与正式项目记忆分别管理。

## 界面与资源

当前工作区采用对话/管理组织，记忆和 Skills 有全局入口，后台任务在活动区，网页预览有独立页面身份。下一版管理设计尚未实施，见 [管理工作区方案](management_workspace.md)。

前端为原生 ESM。command 注册、参数与返回结构应与实际 invoke 一致；事件经公共订阅进入状态拥有者，再触发渲染。共享弹层、焦点和尺寸使用已有 surface/frame 组件。主题 token 负责颜色，状态应有文字与键盘可达路径。

全应用文字使用 12 / 14 / 16 / 24px 四档 token，最小 12px；第三方数学排版、图和编辑器内部排版保持各自语义。分隔线使用共享半像素 token，辅助信息以灰阶、字重和留白分层。全局记忆、Skills 与设置位于侧栏，侧栏开关常驻窗口栏；窄窗导航覆盖工作区，文件树与编辑器上下排列，各自滚动。弹层在窄窗使用较低投影层级以保留完整阴影，外观仍只由 surface 管理。输入框最高 200px 后内部滚动，中文选词的伴生 Enter 只拦截一次，后续主动 Enter 正常提交。浏览器页面矩阵与裁切检查由 `ui-desktop-workbench-smoke.mjs` 记录，模拟 IPC 与原生桌面验收分开留证。

文件写入核对请求路径、物理路径、授权根和磁盘内容修订；外部修改必须显式处理。浏览器区分 pane/headless/attached，页面与 iframe 身份不能由可见性推断；原生窗口有独立权限和验收。截图和渲染正文保留实际来源与观察范围。

## 记忆与研究

公网网页、图片和表情下载统一通过 `public_http`：域名使用配置的 HTTPS JSON DNS 服务查询 A 与 AAAA，默认 AliDNS；引导连接固定到该服务公布的公网 IP，保留域名、TLS 证书与代理策略。解析不使用系统 DNS，因此 Clash/TUN Fake-IP 不成为下载目标。两族全部地址先经过同一公网校验，再将源站连接（含代理 CONNECT）固定到已验证 IP；重定向逐跳重新解析与校验。DNS 错误、截断、问题不匹配、非 HTTPS 引导配置及任一非公网答案显式失败，不切换解析器或放行保留网段。`web.public_dns` 将 endpoint 与 bootstrap 作为原子配置覆盖；模型与 OneBot 的受信端点保持自身网络合同。

联网表情候选与已有收藏共用 `StickerOffer` 投影：素材元数据之外同时返回由 `ReplyInput` 序列化的完整 `reply` 参数，包含选中 ID 的 sticker 附件；发送方可以修改正文并保留附件。该投影不写入素材清单，检索成功不代表发送完成，实际 OneBot 附件和发送回执仍是交付事实。空回复的纠错反馈说明如何提交附件，不能把文字描述当作已经发图。

QQ 是现有无项目运行器的输入/输出适配器，使用 NapCat 的 OneBot 11 正向 WebSocket；传输 SQLite 只拥有对端映射、原始消息、持久输入作业和发送回执，Agent 历史、调度、工具事件与恢复仍由现有 SessionStore/运行器拥有。好友接收与持久输入作业在同一事务中提交，输入使用稳定命令身份进行幂等调度。消息入口与同一连接上的接口响应解耦，身份校验等待响应时不能因入口积压阻止 socket 读取。重连不重放变更请求；明确失败和未知结果分别留证。

最终响应工具通过 `ToolResponseMode::FinalResponse` 声明输出所有权，完成读取与检索后单独执行。成功结果的正文必须是实际交付文本，平台回执放入 display；运行器提交工具结果，再以调用身份提交独立的 assistant 消息并结束本轮，不再向模型请求另一份答复。失败、未知结果与非成功终态仍进入处理回路。`qq_reply` 使用此合同，纯文本转换后的实际发送正文同时作为实时、本轮摘要与历史恢复的最终答案；仅附件回复可以没有正文。

底部上下文面板提供“清理上下文”，复用当前会话的 `conversation.reset` 开启新段，保留旧段历史、草稿、记忆和其他会话。运行中或存在排队输入时拒绝清理。QQ 重置在接收锁内记录当前对端的消息游标；后续最近聊天与自动图片选择只读取游标之后的消息，旧的未接纳作业标为 superseded。异步加载图像后再次校验边界，校验与输入接纳共用重置锁，防止清理前准备的内容落入新段。

QQ 好友与群聊共用结构化 `qq_reply` 出口，支持正文、工作区图片/文件、按素材 ID 选择的自定义表情、内置 face 与真实商城表情元数据。每轮最多一次发送；好友未显式调用时自动发送回合正文，已有发送回执（包括 failed/unknown）时不再追加完成说明。Agent 默认使用 QQ 纯文本；所有正文出口通过 CommonMark 解析转换为可读文本，保留代码缩进、列表、表格单元和链接地址，普通 text 段不执行 CQ 码。复杂排版由 Agent 在工作区制作图片或文档后作为附件发送，不自动截图每条回复。附件路径仅接受当前受信社交工作区的相对路径或 `/workspace/...`，使用目录能力在实际读取时阻止越界及符号链接逃逸；发送原始字节的 Base64，不向 NapCat 传宿主路径。应用预算为每条最多 16 个附件、合计 16 MiB；发送账本只保存素材路径、大小和内容哈希，不持久化 Base64。`qq_stickers` 默认按关键词联网搜索表情图片，经统一公网传输下载、按真实字节校验后，保存原图及来源到当前工作区 `stickers/manifest.json`，返回实际视觉附件和可发送 ID；GIF 保持原字节。单次默认 3 项、最多 5 项，下载合计不超过单条回复的 16 MiB 预算。`qq_stickers` 始终执行联网搜索，仅接受 query 与 limit；`qq_sticker_collection` 独立按 ID、名称或描述查询已有收藏，空 query 列出收藏。空收藏不能被解释为无法联网检索。搜索页无可验证结果、坏清单与下载错误明确报告，部分成功时同时返回成功素材与下载错误。素材缓存及清单通过同一目录能力原子写入，不越过工作区边界。入站投影保留 image/face/mface/file 的平台数据，不把图片链接当作已经读取图片的证据。入站图片另以结构化来源和消息编号持久保存，当前消息与最近聊天使用同一投影，兼容 OneBot 数组与 CQ 字符串。`qq_image` 只接受当前会话已接收的 message_id 和从 0 开始的 image_index，先向当前账号的 NapCat 读取消息原文并校验消息编号、发送者与对端，再通过既有公网传输取得不超过 16 MiB 的真实图片，沿 ToolImage 通道交给模型；不接受 Agent 提供的 URL 或宿主路径。来源不存在、URL 缺失、下载失败及非图片响应明确报错，不能当作看图完成。当前输入由频道在首次模型请求前附加真实图片，不依赖模型先选择读图工具；文字与附件由同一 InputBatch 组装：固定作业上界，以下文重置游标、该发送者的上一直接作业或已接纳水群作业为下界；读取窗口中最近 100 条消息，直接请求将同一发送者的连续消息整体作为当前请求，其他成员仅作背景。单独 @ 是唤起信号，不能覆盖先前尚未处理的问题；已处理消息不重复拼进新请求。直接请求只附加当前请求批次中的图片，逐图保留 message_id/index 来源及加载状态，跨发送者或晚到图片不得混入。失败只作为明确的未读取状态进入输入，不能投影成空消息；单次输入预算沿用通用附件的 18 MiB。先发图再单独 @ 时可读取前图；旧文本记录迁移为空图片索引，仍可通过已登记消息编号读取平台原文，不从旧链接伪造已读取证据。

QQ 回复先理解整批请求；不明确的名字、缩写与现实对象的动态评价使用 websearch 核对，群记忆不能替代网页检索。表情可按人设约定主动使用；明确表情请求必须本轮检索、看图并选择，再通过同一次 qq_reply 发送正文和附件。人设中的旧工具名不注册别名，以实际 schema 为准。websearch 的 auto 在主模型没有托管检索能力时选择 Bing HTML 后端；显式 bing、duckduckgo、codex、responses 分别保留选择。Bing 复用公网 DNS 固定、重定向校验、来源引用与搜索回执，不支持的 recency/locale 过滤明确拒绝；空页、过滤后无结果、验证挑战、版式变化与传输失败分别报告，不自动换后端或重试。

QQ 会话根由引擎根据规范数字身份构造；登记拥有者先创建目录再规范路径，旧混合分隔符登记在同一拥有者中保留进程编号修复，运行、查询和事件使用同一 session 身份。平台会话默认使用结伴档位，自动轮由各频道自己的规则调度，打开界面不得开启项目自主续跑。按账号、friend/group 与对方号码分区。好友必须来自实时好友列表，才能触发助手或接收回复，权限确认只允许当前好友会话中的待处理编号。QQ 问题投影按 permission/question 类型格式化操作、范围、题目与选项，仅展示对应的允许/拒绝或回答指令；内部事件信封和工具执行日志不作为消息发送，未知事件不能退回原始 JSON。群仅接收已启用群的消息；普通水群按间隔、安静时段和主动搭话规则进入同一群会话。OneBot 结构化 at 或 CQ at 精确指向当前账号时，接收事务固化 direct 作业身份与入站载荷，准入时从传输事实构造固定消息批次，取消尚未接纳的旧水群批次，并通过同一稳定命令排队；direct 不受水群间隔、安静时段限制，并可在当前轮运行期间入队，仍使用同一群能力投影。@ 全体、其他账号和文本伪装不构成 direct。作业 trigger 与 pending/accepted/superseded 状态分别拥有原因和接纳事实，旧表迁移为原子事务。群能力投影是装配末端的权威目录，清除本机工具、延迟工具、子代理、技能与本地上下文，不依赖提示词限制；只有显式 qq_reply 发群消息，每轮最多一条。

个人 memory 的唯一拥有者是应用数据目录下的 general 无项目根，普通个人助手、QQ 好友与 B站按同一 MemoryStore、索引、收件箱、来源和候选生命周期处理。平台会话和消息数据库不合并；轮次证据通过公开 SessionStore 服务投影到个人拥有者，按来源数据库和 episode 身份幂等保留，不伪造回合。旧好友文件映射新身份、保留交叉引用、来源快照和原文件。群聊仍按账号和群号拥有独立 MemoryScope，不访问个人或全局记忆。工具和管理 UI 的 project 选择器始终指向当前拥有者，持久化 namespace 仍保留 personal/qq_group 等身份；列表、收件箱、管理对话和图谱共用该选择器。人工修改校验内容版本，模型线索不冒充直接采纳。

QQ 本机配置向导仅调用 NapCat 公共 WebUI API，管理凭据与生成的 OneBot 令牌仅在后端保管；配置读回确认后才绑定应用。B站登录挑战以当前挑战身份和终态约束并发，过期、替换或取消的挑战不能写入账号。B站使用通用社交能力投影，并追加读取和草稿工具；同一工具组件装配到个人助手、QQ 好友、群聊及 B站会话，共用后端登录账号，不改变各自 MemoryScope。扫码接收完整会话 Cookie，去除 Set-Cookie 属性并验证账号后保存；校验失败结束当前挑战，保留旧账号。请求错误区分传输与解析阶段，诊断移除含扫码标识的 URL。发布只经管理页显式操作，SQLite 事务绑定账号、正文版本及配额，sending 在退出恢复时变为 unknown，不重放未知发送。仅平台成功评论编号构成 sent 回执。视频信息、字幕和评论均标注实际模态；未读取的媒体不构成观看证据。前端只有“社交助手”入口，主界面沿用无项目会话控制器、输入框与运行事件，顶部选择个人、QQ 和 B站目标，右侧按需切换 QQ、B站与主动搭话管理；窄屏在同一会话区显示管理面板。已提交输入通过同一 input-received 事件携带输入身份、客户端命令身份和可见消息；本地发送按 commandId 归并，远端提交直接投影到所属 pane。后台实时内容不代表完整历史，首次显示仍装载历史；恢复中的工具调用继续绑定真实执行事件。二维码登录轮询由当前挑战生命周期控制，不因切页或关闭管理中断。管理开关保留当前会话与草稿，频道选择保存最后目标并参与启动恢复。群规则拥有独立增改删命令，在最新配置上原子修改，删除不涉及会话历史和 memory，其他表单刷新不得恢复旧规则。


候选、已确认、失效与归档记忆分别管理。来源、内容修订、使用机会、实际读取、采用/纠正反馈和保留/归档是不同事实；反馈不得跨修订套用，生成成功不构成晋升依据。收益需要真实任务或冻结对照评价，不能以召回命中代替。

`core/preferences` 是基础组件按模型步骤刷新的已保存偏好投影。项目库仅装配 active、preference 且无区域绑定的条目；全局库在此基础上仅装配 source=user 的显式保存偏好。active 不等同于用户逐条确认，投影保留 scope、ID、来源、更新时间、适用线索及文件路径，具体适用性由 Agent 结合当前用户指令判断。模块偏好、普通知识与任务经验按需检索，通用检索和失败召回不读取全局库。General 只装配全局偏好，Isolated 不安装此来源。

偏好整体投影共用字符预算，正文整条加载或整条省略，不截断规则句子；预算计算包含来源说明、按范围统计的省略回执和闭合标签。没有条目时不生成空块，来源读取失败明确中止该上下文装配，不当作没有偏好。原始 Markdown 与前端记忆编辑仍是真源，项目规范保持独立来源。

辅助模型按各自的输入/输出合同工作，不装配完整的主 Agent 工作手册。文件与目录用途只依据给定片段和有效来源，要求完整用途 JSON，解析失败或未正常结束不落成新标注；缓存继续绑定内容指纹，标注本身不证明代码语义已验证。Skill 生成只返回名称、描述和正文，不装配完整创建手册、不接受调用权限字段，也不重置用户的调用设置。网页辅助提取只选择已提供的完整原文行，不生成答案；未正常结束或越界选择不作为提取结果。

自动记忆整理、冻结来源提炼和人工记忆对话各用独立任务提示。自动任务输入为引擎来源数据，轮次编号仅作溯源，不触发晋升；步骤预算来自当前作业。核销只接受当前批次精确 `note_id`，不按正文或失败指纹猜测身份，不向模型提供整箱清空工具。自动任务只能提出候选并处理本批草稿；人工记忆对话保留显式操作范围和版本校验，候选、核销判断、已采纳和已验证保持可区分。

任务记忆提示按本轮实际任务检索项目库，只提供适用线索、完整路径、来源、更新时间与内容版本；不选择任务，也不因零命中要求登记记忆。提示作为本轮系统段组装，不拼入用户原文或持久消息历史。失败召回的指纹与元数据来自同一次策略构建快照，明确标注当前有效性未核验；后台词法检索返回检索时读取的完整条目定位，不混用旧快照元数据。读取或采用由 Agent 结合当前任务决定。

任务提示与失败线索各有包含说明及省略回执的字符预算，只整条列出，按实际列出的条目记录注入；重复条目不重复注入。失败召回保留原始工具结果与失败标记，读取错误、超时和检索不可用作为错误传递并记录 unavailable，与正常零命中的 miss 区分。召回、组装、读取、采用和收益分别观测，注入记录不证明模型已收到或采用，实际请求内容以 manifest 为准。桌面和 CLI 共用记忆准备入口；Isolated 不安装失败召回或任务记忆提示，显式嵌入配置错误不得静默改为无嵌入配置。

开发上下文中的项目知识概览是本轮装配时的采样，默认关闭，启用后只列代码根、项目资产根、首层区域、依赖、记录计数和来源诊断。层级包含与依赖影响分别建模，active 只是记录状态。概览不要求修改前预读、分阶段查询或登记经验；Agent 可直接按模块或文件调用 `architecture context` 获取新的采样。源码使用统一代码根解析，识别最近的独立 Git 工作树根，不将子项目扩大到外层仓库；记忆来自主项目资产。文件列表不再隐式附加项目知识正文。

模型的设计导航上下文只保留项目索引 `.kanzei/project/architecture/README.md` 的完整路径和内容版本；索引正文与目标文档按需读取，不按本仓库的 `docs/design` 路径或身份标签预装材料。索引标注不证明实现或验收结果。模型知识采集也不扫描猜测的设计目录，仓库自身的文档约定与检查留在项目资料和本地验证入口中。

概览与模块上下文的预算包含来源、诊断和闭合回执，整条列出或省略；正文不截成部分约束。模块记录提供主项目的完整来源路径及内容版本，回读时区分修订变化与不可读来源。架构上下文使用严格读取接口，失败返回工具错误；带警告的界面投影不能替代模型读取结果。

已接受项目决策从主项目 `decisions.md` 按模型步骤刷新，只索引 accepted 条目的编号、状态与标题；草案、已替代和已拒绝条目不装入。结论、理由、适用范围与后续校正保留在原文，索引不把标题转换成不可复议的常驻规则，不要求登记新决策，也不构成新增授权。适用性结合当前用户指令及后续修订判断，accepted 不证明实现或验收状态。

`DocStore::load_snapshot` 在一次受锁读取中同时取得解析条目与完整源文版本；文件缺失返回 None，读取失败保留错误。决策索引提供完整来源路径与该版本，预算包含来源、闭合标签和省略回执，条目整条列出或省略。没有 accepted 条目时不生成空块，来源错误通过上下文报告表达；装配不改写决策或推进其状态。

想法收件箱与决策索引共用装配实现，按模型步骤读取主项目 `ideas.md` 的版本快照，只列 inbox 条目的编号、状态和标题。数量表示该状态的记录数，不表示当前任务、排期或执行授权。正文按需读取，索引不将录入方式描述成“未经模型处理”，也不要求想法必须拆解。推进依据用户请求与既有授权，拆解产物的真实引用校验由对应写工具负责。

两个索引均按字符预算整条列出，预算包含来源、总数与省略回执；想法索引不再固定只显示前 20 条。已拆解和已放弃记录不进入背景索引，没有匹配条目时不生成空块，读取失败保留为来源错误。读取不会修改原文、自动生成需求/缺陷或改变工作选择。

研究按来源、发现、计划、实验、运行与产物追溯。代码证据与文献证据使用 V0–V3；仅读摘要不升级为正文核验。实验必须绑定环境、命令、输入、运行事实与结果；本机、SSH、设备和外部服务验收分别记录。语音当前使用本地识别与合成路线，真实麦克风、播放和打断按实测验收。

## 当前工作与历史规格

工作范围、原始验收和未决事项读取[活动需求](../../.kanzei/project/requirements.md)与[活动缺陷](../../.kanzei/project/defects.md)，不在此维护第二份待办。已有设计与交付不自动满足新的端到端验收，也不因删除旧文档而改变条目状态。

旧专题、报告和源码注释中的路径只保留历史定位意义。精简前资料的恢复方式见[项目入口](../../README.md)。活动条目的结构化文档引用转到本文；需要原方案细节时按其记录的版本恢复，不将旧地图行号、未提交描述或外部产品版本重新当作当前事实。

新能力先修改拥有者及调用方，再更新本文受影响的合同。执行与发布步骤统一见[贡献指南](../../CONTRIBUTING.md)，工程约束见 [AGENTS](../../AGENTS.md)。

网页 `webfetch` 与本地 `read`、QQ 图片共用按字节识别的 PNG/JPEG/GIF/WebP 判定。图片响应原样保存为二进制证据，并经 ToolImage 通道交给模型；包括同会话缓存命中。图片不得按 UTF-8 网页转换或进入正文行提取，错误状态、超限截断和伪图片响应不产生视觉成功事实。视觉部件统一使用 PNG/JPEG；GIF/WebP 经同一有解码内存预算的静态预览转换，动图仅展示首帧并明确告知模型，不能把首帧解释为完整动画。原始下载证据、表情收藏与发送仍保持原始文件字节，预览转换不能改变动画交付。
