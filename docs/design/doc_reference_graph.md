## 背景与问题

用户原话:「关于 kanzei 内部注册的文档的引用历史,因为我们不是有设计文档,需求会参考对吧,我想弄一套引用的标记和管理,然后前端做出来显示方便我们管理文档之间的引用关系」。

2026-09-25 对本仓做了只读勘察与量化,口径与脚本见「验证证据」。结论如下。

**引用分散在七套互不相通的写法里:**

- tracker 的 `refs` 与 `依赖` 字段;
- 设计文档头部的「关联需求/缺陷/决策」;
- 测试记录的 `关联`;
- 记忆 frontmatter 的 `refs` 与 `supersedes`;
- research 的 `depends_on` / `entry_refs`;
- prior-art 的 `出处`。

**规模:**

- 当前有 7948 条「源 → 目标」边。
- R/D/A 之间的交叉引用,约 **56% 只写在正文散文里**,没有进任何结构化字段。
- tracker 的 `refs` 字段共 721 行,已经在非正式地承载「条目 → 设计文档」引用(85 个路径 token),但没有代码消费这些路径。

**没有校验:**

- 需求、缺陷、决策、想法的 `refs` 从不校验是否存在。R-111 承诺过,没有落地。
- 设计文档头部的 ID 不校验。
- 设计正文的相对链接不校验。
- 实测悬空引用 46 条边、33 个目标,其中:
  - 7 个是 3dc1129e 把设计文档从短横线命名改成下划线命名后留下的旧路径;
  - 14 个是 git 历史里从未存在过的 T 编号。

**双向规则只在文档里,没人执行:** `docs/design/readme.md:46` 要求设计文档与 A-* 双向引用。实测:

- 双向成立 14 对;
- 设计 → A 单向 18 对(其中头部级 10 对);
- A → 设计单向 4 对;
- 35 篇设计文档一行关联头都没有。

**前端点不开:**

- `jumpToEntry`(`crates/kanzei-app/ui/11-docs-list.js:243-283`)只认 R/D/I/S/F。A、M、T 和设计文档路径点了只提示「找不到」。
- Markdown 查看器不把编号变成链接。

**引用历史没有持久来源:**

- state.db 里带 refs 的 tracker 调用只有 1 次。
- `.kanzei/.write-log` 超过 500 个文件就滚动删除。

## 目标与非目标

目标:

1. 定一套**引用标记约定**,大部分沿用现有写法。只新增一个可选的关系类型前缀。
2. 从 Markdown 真源**机械抽取**引用关系,形成可重建的派生索引:谁引用了谁、用什么方式、锚点在哪一行。
3. 从 git 历史推导**引用历史**:某条引用何时建立、何时删除、何时随归档搬运或改号。
4. 在写入侧对**本次传入**的引用做存在性校验。另给一份体检报告,列出存量问题。
5. 前端:任意文档都能点开跳转;每份文档有「引用 / 被引用」侧栏、引用历史时间线和邻域关系图;另有体检面板。

非目标:

- 不另起一套「链接数据库」当真源(A-015、A-001)。
- 不对存量违规做全局强校验,否则整类文档会拒写,变成棘轮。
- 不新增 agent 工具(D-662 工具面预算)。
- 不引入图库(`architecture_browser.md` 已按 A-007 否决 mermaid/d3)。
- 不覆盖项目根之外的 research 课题工作区(`~/.kanzei/research-workspaces/`)。

## 讨论摘要

- **真源放在哪。** 引用本来就写在 Markdown 里。另建一张引用表当真源,必然与 Markdown 漂移,项目在 D-276/D-294 一族付过这个学费。所以索引只做投影,可以随时删掉重建。
- **历史从哪里来。** 三个候选:
  - git 推导:全量重建约 3.1 秒,增量是毫秒级;重建出的 refs 边与当前工作树吻合 98.6%。
  - state.db 事件:覆盖面极窄,还拿不到 Claude Code、codex、人工编辑和 bash 写入。
  - 新建追加日志:同样拿不到外部写者。
  
  只有 git 能覆盖所有写者,选它当唯一来源。
- **要不要引入关系类型。** 单纯的「关联」回答不了管理上真正要问的问题:
  - 哪些需求在**实现**这份设计?
  - 这条决策被**取代**后波及谁?
  - 这个条目**依据**哪条决策?
  
  所以引入一个很小的闭集前缀。不写前缀时仍是「关联」,旧写法零迁移。

## 候选方案

| 方案 | 要点 | 结论 |
| --- | --- | --- |
| A 结构化链接库为真源 | 新表记录每条引用,写文档时同步写表 | 否:双真源;外部写者绕过写表;违背 A-015 |
| B 标记约定 + 派生索引 + git 历史 | Markdown 为真源;纯函数抽取;git 推导历史;缓存可删 | **采用** |
| C 事件日志推导历史 | 在 tracker 写路径记录每次 refs 变化 | 否:拿不到外部写者和归档搬运。可作为日后「谁、为什么改」的补充 |

## 最终方案

### 1. 节点模型

| 节点 | 键 | 说明 |
| --- | --- | --- |
| 需求/缺陷/决策/想法 | `R-n` / `D-n` / `A-n` / `I-n` | 活跃文件与归档文件合并,同一 ID 一个节点 |
| 测试记录 | `T-n` | ID 有 10 位和 13 位两种 |
| 记忆 | `M-n` | 读 `.kanzei/memory/` 与 `archive/`;M-009 两处都有,以活动目录为准 |
| 研究来源/发现 | `(topic, S-n)` / `(topic, F-n)` | S/F 在课题内编号,根目录与 r221-chain 有同号,必须带课题 |
| 设计文档 | 架构索引中的身份文件名 | 路径会改名,以索引身份为键;旧路径经 git `-M` 形成别名表 |
| 其他文档 | 相对路径 | 架构索引、conventions、research 报告等,只作为引用源 |

### 2. 引用标记约定

强引用是结构化字段,参与检查:

- tracker 的 `refs`(不阻塞的关联)与 `依赖`(阻塞,语义不变)。
- 设计文档头部三行:`- 关联需求:`、`- 关联缺陷:`、`- 关联决策:`。可选第四行 `- 依据文档:`。
  - 解析器容忍全角/半角冒号,也容忍「需求:」「关联:」这类变体。
  - 体检报告给出规范写法建议。
- 测试记录的 `关联`;记忆的 `refs` / `supersedes`;research 的 `depends_on` / `supersedes`。

关系类型是可选前缀,闭集,写在 `refs` 的单个 token 上:

| 前缀 | 含义 | 例子 |
| --- | --- | --- |
| (无) | 关联,默认 | `R-245` |
| `依据:` | 本条依据的决策或设计 | `依据:A-007` |
| `实现:` | 本条实现的设计文档或决策 | `实现:docs/design/cc_codex_alignment_20260925.md` |
| `取代:` | 本条取代的条目、决策或文档 | `取代:A-001` |
| `来源:` | 本条从哪个想法、发现或测试衍生 | `来源:I-003` |

例:`- refs: R-245 实现:docs/design/cc_codex_alignment_20260925.md 依据:A-007`。

弱引用是正文里的行内提及,包括编号、区间(`R-161~R-167`、`D-104～D-110`)、设计文档路径和裸文件名。它们自动抽取,在界面上单独展示(虚线),不参与强制检查。抽取正则用 ASCII 前后断言,不用 `\b`:中文字符在 Unicode 下算 `\w`,「见R-123」会被漏掉。

统一分词函数只保留一个。现在三套规则不一致:

- `Entry::refs` 只拆半角空格和逗号;
- `MemoryEntry::refs` 只拆空白;
- `parse_release_condition` 连全角标点都认。

新函数的规则:

- 拆分符:半角/全角空格、逗号、顿号。
- 展开区间:`~` 与 `～`。
- 剥掉括号注释,例如 `R-149 (medium)`。
- 识别关系前缀。
- 保留无法识别的 token 作为「脏 token」上报,不静默丢弃。

### 3. 派生索引

- **抽取:** kanzei-tools 新模块 `refgraph` 提供纯函数,输入文档文本,输出 `nodes` 与 `edges{src, dst, mechanism, relation, strength, anchor(path:line)}`。
- **复用:**
  - `architecture.rs::links()` 抽取 Markdown 链接;
  - `design_docs` 与身份索引作为设计文档节点集;
  - `validate_source_refs` 的存在性判定模式(但修正它的 M-* 路线,见 §七 缺陷)。
- **缓存:**
  - 写 `.kanzei/artifacts/refgraph/graph-<HEAD 短哈希>-<工作树哈希>.json`(已被 gitignore,可删可重建)。
  - 不建表,避免与回退、定时任务条目争 `SCHEMA_VERSION`。
- **存量兼容:** `refs` 带前缀后,现有消费方会看到 `实现:docs/...` 这样的 token,必须经统一分词函数剥掉前缀再用。涉及:
  - `coupling_signals` / `entry_paths`(`crates/kanzei-tools/src/tracker/scheduling.rs:765-851`);
  - 前端 `ref-link`(`11-docs-list.js:888-909`)。

### 4. 引用历史(git 推导)

- **事件:** `{commit, author_time, op: added|removed|moved|renumbered|renamed, src, dst, mechanism, relation}`。
- **按条目 ID 作键,不按文件路径。** 同一实体在一小时内「先删后加」合并为 `moved`,这是归档搬运:例如 6556d482 从 defects.md 删掉,5 秒后 0313cf88 追加进 archive。
- **改号:** `repair_reused_id` 这类改号记为 `renumbered`,见 814b9d6c。
- **改名:** 设计文档改名用 `-M` 识别为 `renamed`,并把旧路径折算成当前规范路径。
- **未提交:** 工作树中未提交的变化单独标为 `uncommitted`。
- **时间语义:** 取作者时间。
- **成本:** 全量约 3 秒。增量从缓存记录的上次处理提交开始。

### 5. 写入侧校验(只校验本次传入的值)

- **tracker add/update 的 `refs`:**
  - ID 不存在或路径不存在 → `needs_correction`,列出具体 token 与原因。
  - 存量值不校验,也不写进 `integrity_issues`,避免整类文档拒写。
- **tracker update 的 `refs` 是整体替换**(`crates/kanzei-tools/src/tracker/actions.rs:720-726`)。语义不改,但结果里要显式列出「本次被删掉的引用」,杜绝调用方传半份列表时悄悄删掉其余引用。

### 6. 体检(不阻断,按类报告)

报告以下问题:

- 悬空引用;
- 设计文档与决策单向;
- 缺关联头的设计文档;
- 改名残留路径(附新路径);
- 从未存在的 T;
- `refs` 里的脏 token。

入口:

- `kz refs check [--json]`;
- 桌面体检面板。

修复规则:

- 托管文档一律走 tracker 通道修复,不直接改文件。
- 是否把「新增违规」接进 verify,另行决定。见 TODO:接进去必须只看新增,不能让存量把门禁卡死。

### 7. 模型侧接口(不加工具)

- `req/defect get` 的输出追加一行「被引用:」,列出强引用来源(前 10 条加总数)。
- `architecture` 工具增加 `refs` 动作:查任意文档的出边与入边。该工具在工具延迟加载条目里属于延迟层,不占常驻面。

   - `jumpToEntry` 支持 A/M/T 与设计文档路径。

   - 记忆页的 refs 可点。

3. **引用历史时间线。** 列出该文档引用关系的增删与搬运事件,每条带提交号、时间和提交说明。选中一对文档时,显示这条引用「何时建立」。

## 技术选型与取舍

| 决策 | 选择 | 取舍 |
| --- | --- | --- |
| 真源 | Markdown | 索引随时可删;代价是每次查询要么读缓存,要么重扫(约 100 ms 级) |
| 历史来源 | git | 覆盖所有写者;代价是未提交变化只能标「未提交」,「谁、为什么」只能看提交说明 |
| 关系类型 | 可选闭集前缀 | 旧写法零迁移;代价是现有消费方要改用统一分词 |
| 存量问题 | 只报告不阻断 | 避免棘轮;代价是存量要靠体检面板逐步清理 |
| 图 | 邻域图 + 手写 SVG | 不引图库;代价是布局能力有限,够 1–2 跳使用 |
