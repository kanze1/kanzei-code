## 事实契约

- `recall_events` 是召回明细真源。旧 `index.db.memory_recalls` 仅保留历史，不再驱动当前页。
- 检索、注入、正文读取分别记录。读取按 `run_id` 关联到同一运行内最近一次包含该记忆的注入；跨线、历史和手动 UI 搜索不会被追认为读取。读取仅说明 read 工具成功返回该文件的文本，可以是部分内容，不证明理解、采用或阅读完整篇幅。
- 缺少读取观测能力的历史事件显示未知。注入率与读取率均不能作为行为采用或结果改善的替代。
- 排序先按相关性；停止用注入次数充当采纳率加权。仅未读取不足以自动降级记忆。移除基于该代理指标的一键降级 IPC 和按钮，保留逐条查看、修订与状态管理。
- 在线未复发与运行结束按原始含义保留，不再写为 action_changed/outcome_improved。历史 v1 代理记录不作为效果证明。
- 指纹经验晋升须关联对应 episode 中的失败后成功。恢复匹配相同工具与完整目标；读取文件、另一条命令成功或无关轮次不能验证先前修复。

## SQLite v23

新增 `recall_events.run_id`、`read_ids`，均可空。新增 `memory_recoveries` 保存 episode、失败指纹、失败和恢复调用 ID、工具及目标。索引支持运行内定位。

已有召回的新增字段保留 NULL，不推测身份或补造读取。已有文件记忆、事件、评估和来源记录保留；旧在线评估通过查询版本排除。迁移使用 SessionStore 现有事务及升级前备份。回滚旧程序前停用新进程并恢复升级前整库备份；不要仅修改版本号。测试用临时 v22 库验证迁移与幂等，本地用户数据库不主动升级。

## 验收

- 后端：新表有事件、旧表为空时明细仍完整；两条并行运行读取同一记忆不串号；历史 unknown 与实测 false 不混淆；失败后仅读取/不同命令成功不晋升；中断或完成均不能单独证明收益。

- 验证：core/memory/app 定向 Rust 回归及迁移测试，UI runtime/i18n/lint/a11y 等相关检查。完整工作区验证、原生桌面验收与实际收益对照分别报告。

## 背景、选择与取舍

原路径中，当前事件写入 state.db，页面读旧 index.db；注入计数又被命名为 fetched 并用于排序及降级。这让数据增加而收益不可判定。修复选择继续使用现有 SQLite、Markdown 和生命周期门禁：新事件记录运行身份与读取事实，历史保留未知。没有采用按时间窗口猜测旧身份或补算历史读取的方案，以免并行运行串线。

恢复判定使用同一 episode 内相同工具与完整目标的失败后成功；相同文件的 read 成功不修复 edit 失败，另一条 bash 命令成功也不修复先前命令。后续同目标再次失败撤销该轮恢复。这个判据保守地验证操作恢复，不能证明记忆内容对恢复有因果贡献；跨工具修复与业务正确性留给独立评估。

### 实现与边界

- 调度器在本线未阻塞的在途任务中按工作优先模式稳定选择一项，其余列为 `queued_wip`。当前选择终态或阻塞后重新选择，不写入临时停车或依赖。人工停车、具名外部阻塞和其他线认领仍沿原判据处理。
- CLI 和桌面复用 harness 的逐步刷新上下文源，每次模型请求接收当前裁决与近期终态；不把旧裁决固定在 agent.system。`work next` 默认裁剪历史字段、队列和对账，`detail=true` 可取全量；`req/defect get` 不重复携带字段注册表。已归档条目的重复关闭返回 `ALREADY_TERMINAL`，不重新验收、不重复记成功。
- 前端冒烟命令归一化 Windows 路径并识别运行型 Node 调用；语法检查、echo、eval 不视作冒烟。提交级验证可读取 Git 注册工作树的同提交证据；当前源码/配置有变更或未跟踪文件、证据提交不符、所需检查未通过时拒绝复用。返回实际证据路径，保持条目关联要求。
- 记忆候选仍由 FTS/向量生成，在检索门面按显式符号与文件锚点筛选，再考虑标题、适用描述与正文覆盖。弱共词允许返回空；指纹命中和无词面交集的语义召回保留。自主轮预检索采用引擎当前选择，不再固定先取需求队列前两条。
- 自主轮 `question` 返回 `QUESTION_PENDING` 和结构化问题，随现有 ToolResult 持久化；实时工具卡及历史回放均可填入回复草稿。默认选项不构成答案，权限策略保持原判据。文档页显示阻塞条件并提供回复草稿入口；用户发送答复后由正常执行链复核解除条件。
- 本轮结束与任务完成分开。全部阻塞显示等待；只有 BacklogEmpty 使用完成样式，判定不依赖翻译后的文案。UIA 报告新增 `launch_mode`、`cold_start_verified`、`restart_verified`，复用用户窗口不能报冷启动或重启通过。
