## 1. 核心决定

**输入框属于工作台，始终跟当前项目、工作和操作对象在一起。**

保留全局多项目工作台，选中项目后进入一个持续工作的平面。上部看需求、批次和信号，操作台默认停靠下部，也可拖到正在看的内容附近。点记忆、agent 或工具，就进入该模块的管理与会话，输入框同步绑定它的负责人。管理与对话共用一处输入。

这替代 [workbench_first.md](workbench_first.md) 中“项目概览、工作、对话分别进入，输入仅存在于对话页”的交互建议；全局/项目边界、多项目自主推进、摘要减负、稳定刷新等约束继续有效。

全局未选择项目时没有含糊的“对所有 agent 说话”。点项目确定工作，点模块确定接收者；每个项目、模块、对象会话各自保存草稿。工作消息绑定发起者和具体问题，已输入的内容不会自动带给另一个对象。

**能由位置、连线、形态和状态表达的信息，不再重复写成说明文字。** 阅读注意力优先留给目标、问题、依据差异、失败原因和人的输入。对象名称与不确定的状态仍需短标签；图标保留可访问名称和悬停提示，不能把减字变成猜谜。

## 3. 上下文按作用分类，不按入口堆面板

| 类别 | 装什么 | 默认进入方式 | 用户能做什么 |
| --- | --- | --- | --- |
| 约束 | 系统规则、项目约定、显式偏好、执行范围 | 按作用域装配，显示来源和覆盖关系 | 查看；可编辑的项目偏好另存新版本；系统规则只读 |
| 工作 | 当前目标、验收、检查点、未解决决定、有效领取 | 当前 Work Unit 的有界摘要 | 纠偏、补充验收、关联工作 |
| 近期对话 | 近期用户要求与必要往返 | 保护最新明确指令，按轮次装配 | 查看原文；纠正形成新消息 |
| 召回记忆 | 符合范围和状态的 MD 片段 | 按需检索，不把全库都塞进请求 | 本次排除、请求核对、指定新版本、提交修订候选 |
| 工具证据 | 工具参数、返回片段、代码差异、可恢复产物 | 当前步骤所需；大结果外置且保留引用 | 展开原始结果、定位来源、再次取证 |
| 协作交接 | 子任务目标、边界、证据、结论、未完成项 | 显式交接包，经主执行选择后进入上下文 | 查看接收方、核对来源、补充或重派 |
| 折叠历史 | 压缩纪要、原始事件区间、恢复定位 | 摘要在活跃层；原文在归档层按需取回 | 查看摘要与原文对应关系、召回特定片段 |

每项同时显示两种不同状态：**文件生命周期**（候选/影子/有效/废弃/无效）与**本步装配状态**（候选/已纳入/未纳入/已折叠/待下次请求）。不能因为文件有效就称它正在被本轮使用。

“固定”只表示提高后续装配优先级，不承诺突破预算。预算容不下必须显示未纳入原因，不能静默截掉固定项。旧请求保存旧清单；修改只影响之后实际发出的请求。

## 4. MD 的流动是什么

MD 继续是可编辑外部知识的真源。运行事件、工具产物和配置保留现有存储职责：`state.db` 的事件账本、文件产物、`kanzei.toml` 不为统一外观强行转成 MD。

流动图是已有事实的可重建视图，不引入新的知识图谱数据库。节点身份至少包含项目、稳定对象 ID、版本/内容哈希；移动文件保留身份，新内容产生新版本。边指向具体版本和片段，不只指文件路径。

| 边的名称 | 所需证据 | 不能推断为 |
| --- | --- | --- |
| 检索到 | recall 候选/返回记录 | 已进入模型上下文 |
| 已装入 | 最终请求清单及片段字节/估算 token | 被理解、被采纳 |
| 工具已返回正文 | 成功 read 调用、范围、版本 | 全文阅读或有效采用 |
| 决定引用 | 决策/检查点显式引用该版本 | 对决定有真实因果贡献 |
| 派发/交回 | 父子 run 身份与交接包 | 子代理继承所有父上下文 |
| 写入/修订 | 成功落盘后的版本差异与作者事件 | 模型说“已保存”就算写入 |
| 压缩/召回 | 原文区间、摘要版本与实际重新装入记录 | 隐藏/展开界面就改变了模型上下文 |

不画模型内部思维，不根据两个事件的时间接近就连因果线。缺失的历史字段显示未知。

## 5. 记忆调用与演化

主执行维持轻量调用：检索候选 → 读取片段 → 引用版本；新经验经 `memory_note` 提交管理者。管理者复用现有 ADD/UPDATE/MERGE/NOOP、来源门禁和生命周期，不增加“一键自动相信”路径。

用户在操作台可做三种清楚的事：

1. **本次排除**：只改当前工作的后续请求装配；保留磁盘内容和历史引用。
2. **按新版继续**：重读目标版本，在下个请求边界替换；在途请求标明仍使用旧版。
3. **修订记忆**：编辑建议、原因和适用范围，形成新版本候选；历史保持可回看，晋升仍走原有来源校验。

初始作用域是“当前工作”。只有明确选择项目范围才保存项目偏好；不恢复已经废弃的 global MemoryStore。全局运行默认仍归配置，跨项目知识共享需显式导入并保留来源。

热度分别显示检索数、装入数、工具读取数及观察时间窗。高频不等于可信，零次读取不等于无用。没有可靠观测时写“未知”，不显示“死记忆”。频繁修订仅是复查信号。

## 6. 冲突先做可证实的结构问题

优先识别：已被替代/已废弃版本仍进入新请求、来源缺失、引用失效、同一个已明确唯一的决策键在同范围和有效期内指向不同有效值、装入之后文件又改变。

正常分支、不同项目范围、不同有效时间不是冲突。“意思好像不一致”只标待核对，附具体句子与来源。不能凭语言模型相似度自动废弃另一份 MD。

默认只把影响当前工作的异常提到操作台；不让某个项目的异常阻塞其他项目。

## 7. 工具调用变成有依据、可定位的动作

工作面上的工具行先回答：**谁，为了什么，正在对什么做什么，结果怎样。** 点开后才显示完整参数、输出、错误码和产物。

每次调用关联发起请求、agent/run、输入清单和显式证据引用。工具能力列表按读取/修改/执行等实际能力展示；记忆检索只是调用中的一种，不做第二套操作方式。

运行前可调整待执行计划；运行中提供运行器实际支持的取消/暂停动作；完成后只能查看、重新调用或提出纠正，不能编辑历史参数假装过去执行不同。重新调用会生成新 ID 和 `retry_of`，写操作不能因断线重放自动重复。

“为什么调用”来自明确记录的计划或目的说明。没有记录时直接显示“未记录”，不能用后端猜测补成事实。

## 8. 工作台布局与输入语义

```text
项目 / 工作消息   所属需求 · 当前批次 · 阶段 · 运行状态 / 等待原因
                 ┌──────────────────────────────────────┐
                 │ 工作网络 / 对话 / 回放                 │
                 │ 来源 → 当前执行 → 工具 → 产物          │
                 │ 点击模块：管理 / 与该负责人对话        │
                 └──────────────────────────────────────┘
                 当前项目 / 接收者               [悬浮]
                 [对象版本引用，仅在关联对象时出现]
                 ┌──────────────────────────────────────┐
                 │ 给当前模块发消息 / 回复具体工作消息…    │
                 │ [上下文] [模型/设置] 范围          ↑    │
                 └──────────────────────────────────────┘
                 [执行设置展开后显示，不常驻解释]
```

常驻操作台包括接收者、对象引用、上下文入口、输入、最小执行设置；对象引用只在有具体关联时出现。接收者仅在标题显示一次，发送键使用通用箭头，完整目标仍在其可访问名称与提示中。大段正文在上部工作面展开，不把输入框挤出窗口。停靠与悬浮使用同一个 composer DOM、同一份会话状态，不复制第二个聊天窗口。悬浮标题栏可拖动，也支持方向键移动；位置限制在视口内，始终可一键停靠。默认悬浮位留出底部空间，不盖住图中的节点与待回复问题。缩到窄屏时恢复停靠，保留草稿与接收者。

**明确点击模块就是选择该模块的接收者。** 这是用户本次要求对前稿“只改引用、仍发主执行”的替代：点记忆进入记忆管理，点工具进入工具管理，点子任务进入该子代理会话。模块页面标题、输入框接收者、引用对象与发送按钮一同更新；发送快照绑定当时的项目、工作、负责人、会话和对象版本。后台事件、通知和迟到响应不能改接收者。

管理 agent 按需承担角色，不为每个 MD 常驻启动一个模型；工具本身没有对话人格，工具管理者负责安排后续调用。给已结束子任务发消息时明确显示“续聊这个子任务”；接入失败就保留消息并显示原因，不能偷偷改发主执行。管理对话不会自动扩大权限或改写有效记忆，仍需产生有归属、版本和回执的动作。

输入即将发送的原文；快捷选项先填入输入框，可修改后发送。有草稿时追加选项，不覆盖已输入内容。草稿按 `project / work / module / actor / conversation / object` 隔离，工作消息再加入 `interaction_id`。发送后显示排队/已送达/已应用；接收方确认与实际动作成功分别留证，不能把“点击发送”显示成已处理。

当前批次固定展示：所属需求 ID、名称与需求状态；批次 ID、名称和实施/验证/提交回写阶段；当前执行者的运行、等待或暂停状态及原因；最近持久检查点与交付版本。需求状态与运行状态分别呈现，“第 2 / 5 批”不冒充需求完成率。点需求可改目标与验收，点批次可看范围、检查与交付。

内容深度分为项目入口、项目工作台、模块管理、具体依据四层。打开依据固定当时版本，保留当前接收者和草稿；返回恢复上一级入口。深入依据时压缩顶部概况，为原文留出空间。辅助面板沿进入顺序返回，不能统一退回首页而丢失查看位置。

运行中默认“下次请求送达”。暂停当前工具、停止整条线、下一轮不再继续分别命名，不能混成一个停止键。回放时仍可看历史，但发新指令必须返回当前状态，避免把旧执行误当当前。

设置分三层：输入旁显示当前有效模型与偏离默认的限制，例如“只读”；展开查看工具范围、子代理与当前工作的覆盖；项目默认和全局默认进入次级设置。覆盖来源与生效时点在展开处说明，保存反馈按需出现。已经发送的模型请求不热换模型。

### 工作消息：把需要人接话的事情统一起来

提问、待复核决定、需要人介入的阻塞、交付反馈使用同一个收件箱。每条都带项目/需求/批次、发起 agent、原问题、可选回答、版本、影响范围及“是否正在等待你”。点击消息后，当前 composer 变成对这条消息的回复框。处理后可回到刚才的模块与草稿。

新消息用非模态小窗提示，不抢焦点，不阻止继续看图或输入；关闭提示只收起小窗，事项仍在收件箱。打开/已读不等于处理。状态顺序为：`待回复 → 已回复、等待处理 → 已处理`；失败或过期另行展示并保留原回复，重复发送用幂等键去重。

页面打开时，已有事项通过收件箱计数和就地问题入口呈现，不重新弹一遍“新消息”。失败与阻塞事项优先；首页只露出当前工作最需要接话的一项，窄屏放到图前。其余事项留在收件箱，避免同时展示多个问题争抢输入。

事项处理完成后取消已经解除的等待提示，输入区收起成处理状态与“返回工作”。点击后恢复进入消息前的项目、模块、依据层级和草稿；后台自动回执不能替用户返回或切换目标。

自主决策可先实施再供复核，普通复核不阻塞整个系统。确实缺少信息的提问只暂停依赖它的步骤，例如验证目标未定时等待本批验证，其他无依赖工作继续。只有用户明确要求或存在全局依赖，才停下更大范围。

## 9. 默认安静，需要时放大

- 延续暖白底、灰绿结构与少量橙色提醒。主执行作为中心，依据在左，工具与产物在右，子任务靠近所属执行者；不再把所有模块做成同样大的说明卡片。
- 阶段用连续轨道表达；版本差异在管理页并排比较；工具参数默认折叠。首页保留名称、必要版本、等待原因，长解释移到点击后的详情。
- 默认显示当前工作、直接关联的记忆/工具、在途 agent 和异常；正常历史合并成计数。
- 悬停或键盘聚焦只高亮一跳关系，不切换收件人；明确点击才进入管理与会话，返回后恢复原节点焦点。追溯时才增加更长路径。
- 保留原位和选择，后台增量只更新有变化的对象；不重建输入、不抢焦点、不重播整页入场。
- 正在运行的模块缓慢呼吸，等用户时保持琥珀色和原因，完成/暂停后静止。呼吸表达运行状态，不表达取得成果。读写/工具结果等实际事件才沿连线出现一次方向脉冲；没有事件就不循环伪造流动。
- 窄屏先显示待回复事项，再将执行者与依据/行动分组堆叠，操作台继续可达；不把桌面图等比缩小到不可读。输入旁的主要点击目标至少为 44px。
- 键盘可选择对象、展开依据、移动悬浮框和发消息；状态同时有形状/图标及可访问名称，需人判断的等待/失败保留短文字。减少动画设置关闭呼吸和过渡，隐藏页面暂停动画。运行器继续独立工作。

## 10. 接线契约

以下名称是建议契约，不宣称现有代码已经定义。

`ContextManifest`：`project_id, work_id, session_id, run_id, agent_id, request_id, revision, created_at, model, budget, items[]`。每项含类别、角色、来源 ID、来源版本/哈希、片段范围、纳入状态、理由、估算 token 与计量方式。凭最终 provider 请求确认实际纳入，区分缓存统计和上下文长度。

`SignalEvent` 是现有 typed events 的投影：`event_id, project_id, run_id, request_id?, agent_id, sequence, occurred_at, kind, source_ref?, target_ref?, tool_call_id?, evidence_ref?, observation_level`。已有字段复用，缺字段用新增兼容版本；历史保留 unknown。投影自身不是第二份事件真源。

`Intervention`：目标工作/agent/对象版本、作用范围、用户内容、幂等键、预期 revision、生效边界和 `queued / delivered / applied / failed` 回执。`applied` 必须关联实际新请求或成功文件版本；重复提交返回同一结果。版本变化要求展示变化后再提交，防止旧表单覆盖新版。

`ConversationTarget`：`project_id, requirement_id?, work_id, batch_id?, module_id, actor_id, conversation_id, object_ref?, object_revision?`。显式点击原子切换整个目标；发送和草稿保存冻结这份绑定，跨项目响应以目标与请求代次校验。管理 agent 上下文必须展示自己的 manifest；关联主执行的请求清单注明归属，不能伪装成管理者已收到的内容。

`InteractionRequest`：`interaction_id, kind, origin_event_id, project_id, work_id, batch_id?, run_id, actor_id, conversation_id, object_ref?, revision, body, choices[], blocking_scope, status, dedupe_key, created_at`。读取时间、回复 ID、期望问题版本和接收回执分别记录。回复关联原问题，乱序/重放消息以 ID 和 revision 归并；旧回复不得覆盖更新后的问题。

工作消息与模块会话复用同一发送链路。`received` 只说明系统收到了回复，`delivered` 说明发起者请求实际获得回复，`resolved` 由发起者确认该问题已处理。若产生记忆修订、工具派发或批次变更，再关联该动作自己的结果；不能用模型说“收到”代替行动证据。

多 agent 使用独立请求清单，交接只共享明确列出的事实与产物。共享 MD 修订用版本比较和原子写；读到旧版的运行只标注受影响，并在后续边界重读，不伪造过去已经更新。切项目使用请求代次防止迟到响应串到新项目。

压缩保留 before/after 清单、受影响事件区间、纪要文件与可恢复引用。召回明确选择片段、估算成本和进入哪次请求。原文丢失就显示不可恢复，不能用再次生成摘要替代原始证据。

## 11. 实施顺序与验收

| 步骤 | 范围 | 完成标准 |
| --- | --- | --- |
| 1 操作台靠拢 | 共享 composer、模块会话绑定、停靠/悬浮、批次需求与运行条、工作消息收件箱 | 模块/消息与收件人一致；新通知不抢焦点；切换按目标保留草稿；所有模块可键盘进入 |
| 2 请求清单 | 装配端记录请求级 manifest；UI 展示来源、版本、范围与纳入原因 | 从一次工具调用追到具体请求和 MD 片段；旧请求不被新版本改写 |
| 3 定向干预 | 本次排除、新版重读、作用域设置和回执 | 只在所选工作/后续请求生效；在途请求清楚显示旧版；重复点击不重复执行 |
| 4 长期运行 | 压缩/交接溯源、结构异常、局部回放与摘要投影 | 两项目/多 agent 不串归属；恢复不重放副作用；隐藏视图不持续渲染 |

定向验收覆盖：候选被检索但未装入、局部读取、未知历史、两条线引用同一 MD 不同版本、运行中修订、压缩后召回、丢失原文、失败/重复干预、中文输入时后台更新、项目/模块/消息切换、旧问题版本回复、异步来信、悬浮移动与视口限制、窄屏和回放。图的热度或呼吸不作为记忆收益或交付验收。
