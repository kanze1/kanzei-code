# 波次质量审计 SOP(手动触发)

- 状态: 生效(2026-08-16 用户批准;触发方式经用户定调为**手动**,不定时、不挂门禁)
- 来源: 2026-08-16 对 38 提交/+7231 行波次的三路只读审计——几十万 token 换 17 条真缺陷(D-385~D-401,含 2 条 P0),把该实践固化为可重复流程
- 定位: 五件套质量体系的「发现」环。配套机制——close 验收条款对账门禁(`tracker/actions.rs::check_close_acceptance_reconciliation`,防沉默降级)、可重放证据规范(conventions §1.25)、链路收口条目(§1.28)、机制原子上线(§2)。门禁防**沉默**,审计查**真伪**——语法门禁不判语义,本仓一贯口径。

## 1. 触发

- **用户手动发起**(对 Claude/外部 agent 说"跑波次审计"即可),不进 cron、不挂关闭门禁。
- 建议时机:一波密集交付(≥10 提交)后;发版前;或某条链交付后准备核销上游条目前。

## 2. 审计员纪律(硬约束)

1. **只读**:不改任何文件,不 `cargo build/test`——并行自举线可能正在构建,互踩;静态读码+读测试代码+读 tracker/测试记录即可。
2. **以已提交 HEAD 为准**(`git show HEAD:<path>`);工作树未提交改动只标注"进行中"不下结论。
3. **怀疑姿态按四模式清单展开**(见 §4),不泛读;每条指控给 file:line 证据。
4. **登记前当场核验**:汇总方对最重的指控逐条复查(grep/read 原文),证实后才 `defect add`;只列真问题,不凑数。
5. 产物按修复单元拆条目,severity 按后果定(数据丢失/并发绞杀=P0;产品链路断=P0/P1;假绿/文案假承诺=P1/P2)。

## 3. 派发形态(三路并行只读子代理,按波次内容切分)

按交付内容分三路(示例切法,按波次调整):

- **A 路·功能链**:某条新交付的产品链(如移动链)。核对每个端点/UI 的**完整调用链**——从用户入口到效果,找"注册了没人调、写入了没人读、闸门顺序错"。
- **B 路·工具/引擎**:新交付的工具通道。核对工具描述承诺 vs 实现、错误路径、回退轨、权限边界、辅进程生命周期。
- **C 路·基建/不变式**:围栏、快照、日志类机制。核对不变式声明 vs 实现、并发场景(与其它线互动)、覆盖面(所有写者/消费方都接了吗)、性能声明有无实测。

每路提示词必备要素:审计对象提交号清单;"本仓历史失败模式"背景(给怀疑方向);逐项核对清单;输出格式=每项结论(实/虚/部分/降级)+file:line+按严重度排序的缺陷清单。

## 4. 四种失败模式清单(逐波必查;2026-08-16 波次实证)

1. **最后一公里不接线**:命令注册了 UI 不调;事件落库无消费方(死信);serve 排在鉴权闸后;参数有了调用方不传。→ 查法:对每个"新能力"找完整调用链,grep 消费方计数。
2. **证据替身**:自检打临时服务器冒充真链路(查测试记录/轨迹里的**真实地址与端口**);测试断言文案副本而非生产分支;假脚本替代真二进制。→ 查法:test_record 的 command/目标 与被测系统比对;测试代码里找硬编码复制的生产文案。
3. **注释假承诺**:注释/工具描述承诺的机制(粗筛/收尾/落盘)实现里不存在。→ 查法:读模块头注释逐条到实现里找对应物。
4. **沉默降级**:交付形态低于验收原文(静态扫描替代运行时遍历、窗口开点替代合法日志终态),关闭证据不点名落差。→ 查法:验收原文逐条 vs 实现形态 vs 关闭叙述三方对照。(close 对账门禁已拦"条款不覆盖";这里查的是"覆盖了但内容不实"。)

## 5. 汇总与登记

1. 汇总方先取宏观数字定基调:`git diff --shortstat <base>..HEAD`、新增测试数(`grep -c '#\[test\]'` diff)、测试记录数。
2. 对各路最重指控当场核验(§2.4)。
3. `defect add` 逐条登记:标题≤40 字,字段带 根因(file:line)/影响(对到验收条款)/期望(修复方向);来源统一写"波次质量审计+日期";refs 挂被审条目。
4. 若发现"虚假完成已向上游传播"(如核销依据失效),同轮撤回:更新上游条目阻塞字段并点名缺陷号。
5. 提交纪律:并发线活跃时一律 `git commit -m "..." -- <明确路径>` pathspec 限定(共享暂存区会卷走别线预暂存文件,实证见 2026-08-16 记忆)。

## 6. 成本与预期

2026-08-16 首次运行实测:3 个只读子代理约 39 万 token、每路 7~12 分钟,产出 17 条经核验缺陷(2×P0、6×P1)。判定基调参考:**内核与单测大多是真的,断裂集中在集成层与验收纪律**——审计火力应压在链路与证据上,不必逐行重读内核逻辑。
