## 0. 核心决定（一句话）

**agent 身份（代号 + 颜色）提升为贯穿全 UI 的第一等标识。**

> 2026-08-11 发布范围说明：当前产品已在多线页交付 M/A/B 代号与确定颜色、真实协作快照、六要素并列状态、文件交集冲突下钻、合并前预检与“语义层未检查”常驻提示，并通过 800/1024/1280 浏览器布局检查。P2 活动记录按 agent 折叠（批3）、P5 收活五格（批4/批5）、P6 设置按 agent 并顺带关闭 D-246/D-247/D-248（批6）均已随 R-184 上线；P7 耦合预检依赖 R-185，继续推进。

它不是并行视图里的一个局部概念，而是同一个标识出现在**五处**：backlog 列表标「谁取了」、主对话页签标「切到谁」、活动记录标「谁干的」、并行视图的泳道、设置里「谁用什么模型」。

这个决定的直接后果是：几件本来各自孤立的待办，塌缩成同一件事的推论（§6）。

## 1. 取活标记：从「推断」改成「事实」

### 1.1 删掉「下一个」

现状 `ui/12-docs-pages.js:434` 把「下一个」定义为**取活序里第一个可开工的 open/todo**——这是一个**推断值**。

两条理由，第二条是根本的：

1. **任务级并行下它不成立**：N 条线同时取活，没有单一的"下一个"。
2. **它本来就是推断，而 D-207 的病根正是界面在展示推断值**。D-207「取活顺序所见非所得」说的就是视图排序与优先级徽章都不参与真实取活。再加一个推断出来的高亮，只是让所见非所得多一处。

删除面：`ui/11-docs-list.js:341` 的 `isAgentNext` 分支、`ui/12-docs-pages.js:434/638/646` 的「下一个」计算与渲染、`ui/style.css:158` 的次亮样式、`ui/02-i18n.js` 的两条文案。

### 1.2 只标「被取得」

**被取得是事实，不是推断**：哪条线、什么时刻、拿了哪一条，是确定的、可审计的。

条目上的标记形态：`● A` —— 一个 agent 色圆点 + 代号，`title` 给「A 于 04:16 取得，分支 par/d-262」。同一条目同一时刻只可能有一个取得者（一条线一条目）。

**「在做」的呼吸高亮保留**（现状 `ui/11-docs-list.js:335`），但含义收窄为"该条目正被某条线持有"，并染上该 agent 的颜色。

## 2. agent 身份的定义

### 2.1 代号

- **短、可读、批内唯一**：`A` `B` `C` `D`…
- **唯一键是 `代号@批次`**，显示只显示代号。这正是 R-174 遗留的第 (b) 条形态决策要的东西——它记着「前端条目 id 就是角色名，而角色跨轮复用，所以当前实现每角色只留最新一轮；要保住历史轮次得让后端给 `role@round` 之类的唯一键」。**agent 身份就是那个唯一键**，不用再单独设计一套。
- 批次 = 一次并行派发。跨批复用代号是允许的，批是天然边界。

### 2.2 颜色

- 固定调色板，按代号确定性映射（`A`→色1，`B`→色2…），**不随机、不轮转**——同一批里刷新页面颜色不能变。
- **必须过对比度门禁**（仓库已有 `scripts/ui-a11y-smoke.mjs`）。
- **代号是主标识，颜色是辅助**。任何地方都不得**只靠颜色**区分 agent——色觉障碍用户会完全失去区分能力。这条要有断言锁死：移除代号文本后 a11y 冒烟判红。

### 3.4 并行视图（新增第 9 个主视图 `data-view="lines"`）

**为什么是主视图而不是面板**：并列看 N 条线要横向空间。现有三处各管一层、互不替代——线页签是**单线**视角、活动面板是**线内**视角、侧栏 `#worktrees-section` 是**静态清单**。本视图是**跨线**视角。侧栏工作树区块改为本视图的入口，不并存两套。

**考虑过并否决**：塞进 `workspace` 视图。它的定位是"统一查看项目、对话、运行状态"——那是**纵览**；并行视图是**操作台**（要开线、停线、合并）。混在一起两边都变钝。

```
├─ 泳道区 ────────────────────────────────────────────┤
│ ●A D-262 kill_tree     par/d-262   跑着 · bash      │
│ ●B D-261 原子写并轨    par/d-261r  跑着 · cargo     │
│ ●C D-233 文件视图卡顿  par/d-233   完成 ✓           │
├─ 冲突带 ────────────────────────────────────────────┤
│ ⚠ B ✕ C  共同改动 kanzei-tools/src/files.rs         │
│ 文本层已检查 · 语义层未检查（需人读 diff）          │
└─────────────────────────────────────────────────────┘
```

## 4. 泳道卡片与状态机

### 4.1 字段

**直接照搬当晚实际用过并验证有效的那套**（外部脚手架的 `status.ps1`），不多不少：

| 字段 | 数据源 | 为什么必须有 |
|---|---|---|
| `● 代号` + 认领条目 | 开线时绑定 | 一屏答"谁在干哪件事" |
| 分支 / worktree | `git worktree list --porcelain`（R-177 内容③已定为真源） | 收活时要用 |
| 状态 | 见 §4.2 | |
| **当前工具名** | `ToolStart` 实时 | **当晚最想要而没有的字段**——它是"卡住 vs 在长构建"的唯一判据 |
| 轮数 / 已改文件数 / token / 耗时 | `RunEvent` + `episodes` + `git diff --name-only` | 已改文件数同时是冲突带的输入 |
| 单条停止 | 与 R-174 已备的 per-role `CancellationToken` 同源 | 一条跑偏不该停整批 |

展开后三个页签：**transcript**（复用 R-174）、**diff**（复用 `06-activity.js` 的 `buildDiffTree`/`renderDiff`，R-133 已 done）、**报告**。

### 4.2 状态机与判据顺序

```
起线 → 跑着 → 完成 ✓
           ↘ 失败 ✗
           ↘ 疑似卡住 ⏳（可回到"跑着"）
```

判据顺序**必须**是：①`ProcessHandle` 活性 → ②最近 `RunEvent` 时刻 → ③worktree 源码 mtime。

**不得只用"多久没动"判死。** 当晚正是这个误判让操作员把一条**活着的**线当成死的、去动了它的工作树——线在报告里当场抓到了这次越权提交（D-263 的形状真实重演）。「疑似卡住」只是**提示**，不触发任何自动处置。

> kanzei 在这里天然优于外部脚手架：它拥有 runner，`RunEvent` 是实时流。当晚 `claude -p` 的输出全程缓冲，一条线在日志 **0 字节**时已经提交了代码并继续跑了 40 分钟。这个坑在 kanzei 里不存在。

### 4.3 冲突带

**算法（第一版就这么简单）**：每条线的改动集 = `git diff --name-only <merge-base>...<branch>` ∪ 未提交的 `git status --porcelain`；两两求交；非空即告警。

**为什么不用 `merge-tree` 两两预检**：N 条线是 N² 次，且它回答的是"合并会不会冲突"——太晚。文件集求交回答的是"**现在**是不是在往同一个文件写"。`merge-tree` 留给收活流程里真正要合的那一次。

**告警必须早于任何合并动作**。点开下钻到"哪两条线 / 哪些文件"。

### 4.4 诚实：语义层不假装

冲突带旁常驻 **「文本层已检查 · 语义层未检查」**，不可关闭，**冲突带为空时照样显示**。

理由：git 只做文本层。A 把某签名重构成形态①、B 按形态②写完，两边测试各自都绿，合并干净，**语义已经坏了**。R-182 已明确不做语义撞车的事后检测。界面**不得**让"没告警"读起来像"可以安心合并"。

## 5. 收活流程：把当晚的五步固化成五格

```
① 读报告  →  ② 人读 diff  →  ③ 跑门禁  →  ④ 合并  →  ⑤ 回写 tracker
   （人）    （人·必须显式确认） （kanzei）  （kanzei）   （kanzei）
```

- **②不可跳过、不可自动**：必须点一次"我已读过 diff"才能进③。这是语义层唯一的防线，做成必经的一格而不是提示。
- **③门禁由 kanzei 跑**：fmt / clippy / test / 前端冒烟。当晚实测**不能信线自己说的绿**——一条线交付时没跑 `cargo fmt`，三处违规是操作员跑门禁才发现的。
- **④合并**用现成的 `worktree_merge`（含 `merge-tree --write-tree` 预检），保持 `--no-ff`（N2 定案）。合并后**再跑一次全量**：两条线各自绿 ≠ 合起来绿。
- **⑤回写 tracker** 走 tracker 工具落**主根**一份，标记里带取得者代号。线全程不碰 `.kanzei/**`——当晚实测两个 worktree 相隔 10 秒各登记一条缺陷，**都拿到 `D-267`**，因为它们锁的是两个不同的文件。验收未全达成的必须保持 `open` 并写清哪条没成。

## 10. 验收（并入 R-184）

R-184 既有验收之外补五条：

1. **代号与颜色**：同一批内代号唯一、颜色确定性映射（刷新不变）；调色板过对比度门禁；**移除代号文本后 a11y 冒烟判红**（锁死"不得只靠颜色区分"）。
2. **「下一个」彻底消失**：全仓 grep `isAgentNext` / 「下一个会拿」零命中；`computeAgentFocus` 不再产出该值；相关 i18n 键删除。
3. **「被取得」是事实不是推断**：标记只在真有线持有该条目时出现，有反证测试（构造"排在队首但无人取"的条目，断言**不**出现标记）。
4. **状态机三级判据有反证**：构造"进程活着但事件长时间不动"，界面显示「疑似卡住」且**不**触发任何自动处置；构造"进程已退出但无终态"，显示为失败而非卡住。
5. **收活②不可绕过**：未点"已读 diff"时③④⑤全部不可达，有冒烟断言；断言被删则测试变红。**「语义层未检查」提示在冲突带为空时同样显示**，有断言。
