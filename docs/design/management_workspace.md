## 要解决的问题

让人回到项目后能理解：目标是什么、目前依据什么判断、还缺什么、可以推进哪一步、结果究竟证明了什么。台账、图和运行状态服务这个判断，不要求用户先拼接多套分类。

人掌握意图和取舍，Agent 承担已有授权内的调查与执行。事实、解释、建议、问题和决定分别表达；未决问题不自动形成必须等待用户的审批。界面不静默启动工作或更换执行收件人。

## 四个入口

| 入口 | 默认内容与动作 |
| --- | --- |
| 总览 | 关注目标、确认过的变化、当前差距和可推进动作；每项可进入来源 |
| 目标 | 目标条件、当前理解、方案、行动、证据与历史；按需切换大纲/关系 |
| 成果 | 实际产物、关联目标、适用版本、验证范围与反馈 |
| 项目 | 模块、约束、知识、文件与运行依据；消费 ProjectKnowledge，不另造状态源 |

旧需求/缺陷入口定位到“目标 → 全部登记记录”，旧标识、正文、编辑和归档能力保留。大纲与关系共用选择、详情和动作，避免两套地图推导两份状态。局部默认展示一跳邻域，完整图显式进入。

## 语义与所有权

目标描述期望结果和成立条件；理解记录解释、问题与方案，并带来源和修订。工作代表有边界的行动，成果代表实际产物，证据必须说明它支持什么条件及在哪个版本成立。自然语言解释不拥有调度或验收权力。

父子、依赖、覆盖与支持是不同关系；子项全部结束不能自动接受父目标。关注偏好、项目阶段和执行选择分开保存，浏览范围不能成为执行范围。

复用现有 Work Unit、tracker、决定与复核服务、ProjectKnowledge 和领域事件。新持久事实由其能力所有者提供，tools 提供只读组合投影，app 适配 IPC 与呈现，前端不解析自由文本伪造结构化论证。

必须保留三个实际边界：

1. Work Unit 的 `requirement_id` 接受 R 标识；缺陷可统一显示，但不能伪装成已存在的递归执行对象。
2. `source_sequence` 是事件并发版本。规范修订、执行、代码和引用的版本分别绑定，不能一列代替所有证据适用性。
3. Markdown、SQLite、文件与运行数据不共享一次原子读取。查询暴露来源版本、局部失败及过期情况；缓存可重建，不成为第二真源。

## 读取、更新与布局

先展示权威事实，再按需提供带来源的解释。缺失、等待、过时、冲突与失败分别呈现；不能用一段流畅总结覆盖未知。综合解释绑定输入修订，输入失效后标待更新。

使用一个主要阅读滚动区域和按需依据栏。标题及关键结论有足够宽度；窄屏进入可返回的独立详情。图提供空间关系，文字表达判断；状态不能只靠颜色。布局延续现有品牌及 surface/frame，不增加前端框架。

登记、修改和推进分别给出清楚的提交回执；维护草稿，拒绝覆盖并发修改。迟到响应核对项目与对象身份，刷新保持选择及上下文。执行动作再次验证目标版本、归属与授权；停止使用已有运行控制。键盘、焦点、减少动态效果与长标题均属于同一交互合同。

## 实施顺序

1. 明确事实、解释、版本和只读查询合同，审计既有 `docs_snapshot` 归档副作用；查询不代替显式生命周期写入。
2. 打通一个目标的纵向链路：目标 → 理解/缺口 → 行动 → 产物和证据 → 整体验收；兼容没有 Work Unit 的旧记录。
3. 合并两种地图的投影、详情与动作；验证替代路径后移除重复呈现。
4. 用真实来源形成项目总览，再接入有修订和失效规则的综合解释。
5. 联通成果、项目知识和反馈；按真实依赖拆分工作，不把顺序强制变成串行任务链。

## 验收标准

| 场景 | 必须成立 |
| --- | --- |
| 离开后返回、新目标仍模糊 | 能识别目标、已确认变化、缺口与下一实际行动；保留原话，不伪造完整计划 |
| 多个目标共享研究 | 同一成果可服务多目标，适用范围分别检验 |
| 子项结束、整体验收缺失 | 明确显示缺失组合证据，不显示自动 100% 完成 |
| 方向变化、证据过期或冲突 | 保留变化理由与旧记录，识别受影响范围，当前行动绑定有效版本 |
| 无需用户决定的未决问题 | Agent 在既有授权下继续调查，不新增审批负担 |
| 无可行动工作或执行停止 | 解释等待前提和恢复入口，不自动重跑或虚构任务 |
| 旧记录、跨项目和并发刷新 | 标识与历史可追溯，不丢记录、不覆盖草稿、不转移执行归属 |
| 宽窄布局与键盘 | 顺序阅读、定位依据、返回上下文，焦点与选择保持正确 |

验收同时覆盖领域迁移、接口、浏览器合同及真实操作；已有管理页测试不能证明本方案已交付。产品效果用同一组有标准事实答案的场景比较正确率、遗漏、找依据耗时和错误行动，分别记录改善与反例。
