# 前端三期:能力差距全面分析(2026-08-06)

背景:后端能力(多轮调度、子代理、持久化、双模式、权限体系)已明显跑在前端前面。
本文盘点"后端有、前端没有/没跟上"的全部差距,按用户的好用定义排序:
①memory/上下文精准透明 ②方便多 agent 协作 ③快和流畅 ④少打断 ⑤信息清晰。

## 一、后端能力 vs 前端呈现矩阵

| 后端能力 | 前端现状 | 差距 |
|---|---|---|
| steer/queue 双投递 + 队列取消 | 有 delivery 下拉 + 停止取消 | **队列不可见**:排了几条、内容是什么、不能单条撤销 |
| task 并行子代理 + 实时进度 | 块内进度行 + 后台面板 | **轨迹不可回看**:只见结果摘要,子代理内部做了什么(哪些 grep/read)无法展开;后台面板条目 6s 即逝 |
| SessionStore 事件溯源/会话恢复 | 历史对话列表(R-013 进行中) | 回放/继续的交互还在建设 |
| 自动压缩 + 手动总结 | 一条 notice | **纪要不可见**:压缩后模型看到什么无处查看,违背"上下文透明" |
| 权限规则持久化(always-allow) | 无 | R-025:看不到记住了什么,只能手改 toml |
| research 模式(sources/findings 强制引用) | **完全没有 UI** | 侧边栏只有 dev 模式文档;research 的来源/发现列表、引用关系无呈现 |
| 多模态协议(image/document) | 无上传入口 | R-014/R-024 |
| git 集成 | 状态栏一行 | 无提交列表;agent 现在会自动提交,"它提交了什么"要去终端看 |
| 上下文占用计量 | 状态栏百分比 | 无成分拆解(system/工具/历史各占多少) |
| 多进程并行(R-030 设计完) | 单运行位 | 见 r030-process-decoupling.md |

## 二、纯前端易用性债务

1. **强制滚底**:每个事件都 scrollBottom,翻历史时被拽走——需要"在底部才跟随"的智能滚动 + 「回到最新」按钮(④少打断,最高频痛点)
2. 消息不可一键复制;对话内无搜索
3. 权限弹窗一次只显示一个,多 ask 排队时无队列感
4. 连跑控制粗糙:上限 10 写死、无暂停、无"跑完这轮就停"
5. 输入框:无提示词历史、无草稿保存(R-024)
6. diff:无语法高亮、无并排、多文件改动无汇总视图
7. 无键盘快捷键体系(切进程/停止/新对话)
8. 错误一律全屏红条,不区分可重试/致命

  - 历史回放已完成:运行轨迹写入 run.trace 事件,历史会话加载时按对话分段恢复右侧 task/子工具轨迹。

- 既有关联:R-013(会话回放,agent 进行中)、R-018(完成提示音)、R-024(输入体验)、R-025(权限规则管理)、R-016(自更新)
