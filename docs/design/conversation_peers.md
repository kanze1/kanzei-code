# 对话统一模型（2026-10-03）

项目内与无项目对话使用相同的登记、改名、运行、关闭、删除和恢复规则。没有主对话身份，也没有第一条对话的保留权、默认执行权或权限特例。

- 新对话都通过 process_create 登记，默认 dev；readonly/research 是显式运行模式，worktree 是工作区配置。
- IPC 不再返回 authority；kind 由 profile 决定，不由身份前缀决定。发送任务必须指定对话，缺少目标时不猜第一条。
- 关闭任何对话均注销登记并保留历史；删除任何对话均删除对应历史；已注销的身份不复用。列表查询不补建对话，迟到的队列查询和清空请求不能复活已删除身份。
- 后台验证保存发起者 session_id，结果只投递给该对话。旧任务只有能唯一识别归属时才恢复投递。
- 侧栏项目整行点击切换展开/收起，状态刷新保持折叠选择；项目和无项目使用同一标题和菜单规则。

## 升级与回退

不改变 SQLite 表结构。旧版 d|project 对话曾只有基准 session 记录，首次恢复时将其补登记为普通对话；已退休身份跳过补登记。保留原 ID、session_id、标题、消息和附件引用。d 前缀仅用于解析历史存储位置，不参与权限或生命周期判定。

旧版已有 readonly 对话继续保留其显式模式；新建入口不再强制 readonly。后台验证 JSON 新增可缺省 session_id，旧文件仍可读取。

回退前备份整个 Kanzei home 与项目 state.db。旧程序能读取原有表和 ID，但会重新启用旧版第一条对话特例；若需恢复回退前的完整状态，应同时恢复备份，不应手改身份或搬移消息。

## 验证

Rust 覆盖新旧身份的关闭、删除、重启、迟到请求与后台结果归属。浏览器覆盖开合往返、刷新保持、标题、普通新建、交接与草稿隔离；原生 WebView2 通过真实 IPC/SQLite 验证项目和无项目生命周期。
