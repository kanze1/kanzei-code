# AUTO research：从方向到 MVP 结论（R-363）

- 身份: live_design
- 状态：2026-09-21 用户确认流程后的第一批实现（R-363）。

## 用户路径

在课题概览启动 AUTO research，设置检索预算和实验次数预算。Agent 自动完成文献调研和研究地图，展示候选方向的依据、疑点、成本与最小验证方式，等待用户选择。选择后生成可证伪问题与 MVP 方案，准备实验、复现基线、运行 MVP 并解读结果。

首批终点是有实验依据的 MVP 解读。完整实验扩展、云 GPU 自动供应、外部会议模板导入为后续增量；现有本机/SSH 运行器及 LaTeX 通道继续复用。本轮不把这些未实现环节声称为自动化交付。

## 阶段与事实

`survey → map → choose_direction → design_mvp → prepare → run_mvp → interpret → completed`

- `.kanzei/research/<topic>/workflow.json` 保存流程状态、版本、用户选择、MVP 合同、预算和历史。使用锁、原子替换和 revision 检查，过期请求拒绝，不覆盖新状态。
- 来源和发现继续使用 sources/findings；地图正文是带来源的 Markdown，候选方向是其结构化选择入口。
- 探索和实验结果仍使用已有两层模型。工作流只引用 exploration_id/result_id，不建立第三套实验事实。
- 过渡必须携带真实存在的课题内工件；地图候选绑定已登记来源；准备阶段绑定成功基线；实验阶段绑定同一探索的终态运行；解读必须明确支持、否定或不确定及下一步。
- 运行失败不能作为支持或否定科学假设的证据。可记录不确定结论和故障解释。
- 修改 MVP 或转向留下历史；迭代返回 design_mvp，转向返回用户选题。首次完成可以是支持、否定或不确定。

## 人与自动执行的边界

启动、选方向、暂停、恢复由用户入口处理；模型工具不暴露这些动作。启动授权限定预算内的调研；普通 research 会话仍保留原有计划审批行为。已有未批准计划需在计划页明确批准。

自动推进读取当前课题工作流，复用底层续跑事件、取消与失败退避；不查询 dev 待办来决定研究是否继续。选题、明确等待输入、暂停、完成都停止续跑。连续无变化仍停止，避免重复空转。重启后回读同一阶段，由用户点击继续恢复，不能自动重启一个中断的实验。

通用 write/edit/insert 不能改写 workflow.json；所有状态变更走专用接口。新流程不扩大实验执行策略：自有环境复用已有 relaxed 策略，共享/付费策略维持现有运行器合同。实验次数预算含基线、失败与重试，模型不可通过改探索 ID 绕过预算。

用户可在概览调整实验次数预算，修改预算本身不会启动实验。暂停会取消所属课题的排队续跑，当前运行按原有运行器收尾；重启、后台续跑均保留研究档位与课题标识。
