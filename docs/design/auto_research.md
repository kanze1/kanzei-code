# AUTO research：从方向到实验和论文 PDF（R-363）

- 身份: live_design
- 状态：2026-09-24 补齐完整实验返工、历史产物和断点恢复，保留首批全流程工作树实现。

## 用户路径

在课题概览启动 AUTO research，设置检索预算和实验次数预算。Agent 完成文献调研和研究地图，展示候选方向的依据、疑点、成本与最小验证方式，等待用户选择。随后确定可证伪问题与 MVP，准备本机或已登记 SSH 实验环境，复现基线并运行最小实验。解读可以支持、否定或保留假设，也可以回到方案迭代或重新选题。MVP 收敛后继续完整实验、综合分析、论文写作、检查和实际编译，以 PDF、源码和可追溯交付清单结束。

## 阶段与事实

`survey → map → choose_direction → design_mvp → prepare → run_mvp → interpret → plan_full → run_full → analyze → write_paper → review_paper → compile_paper → completed`

- `.kanzei/research/<topic>/workflow.json` 保存阶段、revision、用户选择、预算、MVP、环境、完整实验矩阵、论文及历史。使用锁、原子替换和版本检查；旧请求不能覆盖新状态。
- 版本 2 为完整流程；版本 1 保持原有 MVP 终点，概览提供“扩展到完整实验与论文”，保留旧结果再进入完整实验方案。
- 来源和发现继续使用 sources/findings；地图正文是带来源的 Markdown，候选方向是其结构化选择入口。
- 探索和实验结果仍使用已有两层模型。工作流只引用 exploration_id/result_id，不建立第三套实验事实。
- 过渡必须携带真实存在的课题内工件；地图候选绑定已登记来源；准备阶段绑定成功基线；实验阶段绑定同一探索的终态运行；版本 2 登记结果时再次核对执行环境，并拒绝早于当前环境准备的运行；MVP 结果编号不得重复计入。解读必须明确支持、否定或不确定及下一步。
- 运行失败不能作为支持或否定科学假设的证据。可记录不确定结论和故障解释。
- 修改 MVP 或转向留下历史；迭代返回 design_mvp，转向返回用户选题。只有实际 PDF 编译与检查成功后，新流程才能标记完成。
- `design_mvp` 的阶段提示提供探索文件路径、frontmatter、固定章节与结果表模板；`exploration_id` 是 `E-001` 这样的编号。`define_mvp` 返回具体文件诊断，拒绝格式不完整的探索记录。

## 实验环境与完整实验

`prepare_compute` 接受 Python 路径、GPU/可用显存要求、可选环境 ID、依赖文件和上传文件列表。

- 本机使用课题目录；SSH 使用已登记的 active 环境，在远端 workdir 下创建课题目录并上传明确列出的脚本与依赖。
- 创建课题专用 `.auto-venv`，复用已有科学计算轮子，按 requirements 安装依赖。记录 Python、包版本、PyTorch/CUDA、GPU 型号与显存，并实际执行 GPU 张量探测。
- 探测失败或 GPU/显存不足时保留 `compute-probe.json` 并报错；不把待配置环境标记为可运行。
- 后续运行绑定准备完成的 kind/host/workdir/environment_id；运行器默认继承省略的 host/workdir/environment_id，kind 显式传入并核对。继承的 environment_id 同样用于策略、租约、成本和预算检查。SSH 命令显式切换到绑定的工作目录。
- 本实现配置已有本机/SSH 资源；没有云厂商开户、付费租卡或销毁实例适配器。

完整实验协议至少覆盖 baseline/main 的相同两个随机种子、消融和鲁棒性，共 6–100 项。baseline/main 同一随机种子不能重复计入。运行参数必须与登记的 experiment_id/role/seed 一致，失败项使用新 result_id 重试。预算统计基线、MVP、失败和重试；提交矩阵前也检查剩余预算。

`research_runner` 省略 result_id 时，从探索结果表和运行库中选择未使用的两位编号（如 `E-001-01`）；运行库里尚未回写表格的编号也会保留。AUTO 入口在启动进程前校验编号格式，避免时间戳编号破坏探索表解析。Windows 命令通过 `cmd /D /S /C` 保留原始引号，支持含空格的 Python 路径。工具说明给出指标与心跳回调示例；缺少指标时工作流返回具体修复格式。

所有矩阵项成功且有目标指标后生成 `results.json`，包含原始运行引用、参数、代码引用、环境引用及每组 n、均值、样本标准差。n=1 的标准差为 null，论文表格显示 `--`，不假装估计出了波动。综合解读写入指定工件并同步 `report.md`，由现有结果页展示。

完整实验分析的 `submit_analysis` 支持 `next=complete/iterate/pivot`，默认进入写作。`iterate` 必须附理由，保存本轮再返回 `plan_full`；`pivot` 保存本轮后回到用户选题。写作、审阅、编译与完成阶段也提供“补充实验”入口。

上一轮的协议、结果汇总、分析、来源以及已有稿件的依赖、PDF 和交付清单保存到 `rounds/full-NNN-r<revision>/`，逐个记录 SHA-256，禁止覆盖不同内容。`full_rounds` 保存对应矩阵、结果编号、环境和返工理由。概览中的“历次完整实验”可以打开原协议、分析、结果和 PDF。

新矩阵使用 `reuse_results` 显式复用已归档成功项；实验定义、指标、探索及准备环境必须一致，重新准备环境后不能复用旧运行。至少有一项需要新跑；预算只新增实际运行次数，失败和重试仍消耗预算。新 `results.json` 标明各项复用自哪一轮，并链接旧分析。

## 论文与交付

`paper_init` 可生成 article 模板，也可导入课题内已有 TeX 模板并登记来源；不覆盖现有稿件。自动产生真实结果表格和已登记来源的参考文献，Agent 补写正文。

补充实验后再 `paper_init` 会接续原稿正文，更新结果表和参考文献，并清除上轮审阅与编译状态；Agent 必须更新论述，再次提交、检查和编译。旧 PDF 可从历史轮次打开。

`submit_paper` 提交稿件及主张表；`review_paper` 检查占位内容、基本章节、引用键、主张原文、来源/结果归属和声明的数值。数值由真实运行指标核对；多结果引用的数值按算术均值比较。所有完整实验必须被主张表覆盖。此检查是机械一致性检查，不等于学术同行评审，也不能保证未登记的每一句自然语言论断都正确。

审阅指纹覆盖 TeX 依赖、图表、局部样式、参考文献、主张表、分析、协议、结果与来源文件。审阅后修改输入，必须重新审阅。`compile_paper` 调用已有 LaTeX 后端，清理旧 PDF，检查本次真实 PDF 及未定义引用。失败保留阶段及逐次编译诊断，允许修复重试。

交付文件包括：

- `latex/paper.tex`、结果表、参考文献及 `latex/paper.pdf`。
- `latex/compile-log.txt` 与 `compile-attempt-N.txt`。
- 研究地图、协议、分析、原始运行日志和产物引用、环境探测快照。
- `delivery.json`，绑定论文输入/PDF SHA-256、计算环境、结果记录、实验轮次和工作流路径。

## 人与自动执行的边界

启动、选方向、暂停、恢复由用户入口处理；模型工具不暴露这些动作。启动授权限定预算内的调研；普通 research 会话仍保留原有计划审批行为。已有未批准计划需在计划页明确批准。

自动推进读取当前课题工作流，复用底层续跑事件、取消与失败退避；不查询 dev 待办来决定研究是否继续。选题、明确等待输入、暂停、完成都停止续跑。连续无变化仍停止，避免重复空转。重启后回读同一阶段，由用户点击继续恢复，不能自动重启一个中断的实验。

`research_workflow get` 和状态变更返回 `recovery`，从现有运行事实计算已用/剩余次数、活动运行与成功但尚未登记的完整实验（`pending_full_results`）。恢复时先将待登记结果交给 `record_full`。即使成功结果还没写入 workflow，运行入口也拒绝重跑同一矩阵项，并返回可恢复的 result_id；失败、取消和缺指标的运行仍可用新编号重试。

通用 write/edit/insert 不能改写 workflow.json；所有状态变更走专用接口。新流程不扩大实验执行策略：自有环境复用已有 relaxed 策略，共享/付费策略维持现有运行器合同。实验次数预算含基线、失败与重试，模型不可通过改探索 ID 绕过预算。

用户可在概览调整实验次数预算，修改预算本身不会启动实验。暂停会取消所属课题的排队续跑，当前运行按原有运行器收尾；重启、后台续跑均保留研究档位与课题标识。

## 两个真实案例

可复现驱动：`cargo run -p kanzei-tools --example auto_research_cases -- output/<new-directory>`。要求 PATH 中的 `python` 具备可用的 PyTorch CUDA 环境和已有 LaTeX 后端。夹具脚本：`scripts/fixtures/auto-research-memory-probe.py`。已验证机器为 RTX 4090（24 GB），PyTorch 2.10.0+cu130。

两个案例通过真实工具接口完成联网来源抓取、环境准备、CUDA 子进程、运行回调、暂停/恢复、论文检查及 MiKTeX 编译。研究方向选择、实验方案与论文正文由确定性测试驱动提供，未用其证明 LLM 自主研究质量。

| 案例 | 协议与结果 | 故障覆盖 | 交付 |
| --- | --- | --- | --- |
| agentmem-freshness | 合成过时记忆：768 个键、128 维向量；已知时间戳过滤。baseline/main 各 3 个配对种子，另各 1 个消融/鲁棒性项。主实验准确率 0 → 1，支持该有限合成假设。 | 暂停、重新加载状态、恢复同一矩阵。 | 10 次 GPU 运行，8 项完整实验，2 页 PDF。 |
| agentmem-compression | 同尺寸合成检索，截取 4/128 维。主实验均值 0.115451393，相对基线 1 明显不满足预设的准确率下降 ≤0.01。 | 注入一次进程失败，拒绝用失败支持结论，再迭代；注入一次 TeX 错误，修复、复查、重编译。 | 11 次 GPU 运行（含 1 次失败），8 项完整实验，2 页 PDF。 |

文献背景来自 MemGPT 与 LLMLingua 的 arXiv 摘要抓取，明确按文献域 V1 记录。这些实验不是上述论文复现，也没有评估真实 LLM Agent。通过的是产品完整工具链与合成机制验证。

验收产物：`output/auto-research-acceptance-02/results.json`；每例包含 `case-events.jsonl`、`case-result.json`、独立 state.db、完整课题目录和 PDF。输出目录必须全新，防止覆盖前次证据。
