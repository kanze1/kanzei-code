# 主对话区呈现契约:什么算正文,什么算轨迹

- 身份: live_design
- 状态: 设计基线(2026-09-02 用户就三个方向定调后冻结前两节;§5 为已确认未定项)
- 上游文档: [interaction_modes.md](interaction_modes.md)(R-037 附节,本文的前身)、[frontend_phase3.md](frontend_phase3.md)
- 实施条目: R-350 R-351 R-352;缺陷 D-725
- 一句话: 主对话区从来没有一条「什么算正文、什么算轨迹」的分层契约,本文补上它。

## 1. 根因

用户反馈「主对话的呈现和渲染现在不满意,我有点描述不清楚」。描述不清楚本身就是症状:

**每一块单看都很克制**——淡色、无边框、只有一行摘要,没有哪一条该被单独骂。难受来自
3582 × 2 的**乘法**,而乘法是看不见的。所以他能感觉到、指不出来。

R-037(2026-08-06)定过一次分层方向,随后被两次没有对账的反转作废,此后每一条呈现改动
都在给轨迹加权。**问题不在任何一个控件,在于没有契约。**

## 2. 量化(2026-09-02 直接查 state.db 复核)

```text
assistant 正文块      1293 条        合计   170.7 KB
工具调用              3583 次
工具结果              3582 条        合计    12.0 MB
思考块                2436 个        其中单行 1767 个 = 72.5%

正文 : 工具结果 字节比  =  1 : 72
工具结果字节  p50 903   p90 8830   p99 36964   max 209453
```

一次并行勘察按「全部折叠」的屏占口径估算过一版:12787 行里正文只有 3186 行,
即主对话区约 **75% 的行不是对话**。该行数是模型估算,不如上面的字节数直接;
但两个口径指向同一结论——**正文是零头**。

## 3. 三层契约(本文的核心)

主对话区的每一个可渲染物,必须能被归进且只归进一层:

| 层 | 内容 | 默认形态 | 判据 |
| --- | --- | --- | --- |
| **正文** | 用户消息、assistant 对人说的话 | 完整渲染,结构保真 | 「这句话是说给人读的吗」 |
| **轨迹** | 工具调用与结果、思考 | **一行**,可点击展开 | 「这是过程,不是结论」 |
| **后台** | 子代理内部步骤、原始输出、大块产物 | 不进主区,去活动面板 | 「展开它会淹没上下文吗」 |

三条硬规则:

1. **轨迹默认占一行**,不因为「摘要有内容」就多占一行。行数是乘法项,不是个案。
2. **正文的结构不可被渲染器降级**——标题层级、列表缩进、强调必须保真。
   正文只剩零头时,把这零头渲染糊了是双重损失。
3. **主区任何展开区都必须有高度上限**,超限给出「去活动面板看全的」出口。

## 4. 已定(2026-09-02 用户逐条定调)

### 4.1 工具调用:一行,点击展开

用户原话:「一行合理,像 claude 一样,但是呢,我可以点击展开」。

- 成功:**一行**。`⎿ 摘要` 第二行取消,信息并进该行或只在展开后可见。
- 失败:**仍是一行**,但错误内容**默认展开**——错了不该藏起来。
  *(这条是设计者补的假设,用户只说了「一行 + 可展开」;若不同意,改这一条即可,不影响其余。)*
- 展开:点击行本身展开完整详情,受 §3 规则 3 的高度上限约束。

现状与之相差多远:[05-chat-render.js:449](../../crates/kanzei-app/ui/05-chat-render.js) 的
`block.result.classList.remove("hidden")` 前面**没有任何 if**,CSS 又用 `nowrap + ellipsis`
把它钉死成恰好一行,所以「完成态 = 精确两行」是布局保证而非估算;折叠开关只 toggle
详情容器,`result` 从不参与。3582 × 2 = 7165 行,是主区行数的大头。

### 4.2 轮次边界:不画线,拉开留白

- 轮**间**留白拉到轮**内**的四到五倍;不引入横线,不引入常驻角标。
- 现状是**倒挂的**:`.msg.tool-msg { margin: 1px 0 }` 让工具行↔工具行 = 14px,
  而 `gap: 12px` 让用户↔助手 = 12px——同一轮内部比轮与轮之间还宽。先摆正这个。
- `.turn-divider` 的 CSS 仍在样式表里但**全仓无创建点**,是 745afccc 的遗留,一并清掉。

### 4.3 思考块:单行不单独成块

- 单行思考并进正文尾部或直接不渲染,只保留多行的可展开块。
- 现状 `expandable = lines.length > 1`,而 72.5% 的块只有一行——它们**点上去是空操作**。
  「点了没反应」太琐碎不值得单独提一嘴,但每天发生几十次。

## 5. 已确认但未定方向(需另行拍板或按默认实施)

1. **markdown 结构被渲染器抹平**(投入产出比最高):
   [04-markdown.js:93](../../crates/kanzei-app/ui/04-markdown.js) 捕获了井号数量到 `heading[1]`,
   第 97 行**只用 `heading[2]`**,层级当场丢弃;`.md-h` 不设字号不设字重,
   所以 `#` 与 `######` 完全同形。列表缩进被 `\s*` 吃掉,子条目全部拉平;无斜体规则;
   段间距 5px 而行高 25.8px。→ R-351。
2. **主区展开无高度上限**:`.tool-display` / `.term` / `.diff` 没有 `max-height`,
   而同一展开容器里的 `.tool-msg-raw` 有两道限制、活动面板同款也有 180px,**唯独主区漏了**。
   另:write 工具产出的 diff 是全文件上下文(注释称「由前端裁剪」,但前端并无裁剪代码)。→ R-352。
3. **子代理跨轮撞 id 静默覆写**:确定性缺陷,已立 D-725。
