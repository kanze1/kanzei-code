## 背景与问题

一个会话连续处理多个条目时，上一条的大段文件与搜索结果仍随每次请求发送。已有压缩主要等到 token 预算到线，不能利用工作内容发生切换的自然边界。每换条目另请模型总结，又会增加等待和摘要漂移。

## 目标与非目标

条目切换后主动减负，保持总委托、用户修正和交接连续；整理本身不要求验收、不调用额外模型、不改变条目状态。阶段一只收纳旧观察正文，不宣称整个任务历史已经隔离，也不自动把观察或模型假设写成全局偏好。

## 讨论摘要

用户提出“开新条目正好清理上下文”，并授权设计和优化。结合既有 Work Unit、typed facts 与 compaction surface，选择在成功认领不同条目后建立整理边界；完整聊天仍可审计。

## 候选方案

| 方案 | 成本与影响 | 结论 |
| --- | --- | --- |
| 每个条目新建会话或清空历史 | 容易丢总目标、用户修正、待验收事项 | 不采用 |
| 每个条目请求模型总结 | 增加请求、等待和语义丢失风险 | 不作为默认 |
| 收纳旧观察，保留交接事实 | 无额外模型请求，原文可回读；保留的历史仍会增长 | 本次实现 |

## 最终方案

1. 只识别当前会话已配对的 `work action=claim` 成功收据，支持 R/D 条目和 Work Unit。首次认领只建立锚点；同条目续做、`next`、失败、其他工具里的文本均不触发。
2. 工具组完整返回后、下一次 provider 请求前整理；若上一轮结束时刚认领，下轮第一次请求前也能处理。
3. 保持所有消息与工具配对，仅替换更旧的成功 `read` / `grep` / `glob` 大正文。保留用户指令、assistant 内容、question 决策、work/req/defect 交接、失败、bash 日志、子代理和后台任务结果、图片、既有外置引用以及规则/记忆目录的读取。
4. 最近约 4,096 token 和至少两份大观察不动；已登记同父需求、直接关联/依赖、相交路径范围时，近期窗口扩大到约 12,288 token。未登记的语义关联无法据此推断，原文入口始终保留。
5. 预计并实际节省至少约 4,096 token 才替换。每次最多 16 份结果；不等待配额锁；处理 250ms 后不再启动下一份归档。单次磁盘操作仍受存储延迟影响，这不是实时硬截止。
6. 原文先写入现有 `.kanzei/artifacts/tool-results` 内容寻址存储，共用配额、锁与原子写入；候选消息只留下大小、SHA-256 和 `read` 路径。存储失败保留原文，不截断。
7. 由当前会话的 TypedSessionWriter 原子保存 compaction surface。保存确认后 runner 才替换发送视图。保存失败或消费者不支持（例如子代理 transcript）就沿用原历史。成功收据中的版本化边界标记随 surface 恢复，防止同一次切换反复整理。

界面/CLI 显示“R-… → D-…：收起 N 份旧读取/搜索结果，约减少 X token；原文可回读”。运行轨迹记录 `context.work_item` 及保存状态。token 是 messages 的本地估算，不能当作账单或耗时实测。

## 技术选型与取舍

复用现有工具原文存储和 SQLite compaction 事务，不新增数据库表，也不另建摘要器。自动决策与用户偏好仍使用现有决策记录/复核入口，整理不提升它们的权限。

完整事实和模型发送视图分离。既有 token 预算压缩继续兜底；这里只增强条目切换时的第一层减负。经 bash 调用 CLI 的取活没有可靠的 work 工具收据，本次不根据命令文本猜测成功。

## 实施边界与调用方

| 位置 | 职责 |
| --- | --- |
| `kanzei-tools/src/work/tool.rs` | legacy claim 收据增加已有条目关联 |
| `kanzei-core/src/runner/item_context.rs` | 确定切换、保护窗口、候选整理和落库确认 |
| `kanzei-core/src/runner/drive.rs` | 完整工具组之后、预算检查之前的统一入口 |
| `kanzei-core/src/runner/tool_exec.rs` | 复用工具结果存储，无损归档失败回退 |
| `kanzei-core/src/store/typed.rs` | 当前 writer 的原子 surface 提交；原始 facts 不变 |
| App/CLI RunEvent 消费者 | 保存确认、状态提示和轨迹 |

迁移：无 schema 迁移，旧收据仍可识别；没有关联元数据时使用普通保护窗。回退：移除调用入口即可停止新整理；既有 surface 和原文引用仍可由当前恢复/读取机制消费。不同会话由各自 writer 保存，子代理不借用父会话落库。
