# 无项目对话

- 状态：已实现；2026-10-03 按用户反馈修正为完整通用 Harness，项目流程关闭。验证记录单独保存；尚未公开发布。
- 日期：2026-10-03
- 关联需求、缺陷、决策：无；用户在 Harness 修复后直接补充的功能。

## 背景与方案

用户需要不选项目也能使用完整的通用 Harness。复用现有会话引擎和工具，使用独立存储根，关闭项目流程；该存储根不会作为项目登记。关联时复制到项目讨论，保留原聊天，方便回查来源。此前只保留网页工具的边界过窄，已撤销。

## 实施边界与调用方

侧栏“无项目对话”无需添加项目，可发送文字与附件、选择模型、停止回复、新建聊天、打开历史、分叉和恢复重启前的会话。没有任何项目时首次启动直接进入该模式；有项目时沿用原入口，曾主动选择无项目模式则恢复该模式。普通设置和研究入口继续可用。

会话独立保存在 `KANZEI_HOME/conversations/general/.kanzei/state.db`（默认 `~/.kanzei/conversations/general/.kanzei/state.db`），沿用现有 SQLite 会话、事件、队列和压缩机制。该存储根不加入项目列表，也不覆盖最后选择的真实项目。各会话的输入草稿和附件继续按会话归属隔离。

模型、权限、技能和自定义代理使用全局配置。文件读写、编辑、命令执行、交互式终端、浏览器、网页检索、LaTeX、绘图、记忆、按需派发与持续协作的子代理保留；工具结果预算、自动与手动压缩、停止、历史、回退和分叉沿用共享运行时。

每条会话的默认文件目录为 `KANZEI_HOME/conversations/general/artifacts/<会话标识的稳定哈希>/`。模型生成真实文件，再给出绝对路径链接；可在对话中打开文件。用户明确提供的其他文件路径仍由普通工具和全局权限处理。普通文件的过期保护与回退前检查保持有效。

关闭的项目流程包括需求/缺陷/想法队列、领取与交付记录、强制勘察复核阶段、批次收尾、验收记录和强制提交。工具目录不提供这些项目专用工具；项目规范、取活上下文和 Git 起点提示不注入。旧界面传来的项目自动推进或批次参数也不启动该流程。后端持久化 profile 为 `dev` 以复用工具能力，主代理为 `general`，不是项目开发任务。

用户主动使用 Git 时，普通暂存与提交保持可用；无项目 scope 不要求 Cargo 工程、测试记录、事项 ID 或项目交付验收。明确文件范围与暂存内容版本核对仍有效。

子代理默认开启，用户可自行关闭；旧版只读会话在打开时迁移，新版保留用户的开关选择。可写子代理沿用隔离工作树和显式采纳，只在应用自有会话文件目录按需初始化私有 Git 仓库作快照记账，不要求用户创建项目或提交交付。只读角色和全局自定义角色保留各自权限和提示词。

定时任务可直接选择“无项目对话”。应用定时器扫描这个独立存储根，任务执行使用独立产物目录，不要求 Git 项目；任务定义和历史留在此根，未将其加入项目列表。应用托管任务需要运行中的应用；系统/服务器托管继续使用已有对应实现。

“关联项目”选择一个已登记且可访问的项目，将当前可见段（含已完成压缩）复制为普通项目对话，附上来源会话事实；原聊天完整保留。新对话使用 dev 模式，保留模型、思考强度与子代理设置，可以直接继续执行。运行中、压缩中或存在排队输入时拒绝关联；失败保留原对话，回收未完成的新进程登记。

实现入口：共享 `GeneralChatProfile`、`ToolCtx.project_workflow`，桌面 `general_chat.rs`、`03-general-scope.js`、`29-general-chat.js`。验收脚本 `scripts/ui-general-chat-native-smoke.mjs` 驱动真实 Windows WebView2、Rust 和 SQLite，用本地模型服务检查聊天入口、实际文件产出、连续写入、子代理、命令、定时任务、文件回退、历史恢复与关联。外部模型及网页后端稳定性需另行在线验证。
