## 产品结构

一级空间为开发与研究。开发下选择结伴开发或自主推进；研究以课题为核心，包含概览、对话、文献与发现、计划、实验、成果。项目总览、记忆、文件和设置复用现有能力，并显示范围。导航切换不修改原任务的 profile，不停止后台任务。

开发侧栏显示开发任务和工作摘要。研究侧栏显示课题及该课题的会话。正式研究、开发调研和旧版材料分别展示。旧侧栏来源、发现与平铺报告入口移除；所有引用和报告操作带当前课题。

视觉沿用现有金色主题和字体，通过分组、留白、选中态与短过渡建立层级；每个工作页面聚焦一个主要任务。

## 状态与执行

空间、最近页面、最近会话及课题选择按项目保存到现有桌面偏好通道。切换空间恢复对应会话；研究会话创建时绑定课题，绑定后不能通过导航改写。文本草稿和附件按项目与会话在本次应用会话内保留。已有未绑定研究会话通过“未绑定课题的对话”范围查看和继续，由用户创建新的课题会话进入明确绑定路径。研究空间的“新对话”创建新会话，保留已有历史。

ui_prefs_set 显式采用 snake_case 参数名称，与现有 uiPrefsSave 请求一致；原有权限及自动运行偏好也继续沿用同一通道。process_create、run_prompt 的 UI 调用参数仍使用既有 Tauri camelCase 约定，researchTopic 对应后端 research_topic，存储与返回值使用 snake_case。

processes 新增可空 research_topic 字段，沿用原生 SQLite schema v22 迁移。旧行默认 NULL，无推测性回填；迁移前沿用既有整库备份。回退旧程序需要恢复迁移前备份，保留升级后的数据库以免丢失后续工作。此仓库使用 rusqlite 内置迁移，没有 Alembic 运行时。

创建和发送由后端验证课题名称、目录存在及 profile 一致性。绑定会话发送时继承同一课题；客户端传入其他课题直接拒绝。研究上下文在运行入口注入，原有权限与研究工具范围保持生效。

课题元数据使用 topic.json 保存标题与内容类别；既有材料按报告显式 kind 和实际工件识别，开发勘察及 prior-art 单独归类，无法判定的材料显示待分类。存量文件不迁移、不删除。

### 可重复的用户路径

| 操作 | 预期与已覆盖状态 |
| --- | --- |
| 开发任务运行时进入研究，再返回开发 | 开发 profile、运行状态和输入草稿不变；无 stop_run 或改 profile 请求；开发附件恢复 |
| 课题 A → 对话 → 输入草稿 → 课题 B → 对话 → 返回 A | 每个课题独立创建/恢复会话，草稿不串，历史使用对应 processId |
| 研究空间点击“新对话”并发送 | 新建当前课题会话，旧历史不清空；run_prompt 带 research profile 和当前 researchTopic |
| 选择课题后进入写作页，再刷新浏览器 | 恢复空间、课题、最近会话及写作页面 |
| 切换内容范围 | 正式研究、开发调研、待分类材料、历史材料及未绑定对话分别呈现 |
| 课题 A 请求延迟失败，先切到 B | A 的迟到错误不清空 B 的计划；PDF/编译等异步结果也带相同上下文守卫 |
| 项目 A 快照未返回时切到 B | 立即清空旧项目材料；迟到快照不覆盖 B 的标题、课题或报告 |
| 新建重名课题，再重试有效标识 | 错误在表单内显示并可重试；成功后选中新课题；后端不覆盖已有目录 |
| 无计划或报告的课题 | 显示“尚未创建计划”或“尚未生成报告”，不残留上一课题结果 |
| 同 ID 来源在不同课题中更新状态 | docs_update 使用来源所属 topic，避免落入旧版平铺文档 |
