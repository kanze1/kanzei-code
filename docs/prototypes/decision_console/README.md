# 多项目总控交互原型

日期：2026-09-27。对应 [产品重整草案](../../design/product_operating_model.md)。

视觉方向：沿用 Kanzei 的深灰底、橙色主操作和青色成果提示，以清楚的项目行与侧边详情组织信息。

内容安排：先看多个项目的工作和真正阻塞，再看可试用成果；同页审阅决定，最后查看决定如何形成偏好。没有营销首屏或装饰性统计图。

交互方向：工作行短暂入场；详情切换渐入；关系图只在进入、聚焦与回放事件时运动，隐藏后暂停，支持减少动态效果。

## 使用

在仓库根目录运行：

```powershell
node docs/prototypes/decision_console/serve.mjs
```

打开命令输出的本机地址。也可以直接打开 index.html；图谱复用仓库中的离线 force-graph。无需安装依赖。

所有项目、进度、成果、证据和偏好均为示例。操作只影响当前页面内存；刷新恢复初始数据，不写 tracker、真实全局记忆或运行中的项目。服务仅绑定 127.0.0.1，并仅提供原型文件和两个已有图形资源。

## 可操作路径

- 总控：筛选项目、查看任务、暂停 / 继续示例项目。
- 成果：查看使用路径、认可示例成果；真机 OCR 缺设备只阻塞对应单元。
- 决策：逐条 / 批量认可，或填写修改意见并选择“仅这次 / 本项目 / 所有项目”。
- 修改会让对应成果进入待更新状态，并在项目中增加返工项；记住时新增相应范围的示例偏好。
- 记忆：选择节点、回放一条决定转为偏好的过程，可用列表访问同一批关系。
- 顶栏“重置示例”恢复初始状态。

- `node --check`：console.js 与 serve.mjs 语法通过。
- 浏览器真实页面：初始三项目 / 三成果 / 三决定可见；暂停再继续单个项目时，推进项目数按 3 → 2 → 3 更新。
- 单次认可：待审阅数减少，已确认偏好数量不变。
- 批量认可：仅剩余选中决定进入已认可；没有额外写入全局偏好。
- 纠正并选择全局：产生一条带“所有项目”范围的示例偏好，关联成果进入“待更新 / 原验证已过期”。
- 仅修改本次：产生返工，不新增偏好；图谱没有生成虚假的偏好节点或采用边。
- 项目范围：切到 Kanzei 后，图谱与详情均绑定 Kanzei。
- 图谱：Canvas 实际加载，回放能进入关系阶段，选择偏好节点能看到反馈内容；检查时控制台未记录 error。
- 1440 × 900 桌面断点、390 × 844 窄屏及实际 933 × 764 面板检查；未观察到页面横向溢出。窄屏采用上下布局，实际面板保留双栏。
- 页面入口与操作主要通过键盘激活验证；图谱拖拽、动态效果减少设置和长时间资源占用未做专项实测。

此记录只验证原型交互。没有验证真实多项目调度、持久化、权限、机器测试复用、全局记忆写入或应用安装包。
