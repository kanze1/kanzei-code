# 第二轮原型调整

2026-10-04，依据用户试用反馈。

视觉方向：保持已经认可的对话布局；管理区使用更宽的列表和完整内容页，批次回到格子进度；代码增删使用熟悉的绿 / 红。

内容安排：全局侧栏承接工作台、定时任务、记忆管理、设置。项目内保留对话 / 管理两级；管理内需求、缺陷、交付平级切换。项目工具收纳测试、想法、规范、运行与架构。文件操作直接进入 VS Code。

交互方向：详情使用完整页面并返回原列表；切换记忆范围独立于正在执行的对话；菜单与页面沿用短过渡，后台更新不抢输入焦点。

## 明确决策

- 移除原型中的内置文件浏览页，项目上下文提供「在 VS Code 打开」。
- 记忆管理是全局入口，包含全局记忆及所有项目，支持范围 / 项目 / 状态筛选。条目身份包含所属范围，不能只依赖 M 编号。
- 管理内需求、缺陷、交付各有完整页面，通过同一行按钮切换。交付不放在需求列表下方。
- 批次用格子区分已完成、当前与待开始。可见列表不出现完成数 / 总数；读屏标签保留解释。
- 需求、缺陷、交付打开完整内容页。需求结构由展示适配层承接，已有字段、正文与扩展字段完整保留，不确定新的存储格式。
- 研究模式及其专属工作区、课题、文献、实验、论文工作流退出新方案；通用代码检索、网页搜索与需求实现前调研仍属于正常开发能力。
- Diff 的增加为绿色、删除为红色，与一般运行状态颜色分开。
- 功能完整性以功能对照表记录，区分正式入口、第二轮原型覆盖及后续接入，不能把示例页面当作正式能力已交付。

正式研究链路目前仍存在于仓库；本轮是原型迭代和调用审计，具体退场范围见分析目录中的功能可达性报告。正式数据结构正在并行调整，本轮不改动需求、缺陷、交付的存储层。
