# 第四轮：主干依赖、运行数据和独立预览

2026-10-04，依据第四轮试用反馈。继续迭代本地原型。

视觉方向：保留现有中性界面，主图使用从左到右的主干和折线；减少同时出现的关系。

内容安排：项目地图下方展示项目运行数据；对话工作清单只显示当前工作和下一候选；子代理与终端共用活动栏，网页独立浮窗。

交互方向：点击模块聚焦直接依赖；手动选取当前/候选工作；预览拖动、调整大小、缩放，后台更新保持用户的阅读位置。

## 展示方式调研与选择

| 方式 | 优点 | 对当前项目的判断 |
| --- | --- | --- |
| 完整分层依赖图 | 保留所有边，方向明确 | 22 条非开发依赖同时连线，跨层边遮挡主干，不适合默认视图 |
| 严格树状图 | 层级清楚、连线少 | 共享依赖有多个父节点，强行树化会丢关系或重复模块 |
| 主干依赖＋局部直接关系 | 首屏读结构，点模块核对完整关系 | 本轮采用；保留共享依赖，省略能经其他模块到达的重复路径 |
| 依赖矩阵 | 适合密集关系、没有交叉线 | 需要对照行列，适合作为大型项目后续的第二视角 |

依据：[Graphviz 分层布局](https://graphviz.org/docs/layouts/dot/)、[Graphviz 传递约简](https://graphviz.org/docs/cli/tred/)、[yEd 正交路由与边分组](https://yed.yworks.com/support/manual/layout/layout_hierarchic_incremental.html)、[D3 树布局](https://d3js.org/d3-hierarchy/tree)。据此选择是本项目的设计判断，并非上述工具对本项目的评估。

主图显示的每一条连接仍是真实直接依赖，省略的边保留在局部详情与来源清单。对当前无环依赖做约简，核对可达关系保持一致；不把静态依赖图说成运行时调用图。

## 运行数据口径

本轮从示例运行记录聚合，不读取生产数据库。时间范围、项目/对话筛选同时作用于所有数字。新的演示运行会追加可追溯的本地记录。

- 平均时长：有完整计时的已完成运行，按运行求平均；停止、刷新中断、执行失败不混入完成时长。
- 工具调用：按调用记录累计；真实失败、规则拒绝和用户停止分别统计。
- 记忆：分别看召回、注入、读取记录；没有读取观察时显示未记录，不凭注入推断实际读取或有效使用。
- 运行明细可进入所属对话；失败与缺失数据可区分。项目指标不伪造为某个 Cargo 模块的性能指标。

对接依据：`crates/kanzei-core/src/runner/metrics.rs` 中 `RunMetrics` 的总调用、失败和拒绝；`crates/kanzei-core/src/store/telemetry.rs` 的召回/注入事件；`crates/kanzei-core/src/store/memory_observations.rs` 的使用观察。正式接入应使用当前轮切片、调用 ID 和事件 ID 去重。

## 工作选择

清单属于当前对话，最多一项正在进行、一项下一候选。完整项目台账从“全部工作”进入。草稿、阻塞、待验收和已完成项不作为可执行候选。

闲置时手动切换当前工作，保留旧进度；选择候选只改变顺序，不启动执行。运行中调整明确排在下一轮，本轮执行快照不变。其他正在运行的对话所占用工作不可直接抢占。

## 独立网页预览

网页浮窗与右侧子代理/终端活动栏可以同时存在，独立开关。支持拖动标题栏、右下角调尺寸、最大化/恢复与页面缩放；窗口按对话保存。预览关闭和焦点规则延续第三轮，同一轮后续事件不反复弹窗。
